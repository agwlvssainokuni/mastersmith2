## Q2. メール送信を含む機能のテストの方針

## Q3. メールと招待に関わる固い制約（select all that apply）

固い制約（`ALWAYS …` / `NEVER …` の決まり）は、依頼者が明言したものだけを足します。足すものをすべて選んでください。

A. 配備先が決まるまで、実在の宛先・外部の SMTP へは送らない。手元で見るときは、メールを受けて画面で見せるだけの受け手を compose の profile で起動する。SMTP の接続先と資格情報は環境変数（`.env`）だけから受け取り、接続先の設定が無ければ送らない
B. 招待のトークンを、ログ・監査ログ・トレースの属性・エラー応答に含めない。保存はハッシュで行い、1回だけ有効で有効期限を持たせる
C. メールアドレスをアプリのログとエラー応答に出さない。メールの部品の例外のメッセージと SMTP の応答をそのまま応答に含めない。`mail.debug` を有効にしない
D. メールの本文に差し込む利用者の値は、HTML としてエスケープされる差し込みだけで入れる（エスケープしない `{{{ }}}`・`{{& }}` を使わない）。招待の URL は設定したベース URL だけから組み立て、要求の Host ヘッダーから組み立てない
E. どれも足さない
