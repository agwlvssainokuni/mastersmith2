# Personas — user-management

この Intent に関わる利用者を3人に分ける（`user-stories-questions.md` の Q1: A）。同じ人が立場を移る（招待された人が登録を完了してログインした利用者になる、管理者もログインした利用者である）。ストーリーは、その操作をするときの立場で書く。

## P1 管理者（admin）

| 項目 | 内容 |
|---|---|
| 役割 | 管理者フラグを持つ MasterSmith の利用者。管理画面で、利用者を招待し、招待の状況を見て、送り直し・取り消しを行う（`requirements.md` の FR1・FR3） |
| 目的 | ・使う人に、その人の言語で招待を届け、自分で登録してもらう<br>・送信に失敗した・使われていない招待を見つけ、送り直すか取り消す<br>・誰がいつ招待したかを後から追える（招待中の間は一覧の「招待した管理者」「招待した日時」で見られ、操作は監査ログにも残る。監査ログを見る画面はこの Intent に無い） |
| 困りごと | ・今は初期管理者のほかに利用者を作る道が無い<br>・メールが届かなかったときに、それが分からないと相手を待たせてしまう（この Intent で分かるのは SMTP への送信の失敗まで。宛先の誤りなどで相手に届かなかったこと（戻りのメール）は分からない）<br>・誤って招待した人を、そのまま登録させたくない |
| IT への慣れ | 中〜高 |
| 利用の頻度 | 低い（新しい人が加わるとき。月に数回ほど） |

## P2 招待された人（invitee）

| 項目 | 内容 |
|---|---|
| 役割 | 管理者から招待メールを受け取った人。まだ MasterSmith の利用者ではなく、ログインできない（FR1.3・FR4） |
| 目的 | ・招待メールのリンクから、自分でパスワードと表示の設定を決めて登録を終える<br>・自分の言語で案内を読む<br>・登録を終えた後、どのメールアドレスでログインすればよいか分かる |
| 困りごと | ・リンクの期限が切れていたり取り消されていたりすると、どうすればよいか分からない（送り直すと前のリンクは使えなくなるため、いちばん新しいメールを探す必要がある）<br>・パスワードの決まりに合わないときに、何が足りないのか分からない |
| IT への慣れ | 低〜中（業務の担当者で、MasterSmith を初めて使う） |
| 利用の頻度 | 1回（登録のときだけ） |

## P3 ログインした利用者（signed-in user）

| 項目 | 内容 |
|---|---|
| 役割 | 登録を終えて MasterSmith にログインしている人。管理者も含む（FR5・FR6） |
| 目的 | ・自分の見やすい言語・テーマ・文字の大きさで使う<br>・表示する氏名を自分で決め、画面の右上に自分の名前で表示される<br>・パスワードを自分で変える |
| 困りごと | ・同じ PC をほかの人と使うと、前の人の表示の設定のまま画面が出る。この Intent で解けるのはログインの後だけで、ログインの前の画面（ログインの画面）は、そのブラウザで最後に使った人の設定で出る（決めた動作。要件の FR5.5）。前の人の言語が読めないときの助けとして、ログインの前の画面に言語の切り替えを置く（Could、`user-stories-questions.md` の M6）<br>・画面によって言語がそろっていないと読みにくい |
| IT への慣れ | 低〜高 |
| 利用の頻度 | 日常的（ただし設定を変えるのはまれ） |

## 関係と優先度

- 優先度は **P1 管理者 = P2 招待された人 > P3 ログインした利用者** とする。招待と登録の完了がそろわないと利用者が増えず、この Intent の目的（利用者を増やす）が果たせないため。
- P1 が招待すると P2 が生まれ、P2 が登録を完了すると P3 になる。P1 自身も P3 として自分の設定を変える。
- P3 のストーリー（US4.1・US5.1）は、既存の初期管理者でも確かめられるため、P2 の登録の完了を待たずに作れる。
