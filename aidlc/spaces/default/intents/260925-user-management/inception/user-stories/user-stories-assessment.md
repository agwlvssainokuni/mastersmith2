# User Stories — 実施の判断

## 判断

**実施する（Execute）**

## 理由

- 利用者が画面で操作する機能が中心である。管理者の招待・招待の一覧・送り直し・取り消し、招待された人の登録の完了、ログインした利用者のプリファレンスとパスワードの変更がこれに当たる（`aidlc/spaces/default/intents/260925-user-management/inception/requirements-analysis/requirements.md` の FR1〜FR6・FR10）。
- 利用者の立場が3つある。管理者、まだ利用者ではない招待された人、ログインした利用者で、それぞれ見える画面と許される操作が違う（FR10）。
- 招待の状態（招待中・期限切れ・送信の失敗・取り消し・使用済み）の移り変わりと、メール送信の失敗・同時の操作・列挙の防止などの失敗の場合が多い。利用者から見た流れと受け入れ基準に落とすと、設計とテストの抜けを防げる。

## 考慮した要素

| 要素 | 内容 |
|---|---|
| 種類 | 既存のアプリへの機能の追加（ブラウンフィールド） |
| 利用者に見える範囲 | 管理画面の招待の画面と一覧、ログインなしで開く登録の完了の画面、プリファレンスとパスワードの変更の画面、招待メール、全画面の見た目（テーマ・文字の大きさ・言語・ブランドカラー・フォント） |
| 複雑さ | 招待の状態の移り変わり、外へのメール送信とその失敗、画面の表示の設定の当て方（ログインの前後・ブラウザに残った値）、言語の適用の範囲 |
| 既存の仕組みとの関係 | 利用者の作成・パスワードの規則・ログイン・管理者向け領域と認可・監査ログ・エラー応答の形・画面の登録の仕組みを使う（`aidlc/spaces/default/codekb/mastersmith2/business-overview.md`・`component-inventory.md`） |
| チームの進め方 | 必須テスト（招待と登録の完了・パスワードの変更・メール）と E2E の代表の流れ1本（`aidlc/spaces/default/intents/260925-user-management/inception/practices-discovery/team-practices.md`） |

## ストーリーが特に役立つところ

- 招待から登録の完了・ログインまでの一続きの流れと、途中の失敗（期限切れ・取り消し・送信の失敗・同じメールアドレス）の受け入れ基準
- 登録の完了とプリファレンスで、表示の設定がどの時点で画面に当たるか（ログインの前後・ブラウザに残った値）
- 管理者・招待された人・ログインした利用者のそれぞれに、許される操作と拒否の仕方

## 進め方

- ストーリーの計画は `aidlc/spaces/default/intents/260925-user-management/inception/user-stories/user-stories-questions.md`（Q1〜Q5・F1）で決め、デザイナー・開発・品質の担当の意見（`contributions/`）のうち判断が分かれた点を M1〜M9 で依頼者に確かめてから、ストーリーに取り込んだ。
