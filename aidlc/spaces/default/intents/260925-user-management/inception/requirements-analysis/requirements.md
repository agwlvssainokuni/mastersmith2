## 1. Intent の分析

- **目的**: 管理者が利用者を招待して増やせるようにし（ロードマップの Intent G）、利用者が自分の表示の設定とパスワードを自分で管理できるようにする（Intent H）。2つを1つにまとめる（DESC、RD-9.3）。
- **背景**: 今の利用者は起動時に自動で作る初期管理者だけで、ほかに利用者を作る道が無い（KB `business-overview.md`）。利用者の表は氏名・状態・表示の設定を持たず（K-1）、メール送信の仕組みも無い（K-3）。画面の表示の設定はデザインシステム make-you-chic-ui がブラウザに保存するだけで、利用者ごとに保存する道が無い（K-4・K-5）。
- **利用者**:
  - 管理者（管理者フラグを持つ利用者）: 利用者を招待し、招待を管理する（RD-5.7、RD-5.8）
  - 招待された人: 招待のリンクから登録を完了する（RD-5.8）
  - ログインした利用者（管理者を含む）: 自分のプリファレンスとパスワードを変える（RD-5.9）
- **成功基準**:
  - 管理者が管理画面から、メールアドレスと言語を指定して招待でき、その言語の HTML の招待メールが届く
  - 招待された人が、リンクから自分でパスワードと表示の設定を決めて登録を完了し、ログインできる
  - ログインした利用者が、言語・テーマ・文字の大きさ・氏名・パスワードを自分で変えられ、次のログインでも保たれる
  - ブランドカラーとフォントファミリーが、インスタンス全体の設定どおりに全画面に当たる
- **種類・規模**: 既存のアプリへの機能の追加（ブラウンフィールド）。バックエンド（利用者・認証・監査・新しいメール送信）・フロントエンド（新しい3つの画面と表示の設定の当て方）・内部DB（新しい表と列）にまたがる。メール送信（外への送信）と、外部の自前の部品（java-mustache-processor）の取り込みは、このリポジトリに前例が無い（K-3、TP）。

## 2. 機能要件

受け入れ基準は Given/When/Then で書く。★は設定で変更できる値で、表記は既定値。

### FR1 利用者の招待（管理者）

出典: DESC、RD-5.8、RQ1、RQ2、RQ5、RQ12、RF4、PM（Mandated・Forbidden）

- **FR1.1** 管理者は、管理画面で招待したい人のメールアドレスと言語（ja・en）を入れて招待できる。言語の初期値は、操作する管理者自身の言語（FR7.4）とする。招待の時に入れるのはこの2つだけとする（RQ5）。
  - Given 言語が en の管理者 / When 招待の画面を開く / Then 言語の初期値が en になっている
  - Given 管理者 / When メールアドレスと言語 ja を入れて招待する / Then 招待が作られ、ja の招待メールの送信が行われる
- **FR1.2** メールアドレスは既存の決まり（前後の空白を除き小文字にそろえる、254 文字まで）で正規化・検証する。言語は ja・en のどちらかに限る。
  - Given 形式の正しくないメールアドレス、または ja・en 以外の言語 / When 招待する / Then 入力の誤りとして拒否され、招待は作られない
- **FR1.3** 招待は利用者の表とは別に持ち、登録の完了（FR4）まで利用者を作らない。招待中の人はログイン・トークンの更新・アクセストークンの認証のどの経路にも現れない（RQ1、K-1・K-2）。
  - Given 招待中の人のメールアドレス / When そのメールアドレスでログインを試みる / Then 存在しない利用者と同じ 401 になる
- **FR1.4** 招待しようとしたメールアドレスが、すでに利用者として登録されていれば拒否する。すでに招待中（期限内で、取り消されていない、未完了）であれば拒否し、一覧（FR3）から送り直すよう画面で案内する（RF4）。
  - Given 登録済みの利用者のメールアドレス / When 招待する / Then 登録済みであることを示すエラーになり、招待は作られない
  - Given 招待中の人のメールアドレス / When 招待する / Then 招待中であることと送り直しの案内を示すエラーになり、新しい招待は作られない
- **FR1.5** 招待ごとに、推測できない招待のトークンを作る。トークンは内部DB にハッシュ値だけを保存し、1回だけ有効で、有効期限を持つ（PM（Mandated））。有効期限は作成（または送り直し）から ★24 時間 とする（RQ2）。
  - Given 作成から 24 時間ちょうど前の招待 / When リンクを使う / Then 有効
  - Given 作成から 24 時間を過ぎた招待 / When リンクを使う / Then 拒否される
- **FR1.6** 招待には、招待した管理者・招待した日時・言語・有効期限・送信の結果を記録する（RF1）。
- **FR1.7** 招待のリンクの URL は、設定したベース URL（`mastersmith.web.base-url`）だけから組み立て、要求の Host ヘッダーからは組み立てない（PM（Forbidden）、K-9）。
- **FR1.8** ベース URL か SMTP の接続先のどちらかが設定されていないときは、アプリは起動するが招待（作成・送り直し）を使えないようにし、理由の分かるエラーを返す。管理画面にもその理由を表示する（RQ12、PM（Mandated））。
  - Given ベース URL が設定されていない / When 管理者が招待する / Then 招待の機能が使えない理由を示すエラーになり、招待は作られない

### FR2 招待メール

出典: DESC、RD-5.8、RD-8、RQ4、RQ9、PM（Mandated・Forbidden）、TP

- **FR2.1** 招待メールは HTML のメールとし、言語（ja・en）ごとのテンプレートを自前の Mustache エンジン（java-mustache-processor）で描いて作る。件名は、描いたテンプレートの `<title>` 要素の文面とする（DESC、RD-8）。
  - Given 言語 en の招待 / When 招待メールを作る / Then en のテンプレートから作られ、件名は en のテンプレートの `<title>` の文面になる
- **FR2.2** 招待メールの本文には、招待のリンクと有効期限を載せる。本文に差し込む値は HTML としてエスケープされる差し込みだけで入れる（PM（Forbidden））。
  - Given `<` や `"` を含む値 / When 本文に差し込む / Then タグや属性としてそのまま出ない
- **FR2.3** 招待メールの送信は、内部DB のトランザクションの外で行い、送信を待つ間に内部DB の接続を持ち続けない（RQ4、K-10）。
- **FR2.4** 送信に失敗したとき（受け手が接続を拒む・応答しないなど）も招待は残し、送信に失敗したことを招待に記録する。管理者は一覧（FR3.1）で失敗を確かめ、送り直せる（FR3.2）（RQ4）。
  - Given SMTP の受け手が接続を拒む / When 招待する / Then 招待は作られ、送信の結果は「失敗」として記録され、管理画面に失敗が表示される
- **FR2.5** SMTP の接続先と資格情報は環境変数（`.env`）だけから受け取る。配備先が決まるまで、実在の宛先や外部の SMTP へは送らない（PM（Mandated・Forbidden）、TP）。
- **FR2.6** 送信の失敗の応答とログには、宛先のメールアドレス・SMTP の応答・資格情報を含めない（PM（Forbidden））。

### FR3 招待の管理（一覧・送り直し・取り消し）

出典: RQ3、RQ4、RF4

- **FR3.1** 管理者は、管理画面で招待中の人の一覧を見られる。一覧には、メールアドレス・言語・招待した日時・有効期限・送信の結果（成功・失敗）・期限切れかどうかを表示する（RQ3、RQ4）。
  - Given 招待中の人が2人（うち1人は送信に失敗）/ When 一覧を開く / Then 2人が表示され、1人に送信の失敗が表示される
- **FR3.2** 管理者は、一覧から招待を送り直せる。送り直すと前のリンクは無効になり、新しいトークンと新しい有効期限（★24 時間）で招待メールを送る（RQ3）。期限切れの招待も送り直せる。
  - Given 招待中の人 / When 送り直す / Then 前のリンクは拒否され、新しいリンクが有効になる
- **FR3.3** 管理者は、一覧から招待を取り消せる。取り消した招待のリンクは無効になる（RQ3）。
  - Given 招待を取り消した / When そのリンクを使う / Then 拒否される

### FR4 登録の完了（招待された人）

出典: DESC、RD-5.8、RD-5.9、RQ5、RQ6、RQ7、RF3、TP

- **FR4.1** 招待された人は、招待メールのリンクから登録の完了の画面をログインせずに開ける。期限切れ・使用済み・取り消し済み・存在しない・改ざんしたリンクは拒否し、どの理由でも同じ応答にして、応答から利用者や招待の有無を推測できないようにする（TP）。
  - Given 期限切れのリンクと存在しないリンク / When それぞれ開く / Then どちらも同じ状態コードと同じ `code` の拒否になる
- **FR4.2** 登録の完了の画面では、パスワード（必須、確かめのため2回入力）・氏名・言語・テーマ・文字の大きさを設定する。初期値は、氏名がメールアドレス・言語が招待の言語・テーマが `system`・文字の大きさが `md` とする。氏名はメールアドレスのままでもよい（RQ5、RQ6、RQ8）。
  - Given 言語 ja の招待 / When 登録の完了の画面を開く / Then 氏名にメールアドレス、言語に ja、テーマに system、文字の大きさに md が入っている
- **FR4.3** 登録の完了の画面は、招待の言語で表示する。テーマと文字の大きさは、そのブラウザに最後に保存された値で表示する（RF3）。
- **FR4.4** パスワードは既存の規則（12 文字以上（コードポイント）、UTF-8 で 72 バイト以内）で検証し、2回の入力が一致しなければ拒否する。
  - Given 11 文字のパスワード / When 登録を完了する / Then 規則に合わないことを示すエラーになる
  - Given 12 文字のパスワード / When 登録を完了する / Then 通る
- **FR4.5** 登録を完了すると、利用者（管理者フラグなし）が作られ、入れた氏名・言語・テーマ・文字の大きさとパスワード（bcrypt のハッシュ）が保存され、招待は使用済みになる。既存の利用者の作成の流れ（アカウントのロックの状態の用意を含む）を通す。
  - Given 有効なリンクと正しい入力 / When 登録を完了する / Then 利用者が作られ、同じリンクをもう一度使うと拒否される
- **FR4.6** 同じ招待で登録の完了が同時に2回行われても、利用者は1人だけ作られる。完了の時点で同じメールアドレスの利用者がすでにいれば拒否する。
- **FR4.7** 登録を完了したら、ログインの画面へ移る。自動ではログインしない（RQ7）。

### FR5 プリファレンス（ログインした利用者）

出典: DESC、RD-5.9、RQ8、RF2、K-4、K-5

- **FR5.1** ログインした利用者は、プリファレンスの画面で自分の氏名・言語・テーマ・文字の大きさを見て、変えて、内部DB に保存できる（RD-5.9、RF2）。
  - Given ログインした利用者 / When テーマを dark にして保存する / Then 内部DB に保存され、次にログインしたときも dark で表示される
- **FR5.2** 値は、言語が ja・en、テーマが light・dark・system、文字の大きさが sm・md・lg に限る（make-you-chic-ui の文字の大きさの3段階、K-4）。氏名は空にできない。
  - Given テーマに system・light・dark 以外の値 / When 保存する / Then 入力の誤りとして拒否される
- **FR5.3** 保存した設定は、保存した直後から画面に当たる。テーマが `system` のときは、OS の配色の設定（ライト・ダーク）に合わせて表示する。
- **FR5.4** ログインしたら、その利用者の内部DB の設定（言語・テーマ・文字の大きさ）を画面に当てる。同じブラウザに残った前の利用者の値は使わない（RQ8）。
  - Given 前の利用者がブラウザで dark を使い、次の利用者の設定が light / When 次の利用者がログインする / Then light で表示される
- **FR5.5** ログインの前の画面（ログインの画面など）は、そのブラウザに最後に保存された言語・テーマ・文字の大きさで表示する（RQ8）。保存された値が無いときは、今までどおりブラウザの言語設定と OS の配色の設定で表示する。

### FR6 パスワードの変更

出典: DESC、RD-5.9、RQ10、TP

- **FR6.1** ログインした利用者は、今のパスワードと新しいパスワード（確かめのため2回入力）を入れて、パスワードを変えられる（RD-5.9）。
  - Given 正しい今のパスワードと規則に合う新しいパスワード / When 変更する / Then 新しいパスワードでログインでき、前のパスワードではログインできない
- **FR6.2** 今のパスワードが誤っていれば拒否する。新しいパスワードは FR4.4 と同じ規則で検証する。
  - Given 誤った今のパスワード / When 変更する / Then 拒否され、パスワードは変わらない
- **FR6.3** パスワードを変えても、発行済みのリフレッシュトークン（変更した端末・ほかの端末とも）は無効にしない。アクセストークンも有効期限まで使える（RQ10、PM（DECIDED））。
  - Given 端末 A と B でログイン中 / When 端末 A でパスワードを変える / Then 端末 B のリフレッシュトークンで更新できる（決めた動作として確かめる）

### FR7 利用者の言語の適用

出典: DESC、RD-5.8、RQ9

- **FR7.1** ログインした後の画面の文言は、利用者の言語（ja・en）で表示する。
- **FR7.2** ログインした利用者の要求に対するサーバーのエラーの説明文は、利用者の言語で返す。ログインしていない要求は、今までどおり要求の `Accept-Language` で決める。
  - Given 言語 en の利用者がブラウザの言語 ja でログイン中 / When 入力の誤りの応答を受ける / Then 説明文は en になる
- **FR7.3** 利用者へ送るメールは、その利用者の言語で送る。招待メールは、招待の言語で送る（FR2.1）。
- **FR7.4** 管理者が招待するときの言語の初期値は、その管理者自身の言語とする（FR1.1）。

### FR8 インスタンス全体の見た目の設定

出典: DESC、RD-5.9、RQ12、K-4

- **FR8.1** ブランドカラー（blue・green・purple・orange）とフォントファミリー（sans・serif）は、`application.yml` のインスタンス全体の設定とし、ログインの前後を問わず全画面に当てる。利用者ごとには変えられない（DESC、RD-5.9）。
- **FR8.2** 設定が無いときは既定（ブランドカラー blue、フォントファミリー sans）を使う。許されない値のときも既定を使い、警告のログを出す。どちらの場合も起動は止めない（RQ12）。
  - Given ブランドカラーに red を設定 / When 起動する / Then 起動し、blue で表示され、警告のログが出る

### FR9 監査ログ

出典: RQ11、RF1、TP、PM

- **FR9.1** 次の操作を監査ログに残す。操作した人・対象・結果を残し、パスワード・招待のトークン・招待のリンクの URL は残さない（RQ11、RF1、PM（Forbidden））。
  - 管理者の招待・送り直し・取り消し
  - 登録の完了と、期限切れ・使用済み・取り消し済み・存在しない・改ざんしたリンクによる登録の失敗
  - パスワードの変更（成功と、今のパスワードの誤りによる失敗）
  - Given 管理者が招待を取り消す / When 監査ログを見る / Then 取り消した管理者・対象の招待・結果が記録されている
- **FR9.2** 招待メールの送信の失敗と、氏名・言語・テーマ・文字の大きさの変更は監査ログに残さない（RQ11、RF1）。

### FR10 画面の置き場

出典: RD-5.7、RD-5.8、RD-5.9、KB `code-structure.md`

- **FR10.1** 招待と招待の一覧は管理者だけが使える管理画面の中に置く。サーバー側でも管理者だけに許し、未認証は 401、管理者でない利用者は 403 とする（RD-5.7、TP）。
- **FR10.2** プリファレンスとパスワードの変更の画面は、ログインした利用者が使える画面に置き、ユーザーメニューから開けるようにする。
- **FR10.3** 登録の完了の画面は、ログインせずに開ける単独の画面（アプリの枠の外）とする。

## 3. 非機能要件

- **NFR1 招待のトークン**: トークンは暗号学的に安全な乱数で作り、推測できない長さ（128 ビット以上の乱数）とする。内部DB にはハッシュ値だけを保存し、ログ・監査ログ・トレースの属性・エラー応答に含めない（PM（Mandated・Forbidden））。出典: PM、TP
- **NFR2 個人情報とメール**: メールアドレスをアプリのログとエラー応答に含めない。メールの部品の例外のメッセージと SMTP の応答をそのままエラー応答に含めない。メールの部品のデバッグ出力を有効にしない（PM（Forbidden））。出典: PM
- **NFR3 列挙の防止**: 登録の完了の拒否（FR4.1）とログインの拒否（FR1.3）は、理由によらず同じ応答とし、応答から利用者・招待の有無を推測できないようにする。出典: TP、KB
- **NFR4 認可**: 招待・一覧・送り直し・取り消しの API は管理者だけ、プリファレンスとパスワードの変更の API はログインした利用者だけ、登録の完了の API はログインなしで呼べる。どれもサーバー側のテストで 401・403・200 を確かめる（画面で隠すことを代わりにしない）。出典: TP、K-6
- **NFR5 接続の使い方**: 招待メールの送信の間、内部DB の接続を持たない。要求1件で接続を2本使う経路（確定の後の監査の記録）を含め、同時の要求で接続プールが尽きないことを負荷の試験で確かめる。出典: PM（Corrections）、K-10
- **NFR6 応答時間**: 招待・送り直しの API は、SMTP の送信を含めて 95 パーセンタイルで 5 秒以内に応答する。SMTP の接続と読み取りには時間切れを設け、受け手が応答しないときも時間切れの後に送信の失敗として応答する [assumption]（具体の時間切れの値は NFR 要件の段で決める）。プリファレンス・パスワードの変更・登録の完了の API は、既存の API と同じく 95 パーセンタイルで 1 秒以内 [assumption]。出典: RQ4
- **NFR7 アクセシビリティ**: 新しい画面（招待・招待の一覧・登録の完了・プリファレンス・パスワードの変更）の画面部品ごとにアクセシビリティの検査を1件入れる。テーマ（light・dark）と文字の大きさ（sm・md・lg）のどの組み合わせでも表示が崩れない。出典: TP
- **NFR8 多言語**: 新しい画面の文言、エラーの説明文、招待メールのテンプレートは、ja・en の両方を用意する。出典: TP、RQ9
- **NFR9 テスト**: `team.md` の必須テスト（招待と登録の完了・パスワードの変更・利用者へメールを送る機能）を書く。メールのテストは JVM の中で起動するテスト用の SMTP の受け手で実際に受けて確かめ、送信の失敗のテストも入れる。E2E に招待から登録の完了までの代表の流れを1本足す。カバレッジの下限（行 80%・分岐 70%）を守り、一覧で外している既存のパッケージ（`user` の3つを含む）に手を入れたらパッケージごとの下限の対象に戻す。出典: TP
- **NFR10 スキーマの変更**: 内部DB のスキーマの変更は Flyway の V7 以降の前進のみとし、1つ前の版のアプリが動く後方互換を保つ。既存の利用者（初期管理者）には、氏名・言語・テーマ・文字の大きさの初期値を入れる（FR 前提 A3）。出典: TP、KB `code-structure.md`
- **NFR11 手元の確かめ**: 開発者の PC 上では、メールを受けて画面で見せるだけの受け手を compose の profile で見たいときだけ起動して招待メールを確かめられる。出典: TP、PM

## 4. 制約

- 自前の Mustache エンジン java-mustache-processor は、Git サブモジュール `vendor/java-mustache-processor` として取り込み、Gradle の composite build で組む。中身をこのリポジトリから直接変更しない。版は固定先のコミットで固定し、依存の取得元を Maven Central だけにする決まりは崩さない。推移依存も lockfile と脆弱性検査の対象に含めることを条件とし、最初に取り込む Bolt で確かめる（TP、PM（Forbidden））。
- make-you-chic-ui は変更しない。テーマの `system` と利用者ごとの設定の当て方は frontend の側で扱う（PM（Forbidden）、K-4）。
- 新しい依存（メールの送信の部品、テスト用の SMTP の受け手など）は、採用の前にライセンスを確かめ、Apache License 2.0 と異なるものは理由を設計の記録に残す（TP）。
- 内部DB は組み込みの H2 で、1インスタンスだけで動く前提（KB `architecture.md`）。
- 管理者かどうかは管理者フラグだけで決める。ロール・グループは扱わない（RD-5.7、RD-9.3）。
- アクセストークンは失効の仕組みを持たない（PM（DECIDED））。

## 5. 前提

- **A1** 招待の一覧（FR3.1）に出すのは、完了も取り消しもしていない招待（期限切れを含む）とする。完了した招待・取り消した招待は一覧に出さない [assumption]。理由: 「招待中の人の一覧」（RQ3）の読み方として、管理者が次に行う操作（送り直し・取り消し）の対象に絞るため。
- **A2** 登録の完了の画面での氏名の初期値のメールアドレスは、招待のメールアドレス（正規化した値）とする。RQ5 の「ユーザレコードの氏名にはメアドを入れておき」は、RQ1 で招待を別の表に持つことにしたため、登録の完了の画面の初期値として読む。
- **A3** 既存の利用者（初期管理者）の氏名はメールアドレス、言語は ja（画面の既定の言語）、テーマは system、文字の大きさは md を初期値とする [assumption]。
- **A4** 招待を取り消した後に同じメールアドレスを招待するのは、FR1.4 の「招待中」に当たらないため許す [assumption]。

## 6. 範囲外

- ロール・グループ・作業ロールの切り替え・権限の設定（ロードマップの Intent F）
- 利用者の無効化・削除、管理者フラグの付け外し、利用者の一覧（招待中を除く）
- パスワードを忘れたときの再設定、メールアドレスの変更
- 招待メール以外のメール（パスワードの変更の知らせなど）
- 実在の宛先・外部の SMTP への送信と、配備先の SMTP の設定（配備先が決まってから）
- 監査の記録の共通化（PM（DECIDED）のとおり、業務データの CRUD を扱う後続の Intent で検討する）
