# Requirements Analysis の質問

依頼文とロードマップ（Intent G「ユーザー登録・招待フロー」・Intent H「ユーザープリファレンス」）、コード知識ベースの所見（K-1〜K-11）、`team.md`・`project.md` の決まりから、要件を決めるのに足りない点を尋ねます。

決まっていること（質問にしない）:
- 利用者の登録は管理者だけが行える。登録の時に管理者が対象の言語（ja/en）を選び、既定は管理者自身の言語。その言語の HTML の招待メールを、java-mustache-processor のテンプレートで送り、件名はテンプレートの `<title>` 要素の文面から取る（依頼文・ロードマップ）。
- 招待された人はパスワードを含むプリファレンスを設定して登録を完了する。プリファレンスは言語（ja/en）・テーマ（light/dark/system）・文字の大きさ・パスワード。内部DB に保存する（依頼文）。
- ブランドカラーとフォントファミリーは `application.yml` のインスタンス全体の固定の設定（依頼文）。値は make-you-chic-ui の持つ値（ブランドは blue・green・purple・orange、フォントは sans・serif）に限られる（K-4）。
- パスワードの規則は今の規則（12 文字以上・UTF-8 で 72 バイト以内・bcrypt で保存）を使う。
- 招待のトークンはハッシュで保存し1回だけ有効で有効期限を持ち、ログ等に出さない。招待の URL は設定したベース URL だけから組み立てる。配備先が決まるまで実在の宛先・外部の SMTP へは送らない（`project.md` の Mandated・Forbidden）。
- 管理者かどうかは今までどおり管理者フラグだけで決める。ロール・グループはロードマップの Intent F で扱う。

質問は Standard の目安（5〜8）より多い 12 問です。2つの Intent をまとめており、今のコードに無い仕組み（利用者の状態・メール送信・画面の設定の保存）の境目が多いためです。
