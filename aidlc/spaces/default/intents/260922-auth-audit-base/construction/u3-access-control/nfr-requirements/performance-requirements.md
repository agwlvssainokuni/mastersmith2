# Performance Requirements — U3 管理画面のアクセス制御（u3-access-control）

U3 の性能の要件。測定の環境は、当面の配備先である開発者の PC 上のコンテナとする。

| ID | 要件 | 測り方 | 出典 |
|---|---|---|---|
| NFR1.1 | 管理者向け領域の確認用 API は、同時に 10 件の要求が来る状態で、95% が 300 ミリ秒以内に応答する（成功・403 とも） | 負荷の試験（同時10件を繰り返し、95 パーセンタイルを測る） | Q1、NFR1 |
| NFR1.2 | アクセスの判定（パスの照合と管理者かどうかの判定）は、U2 の要求ごとの処理（トークンの検証と利用者の読み取り、95% で 50 ミリ秒以内）に加えて、内部DBへの問い合わせを増やさない | 判定の処理で発行する SQL の回数を確かめる | U2 の NFR1.4、U3 の決まり 2.4 |
| NFR1.3 | アクセス拒否の出来事の通知と記録（U4）は、同じスレッドで行うが、401／403 の応答を 100 ミリ秒以上遅らせない | 拒否の応答時間を測る | U3 の決まり 3.5、U4 の決まり 1.3 |

NFR1.3 の値は設計上の目標であり、測定の結果に応じて NFR Design で見直す。監査ログの書き込みは要求と同じスレッドで内部DBへ行うため、内部DBが遅いと 401／403 の応答も遅れる危険がある（書き込みの失敗は応答に影響させないが、時間はかかる）。監査イベント1件の書き込みの目標（U4 の NFR1.1、95% が 50 ミリ秒以内）は、この 100 ミリ秒の内側に収まる。
