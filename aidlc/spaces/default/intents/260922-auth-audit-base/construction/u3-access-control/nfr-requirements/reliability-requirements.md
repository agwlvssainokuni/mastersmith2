# Reliability Requirements — U3 管理画面のアクセス制御（u3-access-control）

要件定義書には信頼性の NFR が無いため、本書の要件の ID は、内容が最も近い要件定義の NFR（NFR7 多言語、NFR8 アクセシビリティ、NFR9 保守性、NFR10 観測性）に枝番を付けている。

## 1. 信頼性

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR10.1 | 出来事の受け取り側（監査ログ）で失敗が起きても、401／403 の応答は変わらない | 受け取り側の失敗を起こしたテスト | U3 の決まり 3.5 |
| NFR9.1 | 管理者向け領域は、確認用 API が成功するまで中身を表示しない。通信の失敗などのエラーでは、一般的なエラーの文言を表示し、画面全体を止めない | 画面のテスト | U3 の決まり 5.2 |

## 2. 品質（多言語・アクセシビリティ・保守性）

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR7.1 | 「管理」、管理者向け領域の見出しと説明の文言を日本語・英語でそろえる | テスト | NFR7、U3 の決まり 5.3 |
| NFR8.1 | 管理者向け領域の部品ごとにアクセシビリティ検査（vitest-axe）を1件入れ、違反が無いこと。確認中であることを支援技術に伝える | テスト | NFR8 |
| NFR9.2 | チームの進め方で必須とされた認可のテスト（未認証 401、管理者フラグなし 403、管理者 200 をサーバー側で確かめる）と、パスの照合の境界（NFR3.3）のテストを入れる | テストの一覧の確認 | NFR9、TP |
