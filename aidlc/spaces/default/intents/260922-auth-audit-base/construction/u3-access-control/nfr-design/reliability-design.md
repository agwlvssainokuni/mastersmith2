# Reliability Design — U3 管理画面のアクセス制御（u3-access-control）

U3 の信頼性と品質の要件（`reliability-requirements.md` の NFR10.1、NFR9.1、NFR9.2、NFR7.1、NFR8.1）を満たす設計。処理の流れは U3 の `functional-spec.md`（WF1〜WF4）、技術は U3 の `tech-stack-decisions.md` に従う。性能・安全・拡張性・観測性の要件（`performance-requirements.md`・`security-requirements.md`・`scalability-requirements.md`・`observability-requirements.md`）は各設計書で扱う。`contract-summary.md` は、本ワークフローで Contract Design を行わないため無い。

## 1. 記録の失敗を応答に持ち込まない（NFR10.1）

- U3 はアクセス拒否の出来事をアプリの中に知らせるだけで、受け取り側（U4）を知らない（BR3.5、ADR-004）。
- 出来事は 401／403 の処理の中で、応答を書く前に同じスレッドで知らせる。U4 はその場で自分のトランザクションで記録し、失敗は U4 の中で受け止めてアプリのログに ERROR を出す。
- 念のため U3 の 401／403 の処理も、出来事の通知で例外が戻ってきた場合は捕まえて WARN を1回出し、応答はそのまま返す（受け止めの二重の備え。例外を黙って捨てない）。
- テスト: 受け取り側で例外を起こす出来事の受け取りを置き、401／403 の応答の状態コード・code・本文が変わらないことを確かめる。

## 2. 画面の振る舞い（NFR9.1）

| 確認用 API の結果 | 画面 |
|---|---|
| 確認中 | 中身を表示しない。確認中であることを支援技術に伝える（`aria-busy` と読み上げ用の文言） |
| 204 | 見出しと説明を表示する |
| 403 | 「ページが見つかりません」 |
| 401 | U2 の API 呼び出しの共通部分が更新と送り直しを行い、失敗ならログイン画面へ |
| そのほか（通信の失敗、5xx） | 一般的なエラーの文言を管理者向け領域の中に表示し、アプリシェルとほかの画面は動き続ける |

- 表示のたびに確認をやり直す（BR5.2）。結果をメモリに残さない。

## 3. 品質（NFR9.2、NFR7.1、NFR8.1）

| 要件 | 設計 |
|---|---|
| NFR9.2 必須の認可のテスト | サーバー側で 401／403／204 を確かめ、パスの境界のテストを入れる（`security-design.md` 7章） |
| NFR7.1 多言語 | 「管理」、見出し、説明、確認中の文言を日英で用意し、鍵の一致を U1 のテストの仕組みで確かめる |
| NFR8.1 アクセシビリティ | 管理者向け領域の部品ごとに vitest-axe の検査を1件。確認中の状態も検査する |
