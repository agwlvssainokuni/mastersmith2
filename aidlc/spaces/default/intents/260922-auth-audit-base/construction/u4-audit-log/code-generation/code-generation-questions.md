### Q4. 残りの確認事項（C1〜C5・C7〜C9）を、このまま進めてよいですか？

- C1 パッケージは `cherry.mastersmith.audit`（`domain`・`repository`・`service`。API が無いため `web` は作らない）
- C2 認証の出来事は確定の後に、アクセス拒否の出来事は要求と同じ流れの中で受け取る。U4 の受け取りを最優先の順番にする（ほかの受け取り側が例外を投げても監査が飛ばないように）
- C3 表は `audit_events`、索引は発生の日時に1つ、移行のファイルは `V4__u4_audit_event.sql`
- C4 列の長さは切り詰めの上限の2倍にする（絵文字を含む値が、数え方の違いで上限の2倍の長さになり得るため）
- C5 遅れの WARN のしきい値 200 ミリ秒は定数とし、時間の取り方はテストで差し替えられる形にする
- C7 監査の記録を後から変えられない作りにする（追記と読み取りだけの保存部品、更新できない設定、U4 専用の構造の検査）
- C8 結合テストは表を直接読んで確かめる。E2E は増やさない（監査を見る API が無いため、テストのためだけの API は作らない）
- C9 書き込みの失敗は、失敗する保存部品に差し替えて再現する

- A. すべてこのまま進めてよい
- B. 直したい点がある（番号と内容を書く）
- X. Other (please specify)

[Answer]: A. すべてこのまま進めてよい
