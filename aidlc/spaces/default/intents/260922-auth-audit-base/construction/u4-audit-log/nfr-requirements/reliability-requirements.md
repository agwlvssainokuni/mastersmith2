# Reliability Requirements — U4 監査ログ（u4-audit-log）

要件定義書には信頼性の NFR が無いため、本書の要件の ID は、内容が最も近い要件定義の NFR（NFR9 保守性、NFR10 観測性）に枝番を付けている。

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR10.1 | 監査イベントの書き込みに失敗しても、元の操作（ログイン・ログアウト・401／403）の応答は変わらない。失敗の例外を出来事を知らせた側へ伝えない | 書き込みの失敗を起こしたテスト | FR9.4、U4 の決まり 3.1 |
| NFR10.2 | 元の操作の内部DBの更新が確定した後に、別のトランザクションで記録する。元の操作が取り消された場合は記録しない | テスト（取り消しの場合に記録が無いこと） | U4 の決まり 1.3・1.4 |
| NFR9.1 | チームの進め方で必須とされた監査ログのテスト（対象のイベントごとに必須の項目が記録されること、存在しないユーザーIDでのログイン失敗も記録されること、書き込みに失敗しても操作が失敗しないこと）を入れる | テストの一覧の確認 | NFR9、TP |
| NFR9.2 | 監査イベントの記録（内部DB）とアプリのログを別の仕組みとし、監査イベントをアプリのログで代用しない | テスト（監査イベントが内部DBに記録されること） | FR9.5 |
