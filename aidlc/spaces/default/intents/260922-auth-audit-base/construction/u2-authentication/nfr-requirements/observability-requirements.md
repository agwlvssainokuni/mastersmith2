# Observability Requirements — U2 認証（u2-authentication）

U2 の観測性の要件。ログ・トレースの仕組みは U1 が用意し、U2 はそれを使う。

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR10.2 | ログイン成功・ログイン失敗（理由つき）・ログアウトの出来事を、U2 の決まり 7.1 の項目（日時・種類・メールアドレス・利用者ID（分かれば）・失敗の理由・接続元IP・User-Agent・トレースID）をそろえて知らせる。利用者IDは監査ログには記録されない（U4 の決まり。FR9.2 に含まれないため） | テスト | U2 の決まり 7.1、FR9.2、レビュー指摘 R-03 |
| NFR10.3 | 初期管理者を作成したときは INFO、作らなかったときは WARN（理由と直し方つき）をアプリのログに出す。パスワードの値は出さない | テスト | U2 の決まり 1.3・1.4 |
| NFR10.4 | ロックしたときは、アプリのログに INFO で「どの利用者がロックされたか（利用者ID）」を出す。メールアドレスとパスワードは出さない | テスト | ロックの発生を運用で把握するため |
| NFR10.5 | トークンの検証の失敗（401）は、アプリのログに DEBUG で理由（TOKEN_MISSING などの区分）だけを出す。トークンの値は出さない | 設定の確認とテスト | U2 の決まり 4.4、NFR3 |
| NFR10.6 | 処理中のログには、U1 の仕組みでトレースIDが付く | テスト | FR10.2 |
| NFR10.7 | ログインの失敗の割合（失敗の件数÷試行の件数）を、運用で見る指標の候補とする。本Intentでは監査ログから数える（指標の外部への公開は行わない） | 配備先が決まったときに確かめる | operation フェーズの決まり（エラーの割合の指標） |
