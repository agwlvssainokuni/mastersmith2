# NFR Requirements — Questions（U2 認証 / u2-authentication）

U2 の非機能要件で決まっていない点を確認します。要件定義で NFR の段階へ回した論点（OQ2: パスワードのハッシュ方式、トークンの署名方式と署名鍵の保管。OQ3: アカウントロックの悪用への対策、ログイン試行の回数制限）を扱います。

決定済みの事項（再確認はしません）: 技術は U1 の tech-stack-decisions.md のとおり（Spring Boot 4、Spring Security、Spring Data JPA、H2）。ログインと更新の API は p95 1秒以内（NFR1）。リフレッシュトークンの保存は速い暗号学的ハッシュ（U2 の決まり 5.1）。Cookie は HttpOnly・Secure・SameSite=Strict で送り先を認証の API に限定（U2 の決まり 5.2）。HTTPS は配備先が決まるまで扱わない。

### Q1. パスワードのハッシュ方式は、どれにしますか？

- A. Argon2id（メモリを多く使う方式。現在の推奨。Spring Security の Argon2 の仕組みを使う）
- B. bcrypt（Spring Security の既定。追加の部品が要らない。72 バイトを超える部分は無視される）
- X. Other (please specify)

[Answer]: B. bcrypt（Spring Security の既定。追加の部品が要らない。72 バイトを超える部分は無視される）

### Q2. アクセストークンの署名方式と、署名鍵の保管は、どうしますか？

発行するのも検証するのも同じアプリ（1台）です。

- A. HMAC（HS256）。署名鍵は 256 ビット以上の乱数を環境変数で渡す。鍵を替えるときは、設定を変えて再起動する（発行済みのアクセストークンは使えなくなり、画面はトークンの更新で自動で取り直す）
- B. 公開鍵方式（Ed25519 など）。秘密鍵をファイルで渡し、検証には公開鍵を使う
- X. Other (please specify)

[Answer]: A. HMAC（HS256）。署名鍵は 256 ビット以上の乱数を環境変数で渡す。鍵を替えるときは、設定を変えて再起動する（発行済みのアクセストークンは使えなくなり、画面はトークンの更新で自動で取り直す）

### Q3. ロックを悪用して他人をロックさせる妨害や、大量のログイン試行への対策は、どうしますか？（OQ3）

- A. 接続元IP ごとにログインの試行の回数を制限する（例：1分に 10 回まで。超えたら 429 を返す）。回数はアプリのメモリで数える
- B. 追加の対策はしない（利用者 50 名の社内向けのため、妨害の危険を受け入れる）
- X. Other (please specify)

[Answer]: B. 追加の対策はしない（利用者 50 名の社内向けのため、妨害の危険を受け入れる）

### Q4. Cookie で認証するトークンの更新とログアウトの API への CSRF 対策は、どうしますか？

- A. SameSite=Strict に加えて、要求の Origin ヘッダーが自分の配信元と一致することを確かめ、一致しなければ拒否する
- B. SameSite=Strict だけとする
- X. Other (please specify)

[Answer]: A. SameSite=Strict に加えて、要求の Origin ヘッダーが自分の配信元と一致することを確かめ、一致しなければ拒否する

### Q5. bcrypt の 72 バイトの上限に、どう対応しますか？

Q1 の回答（bcrypt）の確認のための追加の質問。bcrypt はパスワードの先頭 72 バイトしか使わず、日本語などは1文字3バイトのため 24 文字程度で上限に達する。Spring Security は 72 バイトを超えるパスワードに例外を出す。

- A. パスワードは UTF-8 で 72 バイト以内とする。初期管理者の設定で超えたら作らずに警告する。ログインで超えたら、例外にせず通常の失敗と同じに扱う（ダミーの照合も行う）
- B. SHA-256 で固定長にしてから bcrypt にかける
- X. Other (please specify)

[Answer]: A. パスワードは UTF-8 で 72 バイト以内とする。初期管理者の設定で超えたら作らずに警告する。ログインで超えたら、例外にせず通常の失敗と同じに扱う（ダミーの照合も行う）

## Consolidated Summary Confirmation

- パスワードのハッシュ: bcrypt。計算の重さ（cost）は、ログインの p95 1秒以内（NFR1）に収まり、1回の照合が数百ミリ秒になる値（既定 12）とする
- パスワードの長さ: 12文字以上、UTF-8 で 72 バイト以内。初期管理者の設定で外れたら作らずに警告。ログインで 72 バイトを超えたら通常の失敗と同じに扱う（ダミーの照合も行う）
- アクセストークンの署名: HS256。署名鍵は 256 ビット以上の乱数を環境変数で渡す。鍵を替えるときは設定を変えて再起動する
- ロックの悪用・大量の試行への追加の対策: 行わない（利用者 50 名の社内向けのため、妨害の危険を受け入れる）
- CSRF 対策: SameSite=Strict に加えて、トークンの更新とログアウトの API で要求の Origin ヘッダーが自分の配信元と一致することを確かめ、一致しなければ拒否する
