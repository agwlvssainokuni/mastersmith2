## 前提（確認済みのこと）

- 目標の値と測り方は、U1〜U4 の `construction/<単位>/nfr-requirements/performance-requirements.md`・`scalability-requirements.md` にある。想定の規模は利用者 最大 50 名、同時 10 件。目標は 95 パーセンタイルで決まっている（p50・p99 と、秒あたりの件数の目標は無い）。
- この段が持ち主の未検証の目標は 11 件: U1-NFR1.1（ヘルスチェック 500ms）、U1-NFR1.3（共通の処理が加える時間 20ms）、U2-NFR1.1（ログイン 1 秒、成功・失敗とも）、U2-NFR1.2（トークンの更新 1 秒）、U2-NFR1.3（照合 100〜500ms）、U2-NFR1.4（認証の処理が加える時間 50ms）、U2-NFR1.6（想定の規模を1台で）、U3-NFR1.1（確認用 API 300ms、成功・403 とも）、U3-NFR1.3（拒否の記録で 401／403 を 100ms 以上遅らせない）、U4-NFR1.1（監査の書き込み 50ms）、U4-NFR1.2（監査の書き込みが呼び出し元の予算に収まる。最も余裕の少ない経路）。U1-NFR1.9 は Observability Setup で月1回の確認の項目にした。起動の時間（U1-NFR1.4、30 秒）は Build and Test で Met 済み。

- Q1: 負荷は k6（コンテナ `grafana/k6`、版の番号まで固定）でかける。台本はリポジトリ（`perf/` の下）に置く。
