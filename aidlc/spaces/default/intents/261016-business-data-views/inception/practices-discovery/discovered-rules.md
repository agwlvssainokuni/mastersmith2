# 見つけた固い制約（Intent 261016-business-data-views）

> 依頼者が面談で固い制約として確かめたものだけを置く（Q4・Q5・Q6・Q7・Q9 の答え A、まとめの確認は Looks correct）。既存の `aidlc/spaces/default/memory/project.md` の `## Mandated`・`## Forbidden` と重なるものは書かない。

## Mandated

- ALWAYS 主キーの無いテーブルとビューの行の更新・削除は、画面で操作を隠すことに頼らず、サーバー側で拒否する
- ALWAYS カラムの主権限が NONE（読めない）のカラムは、業務データの API の応答に含めない（画面で隠すことを代わりにしない）
- ALWAYS 対象DB へ書き込む場合は、書き込みの接続と資格情報を読み取りと分けて環境変数（`.env`）だけから受け取り、書き込みのアカウントには DSL の対象のスキーマの行の操作（`SELECT`・`INSERT`・`UPDATE`・`DELETE`）だけを与え、DDL の権限を与えない

## Forbidden

- NEVER 業務データの SQL に、利用者の入力（スキーマ名・テーブル名・カラム名・並べ替えの列・検索の値）を文字列のまま組み込まない（識別子は適用中の DSL にある名前と照らしてから引用し、値はバインド変数で渡す）
- NEVER 業務データの行の値（主キーの値を含む）を、アプリのログ・トレースの属性・エラー応答に含めない
- NEVER アクセシビリティの検査の規則を外して（`disableRules`・規則の絞り込み・要素の `exclude` など）axe の違反を通さない
