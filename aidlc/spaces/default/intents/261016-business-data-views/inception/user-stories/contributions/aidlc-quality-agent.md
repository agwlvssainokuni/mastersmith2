### E. 依頼者に尋ねる候補（どちらも正当な選択）

- **Q-A 書けないカラムを本文に入れたときの応答**: (a) NONE・DSL に無いカラムは同じ 400、READ と `detail.visible` で隠すカラムと主キーも 400 にそろえる（監査に残らない。推奨）／(b) READ のカラムの書き込みは権限の不足として 403。どちらでも、NONE と DSL に無いカラムは同じ応答にする（A-2）。
- **Q-B 主キーとビューの決まり（FR9）による拒否の状態コード**: FR12.4 で監査に残すため 403 の `ACCESS_DENIED` と分ける必要がある。(a) 409 か 405 に専用の code（推奨）／(b) 403 で専用の code（状態コードではなく code で監査を分ける）。
- **Q-C 更新の本文の意味**: (a) 本文に入れたカラムだけを変え、入れないカラムは変えない（推奨。同時の更新で A の別のカラムの変更が残る）／(b) 画面の FULL のカラムをすべて送り、すべてを上書きする（後から保存した人の画面の値に全体がそろう）。
- **Q-D 空の入力**: 作成・更新で入力を空にした文字のカラムを (a) NULL にする（作成で既定値があれば既定値、FR6.4。推奨）／(b) 空の文字列にする。更新で値を消したいときの扱いも同じ答えに従う。
- **Q-E NULL の並び**: (a) 3種類の DB でそろえる（例: 昇順で NULL を最後、降順で最初。NFR3 の「同じ振る舞い」に合う。推奨）／(b) DB に任せ、FR3.4 と同じく DB ごとの違いを制約に書く。
- **Q-F 主キーの無いテーブル・主キーの設定の無いビューのページ送り**: (a) 順を約束せず、ページの間で行が重なる・抜けることがあるのを既知の制約にする／(b) 一覧のすべての列で並べて順を安定させる（同じ値の行が複数あると完全にはそろわない）。
- **Q-G タイムゾーン付きの型と秒未満**: PostgreSQL の `timestamptz` と MySQL・MariaDB の `TIMESTAMP` を (a) 対象DB の接続のタイムゾーンで読んだ値をそのまま出す／(b) UTC にそろえて出す。秒未満の値を持つ日時を (a) `DATETIME` の書式では秒までに切って出す／(b) 秒未満も出す。
