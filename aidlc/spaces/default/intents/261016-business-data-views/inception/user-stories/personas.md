# ペルソナ — business-data-views

出典: `aidlc/spaces/default/intents/261016-business-data-views/inception/requirements-analysis/requirements.md` の Intent の分析と FR2、ストーリーの質問 Q1（ペルソナは3人。管理者は前の Intent 261004-role-menu の P1 を引き継ぐ）、前の Intent のペルソナ（`aidlc/spaces/default/intents/261004-role-menu/inception/user-stories/personas.md`）。デザイナーの担当の意見（`contributions/aidlc-design-agent.md` の 1節）で、目的を利用者の言葉に直し、困りごとと監査の読み方を足した。

## P1 業務データを見る人（田中さん）

- **役割**: MasterSmith の画面で業務データを調べる利用者。管理者の印は持たない。作業ロールでは、扱うテーブルの主権限が READ で、作成・削除の権限は無い（例: 「営業（参照）」のロール）。前の Intent の P2（一般の利用者）を、業務データを見る立場に絞った人。
- **目的**:
  - 左のメニューからテーブルを選び、条件で絞って必要な行を早く見つけたい
  - 見つけた行の詳細を、読みやすい表示名と書式（日付・数の区切り・はい／いいえ）で確かめたい
  - 見られないテーブル・カラムや開けない行があるとき、それが権限のせいか、データが無いせいか、つながらないせいかを画面の文で見分けたい（管理者に頼むか、探し直すか、やり直すかを決めるため）
  - 一覧から詳細を見て戻ったときに、絞り込んだ条件とページがそのまま残っていてほしい
- **困りごと（今）**:
  - テーブルを指すメニューの項目を選んでも「準備中」の画面で、業務データを見られない（コード知識ベースの所見 K-52）
  - 対象DB を直接読む道具が無く、ほかの人に頼んで調べてもらっている
  - テーブルに列が多く（最大 100 カラム）、横に長い表を読むことになる
- **技術への慣れ**: 低〜中（SQL は書かない）
- **アクセシビリティ**: キーボードだけで操作する人、読み上げを使う人もいる
- **使う頻度**: 毎日
- **言語**: 日本語または英語

## P2 業務データを直す人（鈴木さん）

- **役割**: マスタの値を登録・修正・削除する担当者。管理者の印は持たない。作業ロールでは、受け持つテーブルが FULL で、CREATE・DELETE が可（例: 「商品マスタ担当」のロール）。ほかのテーブルは READ か NONE のこともある。仕事に応じて作業ロールを切り替える。
- **目的**:
  - 一覧から行を選び、間違いのある値をその場で直したい
  - 新しい行を、入力の誤り（必須・長さ・範囲・形式・同じ値）をその場で教えてもらいながら登録したい
  - 要らなくなった行を、確かめてから消したい
  - 自分の操作がほかの人の変更とぶつかったときや、保存できなかったときに、理由が分かってやり直せることを望む
  - 保存した後に、保存できたこととその結果を、その場で確かめたい
- **困りごと（今）**:
  - マスタの修正のたびに、DB を直接触れる人へ SQL を頼んでいる
  - どのカラムを直してよいかが人によって違い、口頭で決めている
  - テーブルに列が多く（最大 100 カラム）、横に長い表と多くの入力を扱う
- **技術への慣れ**: 中（表の操作は慣れているが、DB の制約やエラーの文は読めない。そのため、保存の失敗は DB の文ではなく業務の言葉と該当のカラムで伝える必要がある。ストーリーの AC2.4.7）
- **アクセシビリティ**: キーボードだけで操作する人、読み上げを使う人もいる
- **使う頻度**: 毎日（月末などに多い）
- **言語**: 日本語が主

## P3 管理者（佐藤さん）

- **役割**: 前の Intent の P1 を引き継ぐ。MasterSmith の管理画面で、利用者・DSL・ロールと権限の設定を受け持つ（管理者の印を持つ利用者）。管理者でも、業務データの見え方と操作は自分の作業ロールで決まる（要件 FR2.6）。
- **目的**:
  - 設定した権限（主権限・補助権限）と DSL の表示の設定が、業務データの画面で期待どおりに効いていることを確かめたい。管理者でも業務データは自分の作業ロールで決まるため、確かめたいロールを自分に割り当てて作業ロールを切り替えるか、「自分の権限を見る」の画面で見る
  - 誰がいつどのテーブルの行を作成・更新・削除したか、拒否・失敗したかを、内部DB の監査の記録で追いたい（今の手順では、配備したアプリを止めた複写を読み取りで開く）。監査を見る画面はこの Intent の範囲の外
- **困りごと（今）**:
  - 権限を設定しても、業務データの画面が無いため効き方を確かめられない（所見 K-50）
  - 業務データの変更の記録が無く、後から誰が直したか分からない（所見 K-54）
- **技術への慣れ**: 中（YAML は読めるが、DB は直接触りたくない）
- **アクセシビリティ**: キーボードや読み上げを使う管理者もいる
- **使う頻度**: 週に数回
- **言語**: 日本語が主。英語の画面も使うことがある

## ペルソナの関係と優先度

1. **P1 業務データを見る人**（最優先）: 一覧・検索・詳細は、見る人と直す人の両方の土台になる。
2. **P2 業務データを直す人**: 作成・更新・削除は、見る機能の上に乗る。
3. **P3 管理者**: 権限と DSL の結果を確かめ、監査を内部DB の記録で読む。設定そのものは前の Intent までの機能で行う。

同じ人が作業ロールを切り替えると、P1 にも P2 にもなる（例: 「営業（参照）」と「商品マスタ担当」）。
