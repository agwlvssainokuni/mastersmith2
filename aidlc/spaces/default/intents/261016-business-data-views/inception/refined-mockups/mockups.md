## 1. 道（URL）と画面の移り方（RQ1: A）

```
メニューのテーブルの項目
        │ 選ぶ
        ▼
S1 一覧  ──行の主キーのリンク／「操作」→詳細──▶  S2 詳細  ──「更新」──▶  S4 更新
  │  ▲                                              │  ▲                    │
  │  └────────「一覧へ戻る」・戻る操作─────────────┘  └──保存・やめる─────┘
  │                                                  │
  └──「作成」──▶ S3 作成 ──保存──▶ S2 詳細（詳細へ移れない行は S1）
                                                     │
                                         「削除」──▶ S5 削除の確かめ ──削除──▶ S1
```

文字の代わりの説明: 一覧（S1）から、主キーのリンクか行の「操作」の「詳細」で詳細（S2）へ移る。詳細から「更新」で更新（S4）へ、保存かやめるで詳細へ戻る。詳細の「削除」で確かめ（S5）を開き、削除すると一覧へ戻る。一覧の「作成」で作成（S3）へ、保存するとその行の詳細（詳細へ移れない行は一覧）へ移る。どの画面からも「一覧へ戻る」かブラウザの戻る操作で一覧へ戻り、一覧の検索の条件・ページ・並びは保つ（SM5）。

- 一覧の道は、今の置き場と同じくテーブルを指す形（今は `/tables?schema=..&table=..&item=..`、K-52）を引き継ぎ、詳細・作成・更新の道は同じテーブルの下に置く。行を指す主キーの値を道に置くか、道を雛形に置き換えてトレースから伏せるかは、要件の未解決の点として機能設計で決める。道に検索の値は載せない（SM5）。
- サイドバーの今の項目（`aria-current`）は、一覧・詳細・作成・更新のどの画面でも、そのテーブルの項目のまま（AC1.1.6）。

```
│ │ 青いペン      │ A01（リンク）    │ 1,200     │2026-10-18│ [操作 ▾]│          │ ← 主キー（または代表のカラム）は詳細へのリンク
```

- **列**（AC1.1.9）: DSL の `list.visible` のカラムを `list.order` の順、`list.width` の幅で出す。主権限 NONE のカラムは出さない（AC3.1.1）。行を指す主キーが `list.visible` でないときは列に出さないが、詳細へのリンクは「操作」の中の「詳細」で行える（AC3.1.8）。
- **詳細へのリンク**（RQ6: A）: 主キーのカラムが列にあれば、その値の文字を詳細へのリンクにする。主キーが列に無いときは、機能設計で決める代表のカラムをリンクにする。リンクの読み上げの名前は「詳細: 商品 A01」の形。
- **行の「操作」**（RQ6: A・AC4.1.1）: 右端の列に Dropdown を置き、`placement` は `bottom-end`。中身は行えるものだけ（「詳細」「更新」「削除」）。トリガーの名前は見えている文字「操作」で始まり、「操作: 商品 A01」の形にする。行える操作が1つも無い行は「操作」の列を出さない（AC3.2.5 の理由を一覧の上に出す）。
- **並べ替え**（AC1.3.3・AC1.3.12）: `list.sortable` のカラムの見出しだけをボタンにし、押すたびに昇順 → 降順 → 既定の順と変わる。向きは ▲／▼ と `aria-sort` で伝える。
- **ページ送り**（AC1.3.1・AC1.3.2・AC1.3.13）: 「前へ」「次へ」と「1 / 3ページ(全45件)」。英語の画面では `Previous`・`Next`・`Page 1 of 3 (45 items)`（Table の `labels` で差し替える）。1ページの件数は 20・50・100 から選ぶ（Should。make-you-chic-ui の Table に件数の選択が無いため、依頼（5）を出し、取り込みまでは Table の外に Select を置く）。
- **値の表示**（AC1.5.2〜AC1.5.8）: 書式は要件 FR11.2 のとおり。時差つきの型は `2026-10-18 00:30:00+00:00`。`password` のカラムは `••••••`。値と表示名は文字として出す。
- **広い表**（AC1.3.15）: 表は横のスクロールの領域に入れ、画面全体は横にスクロールしない。領域にはラベル（例: 「商品の一覧の表」）を付け、キーボードでフォーカスしてスクロールできる（make-you-chic-ui の Table の枠に無いため、依頼（5）を出し、取り込みまでは frontend の側で枠を包む）。
- **作業ロールの表示**: 今の作業ロールはトップバー（前の Intent の WorkRoleSwitcher）で分かる。

### 2.2 検索の領域（RQ2: A）

```
▸ 検索の条件（2 件の条件）                                   ← collapsed のとき閉じて始める（Should、AC1.2.7）
▾ 検索の条件
  商品コード（完全一致）  [        ]                        ← EQUALS
  商品名（部分一致）      [        ]                        ← CONTAINS（% _ は文字として扱う、AC1.2.4）
  価格（範囲）            [   ] 〜 [   ]                    ← RANGE（片方だけでもよい、AC1.2.2）
  状態（選択肢）          ☐販売中 ☐停止                     ← CHOICE（固定の選択肢。複数選べる、AC1.2.3）
  有効（選択肢）          ☐はい ☐いいえ                     ← 真偽値で選択肢の無い CHOICE（AC1.2.13）
  部署コード（完全一致）  [        ]                        ← REFERENCE・LOOKUP の CHOICE は完全一致に読み替え（AC1.2.8）
                          [条件をクリア] [検索]
```

- 項目は DSL の `search.enabled` のカラムだけで、主権限 NONE のカラムは出さない（AC1.2.9）。項目ごとに表示名と演算子の種類を文字で出す（AC1.2.12）。既定の値（`search.default`）を入れて始める（AC1.2.6）。
- 項目は横に並べ、幅が狭いと縦に積む。Enter か「検索」で検索し、条件を変えたら1ページ目へ戻る（AC1.2.10）。
- 入力の誤り（型として読めない値・下限が上限より大きい）は、その項目の下に文字で出し、直前の結果の一覧は消さない（AC1.2.5・AC1.2.2）。
- 閉じているときは、見出しに条件の数（例: 「（2 件の条件）」）を出す。

### 2.4 主キーの無いテーブル・主キーが NONE・ビュー（AC3.2.1〜AC3.2.3・AC3.2.5）

```
┌──────────────────────────────────────────────────────────────────────┐
│ 受注明細の集計                                                         │
│ ⓘ このビューは読み取りだけです。                                      │ ← Alert（info）。理由の文は権限の中身を出さない
│ ▸ 検索の条件                                                           │
```

- 主キーの無いテーブル・主キーのカラムが NONE のテーブル: 「このテーブルは行を1件に決められないため、詳細・更新・削除はできません」（英語 `Rows in this table cannot be identified one by one, so you cannot view, edit, or delete them.`）。作成は CREATE 可なら行える。
- ビュー: 「このビューは読み取りだけです」（英語 `This view is read-only.`）。ビューに主キーの設定があり主キーのカラムがすべて READ 以上なら、詳細へのリンクだけを出す。

## 4. S3 行の作成・S4 行の更新（RQ1: A・RQ7: A）

```
┌──────────────────────────────────────────────────────────────────────┐
│ ← 詳細へ戻る（更新）／一覧へ戻る（作成）                              │
│ 商品を更新: A01                                                       │ ← 作成は「商品を作成」
│ ⚠ 2 件の入力を確かめてください（商品名・価格）                        │ ← 誤りのまとめ（誤りがあるときだけ。フォーカスを移す）
├──────────────────────────────────────────────────────────────────────┤
│ 商品コード      A01（変えられません）                                 │ ← 主キーは更新では読み取り（AC2.2.5）
│ 商品名 *必須    [青いペン                    ] 20 文字まで            │ ← 必須の印と長さの上限を入力の前に出す（AC2.4.8）
│                 ⚠ 商品名を入れてください                              │ ← 誤りはその入力の下（AC2.4.6）
│ 価格            [1200        ]  例: 1234.56                           │ ← DECIMAL は文字の入力（RQ7: A）
│ 発売日          [2026-10-18  ]  形: YYYY-MM-DD                        │ ← type="date"
│ 更新の日時(UTC) [2026-10-18T00:30:00]  UTC で入れる                   │ ← 時差つきの型（AC1.5.7・SM7）
│ 状態            ( ) 販売中  (•) 停止                                   │ ← radio・FIXED の選択肢
│ 部署コード      [D10         ]                                         │ ← REFERENCE は文字の入力（FR6.2）
│ 暗証番号        [            ]  入れたときだけ変わります               │ ← password は空で始める（AC2.2.11）
│ 備考            [            ]  空にすると空の文字列になります         │ ← 空の入力（AC2.2.10）
│ 登録者          佐藤（変えられません）                                │ ← READ のカラムは読み取り（AC2.2.1）
├──────────────────────────────────────────────────────────────────────┤
│                                        [やめる]  [保存]                │ ← 保存中は押せず「保存しています…」（AC2.1.10）
└──────────────────────────────────────────────────────────────────────┘
```

- 出すのは `detail.visible` のカラムだけ。FULL は入力、READ は読み取り。`detail.visible` で隠す FULL のカラムは出さず、値を変えない（AC2.2.7・SQ7）。
- 入力の部品は DSL のフォーム部品に従う（`text`・`textarea`・`checkbox`・`switch`・`radio`・`select`・`date`・`datetime`・`number`・`password`）。日付・日時・時刻・数はブラウザの標準の入力（`date`・`datetime-local`（秒まで）・`time`・`number`）で、形の案内を入力の下に出す。`BIGINT`・`DECIMAL` は文字の入力にして桁を失わない（RQ7: A・AC3.6.5）。
- 検証: 必須・長さ・範囲・型は入力から離れたときと保存のときに画面でも確かめる。`pattern` は保存のときにサーバーの誤りをその入力に出す（AC2.4.1・SM4）。DB が拒んだ保存は業務の言葉で出す（AC2.4.7）。
- 更新の画面は詳細と同じ API で今の値を読む（AC2.2.1）。保存するのは変えたカラムだけ（AC2.2.2）。何も変えずに保存したときの扱いは機能設計で決める（AC2.2.9）。
- 保存せずに離れる（「やめる」・メニュー・戻る操作・作業ロールの切り替え）と、変更があれば確かめの Modal を出す（AC2.2.12・SM6）。

```
┌──────────────────────────────────────────────┐
│ 保存していない変更があります                 │
│ この画面を離れると、入力した内容は失われます。│
│                    [留まる]  [離れる]        │ ← はじめのフォーカスは「留まる」
└──────────────────────────────────────────────┘
```

- 作業ロールを切り替えて FULL が無くなった後の保存は 403 の表示にし、入力していた値は捨てる（AC2.2.13・RQ5: A）。

### 4.1 保存の後と時間切れ（AC2.1.1・AC2.2.2・AC3.3.5）

- 作成の保存: その行の詳細へ移り、「作成しました」の Toast を出す（読み上げにも伝わる）。詳細へ移れない行は一覧へ戻る（AC2.1.4）。
- 更新の保存: 詳細へ戻り、「更新しました」の Toast を出す。
- 時間切れ: 「保存されたか分かりません。」の Alert（warning）と、更新・削除では「この行を開き直して確かめる」、作成では「一覧で同じ行が無いか確かめる」の入口を出す。入力した値は消さない。

## 5. S5 削除の確かめ（AC2.3.1・AC2.3.2）

```
┌──────────────────────────────────────────────┐
│ 商品 A01 を削除しますか                      │ ← role="alertdialog"
│ この操作は元に戻せません。                   │
│                    [やめる]  [削除する]      │ ← はじめのフォーカスは「やめる」。背景のクリックで閉じない
└──────────────────────────────────────────────┘
```

- 削除すると一覧へ戻り（戻る前の条件・ページ・並びを保つ）、「削除しました」の Toast を出す。
- ほかの表から参照されていて DB が拒んだときは、Modal の中に「ほかのデータから使われているため削除できません」を出す（AC2.3.4）。先に削除されていたときは「行が見つかりません（ほかの人が削除した可能性があります）」を出して一覧へ戻る入口を置く（AC2.3.5）。

## 6. S6 開けない・つながらないときの表示（AC3.3.7）

各画面の中身の領域に、次の文を出し分ける（英語の文は `interaction-spec.md`）。

| 状況 | 文（例） | 次の行き先 |
|---|---|---|
| 403（作業ロールで見られない） | このテーブルを見る権限がありません。作業ロールを確かめてください。 | メニューから選び直す |
| 404 テーブル（DSL に無い） | テーブルが見つかりません。 | メニューから選び直す |
| 404 行 | 行が見つかりません（ほかの人が削除した可能性があります）。 | 一覧へ戻る |
| DSL が適用されていない | いまは業務データを使える状態ではありません。管理者に確かめてください。 | ホームへ |
| 対象DB とつながらない・時間切れ（読み取り） | 業務データのデータベースとつながりません。時間をおいてやり直してください。 | やり直す（読み直し） |
| DSL と対象DB の食い違い | テーブルの定義とデータベースが食い違っています。管理者に確かめてください。 | 一覧へ戻る |
| ページを超えた（ほかの人の削除で減った） | このページには行がありません。 | 前のページへ（AC1.3.14） |

- 403 の表示は、画面の見出しを残し、行・入力の部品は出さない（AC1.1.3・AC1.1.8）。作業ロールを切り替えて読み直したときは、前に出ていた行を残さない（AC1.1.5）。
- 文は DB の文・制約の名前・JDBC の例外・接続先を出さない。

## 7. S7 既存の管理の一覧の行の「操作」（AC4.1.1）

利用者・グループ・ロールの管理の一覧の行の「操作」のトリガーの名前を、見えている文字「操作」で始まり、どの行かが分かる「操作: 佐藤 一郎」（利用者）・「操作: 営業」（ロール・グループ）の形に直す。英語は `Actions: …`。見た目は変えない。

## 8. S8 アプリの枠のトップバー（AC4.1.4・AC4.1.6）

E2E 080（表示の設定の画面）で出た axe の違反は、Topbar の利用者のメニューのトリガー（Avatar の頭文字）の可能性が高い（K-56）。axe-core 4.14 で違反の要素を確かめ、Topbar の部品なら依頼（5）で上流に直してもらい、取り込んでから axe-core を上げる（AC4.1.4）。画面の見た目は変えない。

## 9. 画面の幅ごとの振る舞い

| 幅 | S1 一覧 | S2 詳細 | S3・S4 作成・更新 |
|---|---|---|---|
| 狭い（< 768px、375px を含む） | 検索の項目は縦に積む。表は横のスクロールの領域で、画面全体は横にスクロールしない。行の「操作」のメニューは画面の中に収める（`bottom-end`）。作成のボタンは見出しの下に置く | 項目名と値を縦に積む | 1列に積み、ボタンは下に並べる |
| 中（768〜1023px） | 検索の項目は2列 | 項目名と値を横に並べる | 1列 |
| 広い（≥ 1024px） | 検索の項目は横に並べる。表は内容の幅で、はみ出すと領域の中でスクロールする | 同上 | 1列（入力の幅は最大 40rem） |

## 10. 要件・ストーリーとの差

- 1ページの件数の選択（Should、AC1.3.2）と横のスクロールの領域のフォーカス（AC1.3.15）は、make-you-chic-ui の Table に口が無いため依頼（5）を出す。取り込みまでは frontend の側で Table の外に Select を置き、枠を包む（team.md の Way of Working の「間に合わないときに自前で作るかは諮る」は、Functional Design の承認の場で確かめる）。
- 行を指す主キーの値を道に置くかは、この段では決めず機能設計で決める（要件の未解決の点）。
- 何も変えない保存の扱い（AC2.2.9）と、主キーが列に無いときの代表のカラム（AC1.4.7・AC4.1.1）は機能設計で決める。
