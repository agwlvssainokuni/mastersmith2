# Requirements Analysis の質問（Intent 261016-business-data-views）

依頼の文、参考資料の要件のドラフト（2.3〜2.9・4章・5章・6章・7章・9章の J・K）、コード知識ベース（所見 K-49〜K-61）、確定したチームの進め方（`aidlc/spaces/default/memory/team.md`・`project.md`）をもとに、業務データの一覧・詳細の範囲で判断が分かれる点だけを尋ねる。

## 決まっていること（質問にしない）

- 権限の当て方はドラフトの 5.2〜5.5 のとおり。作業ロールの主権限（スキーマ → テーブル → カラム、既定 NONE）と補助権限 CREATE・DELETE（スキーマ → テーブル、既定 不可）を、前の Intent の解決の口（FR8.1）で求め、API ごとにサーバー側で判定する（`project.md` の Mandated）。主権限 NONE のカラムは一覧・検索・詳細・編集から除き、API の応答にも含めない。READ は表示だけ、FULL は編集できる。
- 主キーの有無による操作の可否はドラフトの 5.5 の表のとおり（主キーの無いテーブル・いずれかの主キーのカラムが NONE のときは、詳細・更新・削除をしない。サーバー側で拒否する、`project.md` の Mandated）。
- 画面の入口は、テーブルを指すメニューの項目（今は「準備中」の置き場、K-52）を一覧の画面に置き換える。テーブルの見せ方（一覧の列・並び・検索の項目・詳細の表示・表示名 ja/en・フォーム部品）は適用中の DSL の設定に従う（K-51）。
- 対象DB は MySQL・MariaDB・PostgreSQL の3種類（ドラフトの 7章）。想定の規模は最大 100 テーブル・1 テーブル 100 カラム・利用者 50 名。
- 持ち越しの直しは依頼の文のとおり行う: make-you-chic-ui の固定先を `b0a1e79` に上げる、行の「操作」のトリガーの名前を見える文字を含む形に直す、axe-core 4.14 以降を取り込み dependabot の `ignore` を外す、表示の設定の画面（E2E 080）の違反の部品を確かめる、不安定なテスト2件を直す。違反はすべて直してから上げ、make-you-chic-ui の部品の違反は依頼（5）を出して取り込んでから上げる（`team.md` と `project.md` の Forbidden）。
- テストの進め方・漏えいの防ぎ方・SQL の組み立て方・書き込みの接続の分け方は Practices Discovery で決めた（`team.md`）。
