## 決まっていること（質問にしない）

**画面と状態の持ち方**
- 画面は S1〜S6 を別々の画面にする（RQ1: A）。
- 一覧の状態は画面の中に持ち、道には載せない（SM5）。

**操作の入口**
- 出すカラムと操作の入口は、サーバーが返す操作の可否（`operations`・`restrictionReason`・`writeConfigured`・`editableOn*`）で決める。画面で判定し直さない（AC3.1.9）。
- 行の操作は Dropdown（`placement="bottom-end"`）にする。名前は U4 の `rowActionsName` で作り、行を見分ける値は `rowLabelColumns` から作る（U1 Q8・U4）。

**API と値の受け渡し**
- API は U1・U2 の6本で、道は固定し、名前と値は本文で運ぶ。
- 値は文字か null で受け渡し、BIGINT・DECIMAL を数に直さない。

**表示**
- NULL は「（値なし）」と出す（RQ3）。
- 長い値は1行で省略する（RQ4）。
- `password` は伏せて出し、更新の画面では空で始める（SM3）。
- 時差つきの型は UTC にそろえる（SM7）。

**更新**
- 何も変えなければ保存を押せない（U2 Q7）。
- 送るのは変えたカラムだけ。空にしたカラムは、文字の型なら `""`、ほかの型なら `null` で送る（SM1・SM2）。
- 作業ロールの切り替えで 403 になったら、入力は捨てる（RQ5: A）。

**依頼（5）の取り込みまでの手当て**
- 1ページの件数の選択は、Table の外の Select で出す。
- 横のスクロールの枠は、`src/shared/` の枠で包む。
- 取り込みは B7 で行う（U4）。

**E2E とアクセシビリティの確かめ**
- 業務データの代表の E2E は1本にする（team.md）。
  - 見本の PostgreSQL を前提にし、届くかを先に確かめる。
  - 資格情報はプロセスの環境変数で渡し、報告の json を文字列で検索する。
- axe の E2E と、今の置き場の E2E 170 の書き換えは、本数に数えない。
- 375px の幅と 100 カラムの表で、開いたメニューが画面に収まることを確かめる（project.md）。
- axe は、ブランドカラーとテーマのすべての組で、誤りの状態を含めて確かめる（project.md）。

## Q1. 入力の部品と検証の材料を、どこから読むか（U2 の R-02）

A. 定義の API のカラムの項目を、契約 C2 の `ColumnDefinition` の形に戻して読む。
- 読み取りの項目（表示名・幅・書式・型など）は U1（B2）が返す。
- 検証の材料（`formPart`・`required`・`nullable`・長さ・桁・範囲・選択肢・`pattern` の有無）は U2（B4）が足す。
- B5 は読み取りの項目、B6 は検証の材料を使う。
- U1・U2 の文書との差は、U3 の「上流との差」に書く。

（推奨）
B. 検証の材料も、初めから U1（B2）の型と応答に入れる（U1 の範囲が増える）
C. 画面は検証の材料を持たず、必須と型だけを確かめ、ほかはサーバーの誤りだけで出す（画面の側の検証の受け入れ基準を満たせない）

## Q2. 定義が変わったと分かったときの画面の振る舞い（U1 の R-04）

A. U1 は、400 の誤りの応答にも `definitionChanged` を付ける形に直す前提にする（契約 C2 の誤りの型と同じ）。
- 画面は、読み取りの応答か 400 でこれを受けたら、定義を読み直す。
- 使えなくなった検索の条件と並べ替えを外して読み直し、「表示の設定が変わりました」と読み上げでも伝える。
- 書き込みの 409 `BUSINESS_DEFINITION_CHANGED` では、今も入力できるカラムの入力を残し、確かめてもう一度保存するよう促す。

（推奨）
B. U1 は、要求の識別が今と違えば 400 より先に定義の変更を返す（画面は A と同じ。U1 の判定の順に1段増える）
C. U1 を直さず、画面は 400 を受けるたびに定義を読み直して比べる（要求が増え、見分けが推測になる）

## Q3. 検索の項目の作り方と、画面での確かめ（U1 の R-01）

## Q4. 詳細・更新の画面で、行の主キーと一覧の状態をどこに持つか（CQ2・SM5）

A. 機能の中の記憶（画面の外の変数）に持つ。
- 主キーは、履歴に置いた意味の無い印（乱数）で引く。主キーの値そのものは、履歴にもブラウザの保存にも置かない。
- 再読み込みで記憶が消えたら、一覧へ移る。
- 一覧の状態は、テーブルごとに同じ記憶に持つ。

（推奨）
B. 主キーを、履歴の状態（`history.state`）にそのまま置く（多くのブラウザは再読み込みでも残すため「一覧へ戻る」にならず、ブラウザの保存に値が残る）

## Q5. 保存していない変更があるまま、作業ロールを切り替えるとき（AC2.2.12）

A. 画面の骨組みの作業ロールに、「切り替えの前の確かめ」を登録する口を足す。作成・更新の画面は、変更のある間だけ確かめを登録し、離れるときと同じ確かめの表示を出す。［留まる］を選べば切り替えない（推奨）
B. 変更のある間は、作業ロールの切り替えを押せなくし、理由の文を添える
C. 確かめずに切り替え、その後の 403 か定義の変更で知らせる（AC2.2.12 を満たさない）

## Requested Changes Feedback

承認の場（2026-10-18）の Request Changes で、次の直しを決めた（Major と、単位の継ぎ目に関わる Minor）。

- R-01（Major）保存の後の移動: 保存に成功した後の移動では、未保存の確かめを1回だけ飛ばす（最新の変更の有無を ref で読み、成功の直後に「変更なし」にしてから移る）。この形は roleadmin から移す `src/shared/` の部品に口として足し、テストで確かめる。
- R-02（Major）行の名前: 行のリンク「詳細: …」・行の操作の名前・詳細の見出しは、画面に見えている文字と同じく、書式の関数（D15）を通した後の文字で作る。
- R-05（Minor・継ぎ目）前提が崩れたとき: 400 の `fieldErrors` が今の定義に無い項目を指したら、定義を読み直す。B5 に要る前提（U1 の R-01・R-04）と B6 に要る前提（U2 の R-02）を分けて書く。
- R-08（Minor）traceability: D5 を coverage か reverse に載せる。
- そのほかの Minor（R-03 B5 の E2E の行の出どころ、R-04 作業ロールの確かめの後の画面、R-06 保存の 403 の文、R-07 主キーの記憶）は、この単位の記録に残し、後の段で拾う。
