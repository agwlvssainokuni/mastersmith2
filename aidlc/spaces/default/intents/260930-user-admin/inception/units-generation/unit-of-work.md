# 作業の単位（Unit of Work）— user-admin

出典の表記: 部品と ADR は `aidlc/spaces/default/intents/260930-user-admin/inception/domain-design/`（`components.md`・`decisions.md`）、FR・NFR は `.../requirements-analysis/requirements.md`、US・AC は `.../user-stories/stories.md`、UQ1〜UQ3 は `.../units-generation/units-generation-questions.md` の確定した答え。

## U1 利用停止の状態と3つの入口（u1-user-suspension、library）

- **説明**: 利用者に利用停止の状態を足し、ログインの照合・トークンの更新・アクセストークンの認証の3つの入口で停止を判定する。止めた利用者のリフレッシュトークンをまとめて無効にする口を作る。U3 の止める操作が使う土台になる。
- **境界（作るもの）**:
  - UserAccount: `users` に停止の状態を足す移行（Flyway の V9、既存の利用者は「有効」、前進のみ・後方互換、ADR-002・NFR10）。入口が読む利用者の情報に停止の状態を含める。
  - Authentication: 3つの入口での停止の判定（ログインは停止の確かめをロックの判定より前に置き、失敗回数とロックの状態を変えず、読み書きの回数をパスワードの誤りとそろえる。トークンの更新と認証は無効なトークンと同じ応答、ADR-008・FR3.2〜FR3.4）。利用者のリフレッシュトークンをまとめて無効にする口（ADR-003）。
  - AuditLog: ログインの失敗の理由「停止中」（ストーリーの差5）。
  - リポジトリ: `.idea/.gitignore` に `dataSources.xml`・`dataSources/` を足す（UQ2 A。Delivery Planning で最初の Bolt が別の単位になれば、その単位へ移す）。
- **作らないもの**: 止める・解く操作そのもの（U3）、画面（U5）。
- **責務**: 停止の状態の保持と、3つの入口での判定、トークンのまとめての無効化の口。
- **配備**: WAR に組み込み（embedded）。
- **確かめ**: 停止の状態をテストのデータとして入れれば、U3 より前に作って確かめられる（ストーリーの US3.2 の依存の注）。`team.md` の必須テスト（利用停止の3つの入口・停止の前のトークン・列挙の防止）。
- **注意**:
  - `auth.domain`・`auth.repository` は `packagesJudgedByTotal` の一覧にあり、手を入れたら下限を満たして一覧から外す作業が付く（`team.md`、ADR-003・ADR-008）。
  - 停止中のログインで読み書きの回数をそろえる形が成り立つかを、機能設計で確かめる（ADR-007 の項目4）。

## U2 ページ送りの共通化（u2-shared-paging、library）

- **説明**: 招待の一覧のページ送りの計算を、サーバーは `common.paging`（Paging）、画面は `src/shared/`（UiPaging）に移し、招待のサーバーと画面を切り替える（ADR-004）。招待の振る舞いは変えない。
- **境界（作るもの）**: Paging（1ページ 20 件、ページの番号の検証、最後のページより後は空の一覧）、UiPaging（前へ・次への可否と表示の元の値）。招待の `InvitationPaging` と `features/invitation/paging.ts` の置き換え。
- **作らないもの**: 利用者の一覧（U3・U5）。
- **責務**: 管理の一覧のページ送りの計算を1か所にする。
- **配備**: WAR に組み込み（embedded）。
- **確かめ**: 性質ベースのテスト（jqwik・fast-check、`team.md`）。招待の既存のテストが通ったままであること。
- **注意**: `common.paging` は新しいパッケージで、パッケージごとの下限の対象になる。`invitation` は一覧に無い（すでに下限の対象）。

## U3 利用者の管理の API（u3-user-admin-api、service）

- **説明**: 管理者による利用者の管理の API（`/api/admin/` の下）と業務の決まりを作る。一覧（利用者の要約＋ロックの判定の結果、ページ送り・検索）、管理者の印の付け外し、利用停止と解除、失敗回数の取り消し、氏名と言語の変更。
- **境界（作るもの）**:
  - UserAdministration（新しいパッケージ `useradmin`）: 拒否の理由の判定と順（対象がいない → 自分自身 → 対象が停止中 → 変えるものが無い → 最後の有効な管理者）、最後の有効な管理者の保護（管理者の行を決まった順で排他し、操作者を確かめ直してから数える、ADR-007）、止めるときのトークンの無効化（U1 の口）、管理の操作の監査の出来事、TRACE のログで個人に関する値が出ない受け渡しの型。新しい境界の検査（ADR-001）。
  - UserAccount: 管理者の印・停止・氏名と言語の変更の口、利用者の要約の一覧と検索（特殊文字は文字どおり）、有効な管理者の数え上げ、管理者の行を決まった順でまとめて排他する口。
  - Authentication: 失敗回数の取り消し（同じ行の排他、解除の予定の時刻を無くす、行の無い利用者に行を作らない）、ロックの判定の結果の口（失敗回数の生の値は出さない）。
  - AuditLog: 出来事の種類5つ（印を付ける・外す・止める・停止を解く・失敗回数を戻す）と失敗の理由5つ（ADR-006）。
- **作らないもの**: 画面（U5）、403 の画面の扱い（U4）、停止の状態と入口（U1）、ページ送りの計算（U2）。
- **責務**: 利用者の管理の業務の決まりと API。
- **配備**: WAR に組み込み（embedded）。API を持つため種別は service。
- **確かめ**: `team.md` の必須テスト（管理者の印の変更・ロックの解除・最後の管理者の保護（待ち合わせで重ねる同時の操作）・管理の API の認可 401／403／200・要求の改ざん・管理の操作の監査・利用者の管理の漏えい）。ストーリーの AC の大半のサーバー側。
- **注意**:
  - `auth.repository`・`auth.domain`・`audit.repository` などの一覧のパッケージに手が入り、下限の作業が付く（Delivery Planning とコード生成の計画で実測して見積もる）。
  - `audit` の3ファイルがさらに大きくなる（ADR-006）。
  - 排他の細部と、待ちの上限切れの応答は機能設計・NFR 設計で決める（ストーリーの AC4.1.11）。

## U4 管理の画面の 403 の共通の扱い（u4-admin-forbidden-ui、ui）

- **説明**: 管理の画面すべて（入口・DSL・招待・利用者の管理）で、403 を受けたら同じ表示（「この画面を使う権限がありません」と「ホームへ戻る」）にし、ログインの状態を読み直して管理のメニューを消す仕組みを、画面の骨組みに作る（ADR-005、ストーリーの US2.2・差2）。
- **境界（作るもの）**: ApiClient（`/api/admin/` の下で code が `ACCESS_DENIED` の 403 を「権限が無い」として知らせる）、AppFrame（共通の表示への切り替えとログインの状態の読み直し）、AdminArea・DslAdminUi・InvitationUi の 403 の扱いの置き換え（「ページが見つかりません」・一般の誤りの文言から）。自分自身の氏名・言語が変わったときに画面の言語と上の帯の氏名を変える口（U5 が使う）。
- **作らないもの**: 利用者の管理の画面（U5）。
- **責務**: 管理の画面の 403 の扱いの共通化。
- **配備**: WAR に同梱する画面の `dist`（embedded）。
- **確かめ**: 画面部品ごとのアクセシビリティの検査。既存の3つの画面のテスト（403 を「ページが見つかりません」として確かめているもの）を新しい表示に合わせて書き換える。
- **注意**: 既存の画面とテストの書き換えが範囲に入る（ADR-005 の悪い点）。

## U5 利用者の管理の画面（u5-user-admin-ui、ui）

- **説明**: 利用者の管理の画面（画面イメージの S1〜S5、操作の仕様の部品）を作り、サイドバーの管理のメニューに機能として登録する。E2E の代表の流れを1本足す。
- **境界（作るもの）**: UserAdminUi（一覧・検索・行の操作のメニュー・確かめの表示5種類・氏名と言語の入力・結果の知らせ）。ページ送りは UiPaging（U2）、403 は AppFrame の共通の扱い（U4）、API は U3。
- **リポジトリの作業**（UQ2 A）:
  - make-you-chic-ui の固定先を `3481488` 以降に更新する（Dropdown の押せない項目と理由の文を使うため）。承認を得た専用のコミットで行い、更新前後のコミットのハッシュを記録する（PM の Mandated）。この単位の統合は fast-forward でよい（`team.md`）。
  - `frontend/.npmrc` に `ignore-scripts` を入れる（`team.md`）。`vendor/make-you-chic-ui` のインストールへの影響を確かめる。
- **作らないもの**: API（U3）、403 の共通の扱い（U4）。
- **責務**: 利用者の管理の画面。
- **配備**: WAR に同梱する画面の `dist`（embedded）。
- **確かめ**: 画面部品ごとのアクセシビリティの検査（2語の氏名・誤りの状態、ストーリーの AC1.1.12）。E2E の代表の流れ（自分で作った利用者で、ロック → 失敗回数を戻す → 止める → ログインできない → 停止を解く → ログインできる。ストーリーの M9 A）。E2E は目当ての利用者を検索（Should）で探す。
- **注意**: 検索（Should）を後に回すと、E2E の書き方を変える必要がある（ストーリーの申し送り。Delivery Planning で決める）。
