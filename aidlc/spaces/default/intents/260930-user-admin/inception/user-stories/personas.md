# ペルソナ — user-admin

出典: `aidlc/spaces/default/intents/260930-user-admin/inception/requirements-analysis/requirements.md` の 1節（利用者）、ストーリーの質問 Q1（ペルソナは2人。運用者・監査者は監査の受け入れ基準の中で扱う）、同じファイルの「リードが決めた点」（印を外された元の管理者も P2 に含める）、デザイナーの意見 D-10。

## P1 管理者（佐藤さん）

- **役割**: MasterSmith の管理画面で、利用者と業務データの設定を受け持つ管理者（管理者の印を持つ利用者）。ほかの管理者は1〜2人いる。
- **目的**:
  - 利用者の状態（管理者かどうか・止めているか・ロック中か）を一目で確かめたい
  - 退職や異動の人の利用をすぐ止め、戻ってきたら再開したい
  - パスワードを誤り続けてロックされた人を、30 分待たせずに使えるように戻したい
  - 管理者の担当を替えるときに、印を付け替えたい
  - 登録の時の誤りや利用者の頼みに応じて、氏名・言語を直したい
- **困りごと（今）**:
  - 利用者を管理する画面が無く、DB を直接直すしかない（KB `business-overview.md`）
  - ロックされた人は、解除の予定の時刻まで待つしかない
  - 誤って最後の管理者を無くすと、管理画面に誰も入れなくなる
  - 2〜3人の管理者で同じ利用者を同時に扱うと、ほかの人がすでに変えたことに気づけない（前提 A2 と、拒否の理由ごとの文言・一覧の読み直しの根拠）
  - 誤って人を止める・権限を与えると、利用者の仕事を止めたり管理のすべてをできるようにしてしまう（操作の前の確かめの表示の根拠）
- **使い方**: 問い合わせ（電話・チャット）を受けながら操作することが多い。操作の後に、相手に「もう入れます」と言えるだけの確かさ（今の状態の表示）が要る
- **技術への慣れ**: 中（DB は直接触りたくない）
- **アクセシビリティ**: キーボードや読み上げを使う管理者もいる（画面の共通の決まりの根拠）
- **使う頻度**: 週に数回。入社・退職・問い合わせのたび
- **言語**: 日本語が主。英語の画面も使うことがある

## P2 管理される利用者（田中さん）

- **役割**: MasterSmith の画面で業務データを扱う利用者。管理者の操作（利用停止・停止の解除・ロックの解除・印の付け外し・氏名と言語の変更）の結果を受ける側。管理者の印を外された元の管理者も含む（外された後は印の無い利用者として扱う。リードの決定、D-10 の (a)）。
- **目的**:
  - ロックされたら、管理者に頼んですぐにログインできるように戻してほしい
  - 止められている間は使えず、再開されたら再びログインして使いたい
  - 管理者の印を外されたら、管理の画面が使えなくなったことを分かりやすく知りたい（どの管理の画面を開いていても）
- **困りごと（今）**:
  - ロックされると 30 分待つしかない
  - 止められたかどうかを、画面から推測できてしまうのは困る（止められていることは管理者から聞けばよい。攻撃者に知られたくない）
  - 管理者の印を外された元の管理者は、管理の画面が「ページが見つかりません」などになると、画面が壊れたと誤解する
- **技術への慣れ**: 低〜中
- **使う頻度**: ほぼ毎日

## ペルソナの関係と優先度

| 優先 | ペルソナ | 関係 |
|---|---|---|
| 1 | P1 管理者 | 操作する人。US1.1・US2.1・US3.1・US4.1・US5.1 の主語になる |
| 2 | P2 管理される利用者（元の管理者を含む） | P1 の操作の結果を受ける人。US2.2・US3.2 の主語になり、利用停止・ロックの解除・印の変更の効き目を確かめる観点になる |

P1 の管理者も、ほかの管理者の操作の結果としては P2 の立場になる（印を外される・止められる）。運用者・監査者は独立したペルソナにせず、監査に残る記録の受け入れ基準の中で扱う（ストーリーの質問 Q1）。
