# Refined Mockups の質問

承認済みのユーザーストーリー（`aidlc/spaces/default/intents/260930-user-admin/inception/user-stories/stories.md`）と要件をもとに、利用者の管理の画面の組み立てを決めます。classic の範囲のため、Ideation のラフな画面イメージと利用者の流れはありません。画面イメージはストーリーと要件から直接作ります。

## 決まっていること（質問にしない）

- **置き場:** 管理画面の中（サイドバーの管理のメニューから開く）で、招待の画面と同じ形の1つの画面にする（FR8.1）。部品は make-you-chic-ui のもの（`Table`・`Badge`・`Button`・`Modal`・`Toast`・`Alert`・`TextInput`・`FormField`・`Select` など）を使い、足りない部品は frontend の側で作る（PM）。
- **画面の共通の決まり（ストーリーの前提）:**
  - 4つの状態（読み込み中・表示・結果 0 件・読み込みの失敗）を持つ。
  - 成功は `Toast`、失敗は理由ごとの文言を `Alert` で出し、どちらの後も一覧を読み直す。
  - 処理中は二重の送信を防ぐ。
  - 行ごとの読み上げの名前を付け、状態は色だけに頼らない。
  - キーボードで操作できる。
  - 日時は利用者の言語の書式で出す。
  - light・dark と文字の大きさのすべての組で崩れない。
  - ja・en の両方を用意する。
- **確かめの表示:** 5つの操作（印を付ける・外す・止める・停止を解く・失敗回数を戻す）の前に出す。はじめのフォーカスは「やめる」、Escape で閉じ、背景のクリックでは閉じない（M4 B）。
- **自分の行:** 自分の行の「印を外す」「止める」は押せない形で出し、理由を示す（M6 B）。
- **403 を受けたとき:** 管理の画面すべてで同じ表示にし、ログインの状態を読み直して管理のメニューを消す（M5 B）。
- **アクセシビリティ:** WCAG 2.1 AA（前の Intent と同じ）。

ストーリーの承認のときに受け入れた指摘のうち、画面にかかわる2点（一覧の並びの向き、403 の表示の文言）も、ここで尋ねます。
