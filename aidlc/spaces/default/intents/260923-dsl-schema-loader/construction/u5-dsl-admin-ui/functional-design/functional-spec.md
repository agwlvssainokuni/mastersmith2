# Functional Spec — U5 DSL の管理画面（u5-dsl-admin-ui）

U5 は、管理者が DSL を扱う画面（`/admin/dsl`）と、その画面が使う ApiClient の拡張を受け持つ。画面の配置は `inception/refined-mockups/mockups.md`、部品ごとの状態・入力・アクセシビリティは `inception/refined-mockups/interaction-spec.md`、使う make-you-chic-ui の部品は `inception/refined-mockups/design-system-mapping.md`、点検の項目は `inception/refined-mockups/accessibility-checklist.md` が正本で、ここでは繰り返さない。API の形は `inception/contract-design/contract-summary.md` の C6 が正本。ここで決めるのは、画面の中の置き場・状態の持ち方・読み直し・API の呼び方・文言の持ち方である。

U5 は画面の単位のため、保存するデータ（エンティティ）を持たない。画面の中の状態は `frontend-components.md` の2節に示す。

## 1. 置き場と登録

| 項目 | 値 |
|---|---|
| 機能の置き場 | `frontend/src/features/dsl/` |
| 機能の識別（featureId） | `dsl` |
| 画面の URL | `/admin/dsl`（`layout: 'SHELL'`・`access: 'ADMIN'`） |
| サイドバーの項目 | 識別 `dsl`、文言の鍵 `dsl.nav.label`（「DSL」／「DSL」）、`path: '/admin/dsl'`、`order: 210`（「管理」の 200 の次）、`visibleWhen: 'ADMIN'` |
| 文言 | 登録の `messages` に ja・en を対で置く。鍵は `dsl.` で始める |
| API の呼び方 | 既存の `frontend/src/shared/api-client` を使う（`frontend-components.md` の 1.3 の拡張を含む） |
| 画面の読み込み | 既存の機能と同じく `lazy` で読み込む。名前付きのエクスポートだけを使う |

- **BR1.1** 登録は `frontend/src/features/dsl/registration.ts` の名前付きの `registration` だけで行い、画面の骨組み（`frontend/src/app/`）のファイルは書き換えない（既存の登録の決まり）。
- **BR1.2** サイドバーの「DSL」を隠すのは表示の切り替えにすぎない。管理者でない利用者が URL を直接開いたときは、既存の `access: 'ADMIN'` の扱い（表示できない旨）になり、判定はサーバー側（401・403）で行う（AC6.2.4）。

## 2. 画面の部品の構成と API の呼び方

部品の構成、dslApi（C6 の 11 本の呼び方、BR2.1〜BR2.5）、ApiClient の拡張（BR2.6〜BR2.8）は `frontend-components.md` の1節に置く。

## 3. 画面の状態

画面が持つ値と、プレビューのタブの状態の移り変わり（BR3.1〜BR3.3）は `frontend-components.md` の2節に置く。

## 4. 操作の手順

### 4.1 画面を開く

1. 今の状態（getStatus）と、プレビューのタブの中身（getPreview）を読む。
2. 適用中が無ければ「まだ適用していません」、プレビューが無ければ「プレビューはありません」と読み込み・投入への案内を出す（AC3.1.7）。

### 4.2 スキーマの読み込み・投入・履歴からの戻し

1. プレビューがあれば、置き換えの確認を出す（今のプレビューの出どころ・置いた人・日時を示す。AC1.1.6・AC2.1.3・AC5.1.4）。やめたら何も変えず、投入の入力は残す。
2. 投入では、入力が無ければ投入のボタンを使えなくして案内を出す（AC2.1.4）。大きさが上限を超えれば送らずに案内する（BR2.3）。
3. 処理中にして API を呼ぶ（BR3.2）。
4. 成功したら、Toast で知らせ、プレビューのタブに切り替え、今の状態を読み直し、応答のプレビューを表示し、プレビューのパネルの見出しへフォーカスを移す。投入の入力は空に戻す。
5. 422 なら、誤りの一覧を出す（5節）。投入の入力（貼り付けた文字列、選んだファイル名）は残す（AC2.2.9）。戻しの 422 は履歴のタブに出す（AC5.1.6）。
6. 503 なら、設定が無いのか接続できないのかを分けた文言で、運用者に確かめてもらう案内を出す（AC1.1.7・AC1.1.8）。
7. 404 `DSL_REVISION_NOT_FOUND` なら、その版が無くなったことを出し、履歴を読み直す。

### 4.3 適用

1. 確かめる表示を出し、違いの件数（増えた・減った・変わったテーブルとカラムの数）と照合の警告の件数を示す（AC4.1.2）。件数は表示中のプレビューの `diff` と `warnings` から数える。
2. 確かめたら、表示中の `previewId` を付けて適用する（BR2.5）。
3. 成功したら、Toast「DSL を適用しました」、今の状態に応答の値を入れ、プレビューのタブを空の状態にする（AC4.1.1）。履歴は次に履歴のタブを開いたときに読み直す。
4. 409 `DSL_PREVIEW_CHANGED` なら、今の状態を読み直し、プレビューがあれば（識別が違う）「別の管理者によって置き換えられました」と「最新のプレビューを表示する」を、無ければ「別の管理者によって破棄されました」と空の状態の案内を出す（AC4.2.1・AC4.2.2、mockups.md の 3.6）。どちらでも自動で適用しない。

### 4.4 破棄

1. 確かめる表示を出す（AC3.3.1）。やめたら何も変えない。
2. 確かめたら破棄し、成功したら Toast と空の状態。
3. 404 `DSL_PREVIEW_NOT_FOUND` なら、既に無いことを知らせ、空の状態にする（AC3.3.3）。

### 4.5 ダウンロード

1. プレビュー中はプレビューのパネルから、適用中は履歴のタブから、ダウンロードする（BR2.4、AC3.4.1・AC5.2.1）。
2. 404 なら、無いことを知らせ（`DSL_PREVIEW_NOT_FOUND`・`DSL_APPLIED_NOT_FOUND`）、今の状態を読み直す。

### 4.6 読み直しの決まり

- **BR4.1** 読み込み・投入・戻し・適用・破棄の成功の後、適用の拒否（409）の後、プレビュー・版・適用中が無い（404）の応答の後に、今の状態と開いているタブの中身を読み直す。
- **BR4.2** 定期的な自動の読み直しはしない。ほかの管理者の操作は、次の操作・読み直しの時点で分かる（適用は `previewId` で守られる、US4.2）。

## 5. 誤り・警告・知らせの表示

- **BR5.1** 誤りの一覧は、件数（`total`）を先頭に出し、先頭100件（`errors`）を行・列・場所・内容の表で示す。`total` が表示の件数より多ければ、残りの件数を示す（mockups.md の 5.2）。
- **BR5.2** 誤りの種類（`kind`）ごとに見出しの文言を画面で持つ（構文・意味・版・大きさ・深さ・別名・タグ・重複キー）。危険な形・版の非対応（`SIZE_LIMIT`・`DEPTH_LIMIT`・`ALIAS_LIMIT`・`FORBIDDEN_TAG`・`DUPLICATE_KEY`・`UNSUPPORTED_VERSION`）で1件だけのときは、理由の1件だけを出す（interaction-spec.md の single-reason）。
- **BR5.3** 誤り・警告の一つ一つの内容（`message`）は、サーバーが表示言語で返した文言をそのまま示す。画面で作り直さない。行・列・場所が無い（null）ときは「—」を示す。
- **BR5.4** 誤りの一覧を出したときは、件数の警告（`role="alert"`、`tabindex="-1"`）へフォーカスを移し、件数と、表示を100件に絞ったことを読み上げる（AC2.2.9）。
- **BR5.5** 失敗の知らせは、サーバーの `code` から文言を選ぶ（6節）。知らない `code`・`code` の無い応答・通信の失敗は、状態コードの種類に応じた一般の文言にする。内部の例外の文言、`detail`、接続先の値は画面に出さない（AC1.1.7・AC2.2.8）。
- **BR5.6** 表示名が埋まっていない場所（`missingDisplayNames`）は、先頭100件を場所と言語で示し、総数を示す。総数は U4 の BR2.3 の値（`missingDisplayNameTotal`）を使い、無ければ一覧の件数を示す（AC3.1.2）。
- **BR5.7** 違いの表は、テーブルの区分をバッジの文字（増えた・減った・変わった・変わらない）で示し、既定では違いのあるテーブルだけを示す。「すべて表示」で変わらないテーブルも示す。適用中が無い（`appliedExists: false`）ときは、「適用中の DSL がまだ無いため、すべてを増えたとして示します」と添える（AC3.1.3〜AC3.1.5）。変わった項目（`changedItems`）は項目の名前のまま示す。
- **BR5.8** 照合の警告は、種類ごとの見出しと、場所・内容を示す。照合できなかった（`TARGET_UNCONFIGURED`・`TARGET_UNAVAILABLE`）ときは、照合できなかったことを先頭に示し、プレビューそのものは表示する（AC3.2.1〜AC3.2.4）。
- **BR5.9** テーブル名・カラム名などの物理名と、DSL の識別は訳さない。メニューの木の表示名は、表示言語（ja・en）の表示名を示す（AC6.2.5）。
- **BR5.10** DSL の識別は先頭12文字に縮めて示し、全体をツールチップと読み上げで読めるようにする（interaction-spec.md の DslStatusPanel）。

## 6. 文言

- **BR6.1** 文言は登録の `messages` に ja・en を対で置き、鍵は `dsl.` で始める。サーバーの `code` ごとの文言の鍵は `dsl.error.<code>`、誤りの種類ごとは `dsl.errorKind.<kind>`、警告の種類ごとは `dsl.warningKind.<kind>`、出どころは `dsl.source.<source>`、違いの区分は `dsl.change.<change>` とする。
- **BR6.2** `code` の文言は、何が起きたか・どうすればよいかを書く。

| code | 文言の要点（ja） |
|---|---|
| DSL_INVALID | DSL に誤りがあります。一覧を見て直してください |
| DSL_TOO_LARGE | DSL が大きすぎます（5MB まで） |
| DSL_PREVIEW_NOT_FOUND | プレビューはありません（別の管理者が適用・破棄した可能性があります） |
| DSL_PREVIEW_CHANGED | 確かめた後にプレビューが変わりました（4.3 の 4 で置き換え・破棄を分ける） |
| DSL_APPLIED_NOT_FOUND | 適用中の DSL はありません |
| DSL_REVISION_NOT_FOUND | その版は履歴にありません（件数の上限で消えた可能性があります） |
| TARGET_DB_UNCONFIGURED | 対象DB の接続先が設定されていません。運用者に確かめてください |
| TARGET_DB_UNAVAILABLE | 対象DB に接続できませんでした。運用者に確かめてください |

- **BR6.3** 日時は UTC で受け取り、表示言語に合わせた書式で、利用者の端末の時差で示し、時差の略号を添える（例: `2026-09-20 16:40 JST`）。

## 7. アクセシビリティ

- **BR7.1** 部品ごとのロール・キーボード・名前・フォーカスは interaction-spec.md のとおり。確かめる表示は、はじめのフォーカスを「やめる」にし、閉じると開く前のボタンへ戻す。背景のクリックでは閉じない。
- **BR7.2** 処理中と結果は読み上げの領域で伝える（成功は `aria-live="polite"`、失敗は `assertive`）。
- **BR7.3** 検証の結果・警告・誤り・適用中の印は、色だけでなく記号と文言で示す（WCAG 2.1 AA、accessibility-checklist.md）。
- **BR7.4** 画面の各部品に、アクセシビリティ検査（vitest-axe）のテストを1件ずつ入れ、違反0件とする（AC6.2.6）。

## 8. アクセス制御の一括の確かめ

- **BR8.1** C6 の 11 本の API を1つの一覧にし、未認証（401）・管理者でない（403）・管理者（成功）を、サーバー側の結合テストで一括して確かめる（AC6.2.1〜AC6.2.3、unit-of-work-story-map.md の「一括の確かめは U5 で閉じる」）。403 ではアクセス拒否の監査の出来事が記録されることも確かめる。401・403 では内部DB のプレビューと履歴が変わらないことを確かめる。各 API の個別の確かめは U4 が持つ。
- **BR8.1a** このテストはバックエンドの結合テストで、U5 の境界（画面と ApiClient）の外にある。置き場は `backend/src/test/java/cherry/mastersmith/dslmanage/web/` の `DslAccessControlIT`（team.md の `XxxIT` の命名）とし、U5 の Bolt（B6）で書く。U4 の API がすべてそろった後に書くためで、本番のコードは足さない（テストだけ）。
- **BR8.2** 画面でサイドバーの項目を隠すことは、BR8.1 の代わりにしない（`aidlc/spaces/default/memory/team.md` の Testing Posture）。

## 9. 失敗の場合とふるまい

| 場合 | ふるまい |
|---|---|
| 今の状態・プレビュー・履歴を読めない（通信・5xx） | その領域に Alert と「もう一度読み込む」。ほかの領域は使える |
| 投入の入力が無い | 投入のボタンを使えなくし、案内を出す |
| 投入が 5MB を超える（送る前・413） | 送らない（413 は送った後）、上限の案内。入力は残す |
| 投入・戻しが 422 | 誤りの一覧、入力は残す、件数へフォーカス |
| 読み込みが 503 | 設定が無い・接続できないを分けた案内。プレビューは変わらない |
| 適用が 409 | 今の状態を読み直し、置き換え・破棄を分けて示す。自動で適用しない |
| 破棄・ダウンロードが 404 | 無いことを知らせ、読み直す |
| 401（更新しても未認証） | 既存の ApiClient がログインの画面へ戻す |
| 403 | 既存の管理者向け領域と同じ、表示できない旨 |
| 知らない code・code 無し | 状態コードの種類に応じた一般の文言。`detail` は出さない |
| 確かめる表示をやめる | 何も送らない、何も変えない、フォーカスを元のボタンへ |
