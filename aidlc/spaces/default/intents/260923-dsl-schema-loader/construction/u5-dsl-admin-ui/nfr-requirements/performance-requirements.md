# Performance Requirements — U5 DSL の管理画面（u5-dsl-admin-ui）

画面の時間の目標を示す。API の時間（照合 10 秒・生成 30 秒・ほかの API 1 秒）は U4 の performance-requirements.md。答えは `nfr-requirements-questions.md`（要点の確認）。NFR1 の枝番は単位の間で通しで振る（U4 までで NFR1.17）。

| ID | 対象 | 目標 | 条件 | 測り方 |
|---|---|---|---|---|
| NFR1.18 | 画面を開いてから、今の状態とプレビューが表示されるまで | 3 秒以内（照合の時間を除く）。照合を含む表示は、API の 10 秒に画面の 1 秒を足した 11 秒以内 | 想定の規模（100 テーブル × 100 カラム）のプレビュー、手元の PC のブラウザー | Build and Test で E2E（実際のブラウザー）で測る。時間は統合の関門のテストにせず、測った値を記録する（jsdom の時間は不安定なため。team.md の「不安定なテストは統合しない」） |
| NFR1.19 | 違いの表の描き方 | 開いた行のカラムだけを描く（100 テーブル × 100 カラムを一度に描かない）。行を開いてから表示まで 0.5 秒以内 | 1つのテーブルに 100 カラム | 描き方（開いた行だけが描かれること）は画面部品のテストで確かめる。時間は E2E で測って記録する（NFR1.18 と同じ扱い） |
| NFR1.20 | 10MB のファイルを選んでから送り始めるまでの読み込み | 2 秒以内 | 上限の大きさのファイル | 大きさの判定（バイト数で、文字列にする前に判定する）は画面部品のテストで確かめる。時間は E2E で測って記録する |
| NFR1.21 | 誤りの一覧の表示 | 先頭 100 件だけを描く（総数は数字で示す） | 誤りが 100 件を超える | 画面部品のテスト（機能設計の BR5.1） |
