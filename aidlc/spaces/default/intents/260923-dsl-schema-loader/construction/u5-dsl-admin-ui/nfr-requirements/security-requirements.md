# Security Requirements — U5 DSL の管理画面（u5-dsl-admin-ui）

画面のセキュリティ・日英・アクセシビリティの要件を示す。アクセス制御の判定はサーバー側（U4・既存の AccessControl）で、画面の表示の切り替えはその代わりにしない（機能設計の BR1.2・BR8.2）。

## 1. 守るものと脅威

| 脅威（STRIDE） | 例 | 主な対策 |
|---|---|---|
| 改ざん・情報の漏えい（T・I） | DSL の表示名や対象DB のコメントに HTML・スクリプトを入れ、画面で動かす（XSS） | NFR3.9 |
| 情報の漏えい（I） | アクセストークンを画面の部品やログに持ち回る。サーバーの内部の情報を画面に出す | NFR3.10、NFR5.6 |
| なりすまし（S） | JSON Schema のリンクを外のサイトに向ける | NFR3.11 |

## 2. 要件

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR3.9 | DSL・対象DB・サーバーから来る文字列（表示名・コメント・誤りの文言・警告・物理名）は文字として表示し、HTML として埋め込まない（`dangerouslySetInnerHTML` を使わない。リンタの `react/no-danger` で止める） | リンタと画面部品のテスト（`<script>` を含む表示名が文字のまま表示される） | NFR3、team.md の Code Style |
| NFR3.10 | アクセストークンは既存の ApiClient だけが扱い、画面の部品の状態・URL・ログに入れない。ダウンロードも ApiClient を通す | コードの点検と画面部品のテスト | 既存の決まり |
| NFR3.11 | JSON Schema のリンクは同じオリジンの静的なファイル（例 `/dsl/dsl-schema-v1.json`）だけを指す。外の URL を組み立てない | 画面部品のテスト | U2 の NFR 要件（F1: A） |
| NFR5.6 | 失敗の文言は `code` から選び、`detail`・内部の文言・接続先を出さない。`DSL_BUSY` と `DSL_TOO_LARGE`（10MB）の文言を持つ | 画面部品のテスト | NFR5、U4 の NFR 要件 |
| NFR9.1 | 画面の文言はすべて ja・en を対で持ち、欠けを単体テストで止める（既存の登録の検査）。物理名・識別は訳さない | 単体テストと画面部品のテスト（英語にしたときの表示、AC6.2.5） | NFR9 |
| NFR10.1 | 画面の部品ごとに vitest-axe で違反 0 件。WCAG 2.1 AA（コントラスト・キーボード・読み上げ・色だけに頼らない） | 画面部品のテスト（AC6.2.6）と accessibility-checklist.md の点検 | NFR10 |
