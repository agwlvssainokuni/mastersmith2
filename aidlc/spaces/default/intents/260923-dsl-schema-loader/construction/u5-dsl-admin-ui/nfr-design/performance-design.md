# Performance Design — U5 DSL の管理画面（u5-dsl-admin-ui）

画面の性能の要件（`construction/u5-dsl-admin-ui/nfr-requirements/performance-requirements.md`）を満たす作りの方針。要点の確認は `nfr-design-questions.md`。

| ID | 作り |
|---|---|
| NFR1.18 | 画面を開いたときに、今の状態（`GET /status`）とプレビュー（`GET /preview`）を同時に要求する。プレビューの表示を待つ間も今の状態は先に描く。時間は Build and Test の E2E（実際のブラウザー）で、想定の規模のプレビューで測って記録する（統合の関門のテストにしない） |
| NFR1.19 | 違いの表はテーブルの行だけを描き、カラムの違いは行を開いたときだけ描く（開いていない行のカラムは描かない）。メニューの木は既定で1段目だけを開く。描き方は画面部品のテストで確かめ、開くまでの時間は E2E で測る |
| NFR1.20 | ファイルの大きさ（`File.size`、バイト数）で 10MB を先に判定し、超えたら読まずに案内する（読む前に判定するので、上限を超えるファイルを読み込まない）。上限の内なら、承認済みの機能設計の BR2.2 のとおり、テキスト（UTF-8）として読んで `application/yaml` の本文で送る。貼り付けは文字列を UTF-8 にしたバイト数で判定する |
| NFR1.21 | 誤りの一覧は先頭 100 件だけを描き、総数は数字で示す（機能設計の BR5.1） |
