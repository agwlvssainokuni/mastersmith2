# Security Requirements — U3 既定の DSL の生成（u3-default-dsl-generation）

U3 が受け持つ非機能の要件のうち、セキュリティに関わるものを示す。U3 は対象DB の写し（U1 の結果）から既定の DSL を作るだけで、対象DB に直接は触れず、利用者の入力も受け取らない。機能の決まりは `construction/u3-default-dsl-generation/functional-design/rules.md`（BR1.x〜BR5.x）、選定と数値は `tech-stack-decisions.md`。答えは `nfr-requirements-questions.md`（Q1・Q2）。

## 1. 守るものと脅威

| 守るもの | 脅威（STRIDE） | 例 | 主な対策 |
|---|---|---|---|
| 生成した DSL の正しさ | 改ざん（T） | 対象DB のコメントや名前に YAML の記号・改行があり、書き出した YAML の構造が変わる（別の項目を差し込まれる） | NFR4.7、NFR4.8 |
| 対象DB の接続情報 | 情報の漏えい（I） | 生成した DSL・誤り・ログに接続先が入る | NFR4.9 |
| アプリの可用性 | サービス拒否（D） | 巨大なスキーマで生成が終わらない、メモリを使い切る | NFR1.7、NFR2.5 |

対象DB のコメントは、対象DB の管理者が書いた信頼できない文字列として扱う（DSL の作者と同じく、アプリの外から来る値）。

## 2. 要件

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR4.7 | YAML は YAML の部品（SnakeYAML）で書き出し、文字列の連結で組み立てない。名前とコメントは部品に引用させる | 性質ベースのテスト（jqwik）: 任意の文字列（`:`・`#`・`-`・改行・引用符・`&`・`*`・`!` を含む）のコメントと名前で生成した DSL が、U2 の検証を通り、読み直した値が元と同じ | NFR4、BR5.2 |
| NFR4.8 | コメントの制御文字（改行・タブを除く C0・C1 の制御文字）は取り除く。長さは切り詰めない | 単体テスト: 制御文字が消え、改行・タブと長いコメントはそのまま残る | BR1.2 |
| NFR4.9 | 生成した DSL・U3 の結果・ログに、接続先・ユーザー名・パスワードを含めない（DSL の書式に接続先の項目が無く、U3 は写しだけを受け取る） | 単体テスト: 生成した DSL に写しの外の値が入らない。結合テスト（U4）で生成した DSL に接続先の文字列が無い（ストーリーの AC3.4.4） | NFR4、BR5.3 |
| NFR2.5 | 生成した DSL も U2 の上限（10MB）の内に収める。超えたら生成の失敗（想定外の失敗）とし、プレビューを変えない | 単体テスト: 上限を超える写しで失敗し、部分的な DSL を返さない。Build and Test: 100 × 100 の生成で上限の内（約 5.3MB） | NFR2、BR5.2、Q1: B |

## 3. 残る危険

| 危険 | 扱い |
|---|---|
| 対象DB のコメントに、画面に出すと危険な文字列（HTML など）がある | U3 は文字列のまま DSL に入れる。画面（U5）は文字として表示し、HTML として埋め込まない（team.md の Code Style の `react/no-danger`） |
| 想定を大きく超えるスキーマ（数千テーブル）で、生成した DSL が 10MB を超える | NFR2.5 で失敗にする。対象のスキーマを分けるなどの対応は、利用者の運用に任せる（README に書く） |
