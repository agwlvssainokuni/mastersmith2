# Security Requirements — U4 DSL の管理（u4-dsl-management）

U4 の API のセキュリティの要件を示す。アクセス制御（管理者だけ）は既存の仕組み（AccessControl）で、各 API の 401・403 は U4、一括の確かめは U5（BR8.1）。機能の決まりは `construction/u4-dsl-management/functional-design/rules.md`。

## 1. 守るものと脅威

| 守るもの | 脅威（STRIDE） | 主な対策 |
|---|---|---|
| 適用中の DSL（後続の画面の元） | 改ざん（T）: 管理者でない人が投入・適用する。確かめていない DSL を適用させる | NFR3.7、NFR8.2（見たプレビューの識別） |
| アプリの可用性 | サービス拒否（D）: 大きな本文の連続、重い処理の重なり | NFR2.6、NFR1.13 |
| 接続情報・内部の情報 | 情報の漏えい（I）: 応答・ダウンロード・ログに接続先や部品の例外の文言が出る | NFR4.10、NFR5.4 |
| 監査の記録 | 否認（R）: 誰が適用したか分からない | 監査の出来事（機能設計の BR7.x） |

## 2. 要件

| ID | 要件 | 確かめ方 | 出典 |
|---|---|---|---|
| NFR2.6 | 要求の本文の上限は、投入の API（`POST /api/admin/dsl/preview`）だけ 10MB（10,485,760 バイト）、ほかの API は今までどおり 1MB。超えたら 413（投入の API は `DSL_TOO_LARGE`） | 結合テスト: 投入の API でちょうど 10MB は受け付け、1 バイト超えは 413。ほかの API で 1MB 超えは既存の 413 | NFR2、BR1.6 |
| NFR3.7 | DSL の操作の API は管理者だけ（未認証 401・管理者でない 403）。検証はサーバー側を正とし、API を直接呼んでも同じ検証を通る | 結合テスト（各 API。一括は U5 の BR8.1） | NFR3 |
| NFR4.10 | 応答・ダウンロード・ログ・監査に、対象DB の接続先・ユーザー名・パスワードを含めない | 結合テスト（AC1.1.7・AC3.4.4・AC6.3.2） | NFR4 |
| NFR5.4 | エラー応答は Problem Details と安定した `code`。部品の例外の文言・スタックトレース・`detail` に内部の情報を載せない。誤りの一覧は文言の鍵から表示言語の文言にする | 結合テスト（AC2.2.8） | NFR5 |
| NFR5.5 | 新しい code `DSL_BUSY`（503）を1つの状態コードで登録する（既存の仕組みでは1つの code に状態コードは1つ） | 起動時の登録の検査（既存）と結合テスト | NFR5、Q2: A |
| NFR3.8 | ダウンロードは `Content-Disposition: attachment` と `application/yaml`（`X-Content-Type-Options: nosniff` は既存）で返し、画面の中で表示させない | 結合テスト | NFR3 |

## 3. 残る危険

| 危険 | 扱い |
|---|---|
| 管理者の端末から大きな本文を繰り返し送られる | 管理者だけの API で、重い処理は同時に1つ（NFR1.13）。回数の制限は範囲外 |
| DSL の中の文字列（表示名など）が画面で HTML として解釈される | 画面（U5）は文字として表示する（team.md の `react/no-danger`） |
