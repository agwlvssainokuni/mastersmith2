# Accessibility Checklist — DSL の管理画面

目標は **WCAG 2.1 の AA**（`refined-mockups-questions.md` の Q7: A）。部品ごとの axe の検査（違反0件、AC6.2.6）に加えて、axe では見つからない点をキーボードと読み上げで確かめる。確かめ方の列は、画面の部品のテスト（Vitest＋Testing Library＋user-event＋vitest-axe）か、手での確認（キーボード・読み上げ・拡大）のどちらで確かめるかを示す。

## 1. 知覚できる（Perceivable）

| # | 項目 | WCAG | 当てる場所 | 確かめ方 |
|---|---|---|---|---|
| P1 | 状態・区分・結果を色だけで示さない。文字（増えた・減った・変わった・変わらない・適用中）と記号を必ず付ける | 1.4.1 | 違いの表、履歴、検証の結果、警告、誤り | 部品のテスト（文字の有無） |
| P2 | 文字のコントラストは 4.5:1 以上、部品と記号は 3:1 以上 | 1.4.3、1.4.11 | 画面の全体 | axe、make-you-chic-ui の値だけを使う |
| P3 | 表は列見出しを持ち、見出しと値が結び付く | 1.3.1 | 違いの表、誤りの一覧、履歴 | axe、部品のテスト |
| P4 | 画面の見出しの順（「DSL」→ 今の状態・各タブのパネル → 要約・違い・警告・メニュー）が飛ばない | 1.3.1、2.4.6 | 画面の全体 | 部品のテスト（見出しの階層） |
| P5 | 記号（Icon）は飾りなら読み上げから外し、意味を持つなら文字を並べる | 1.1.1 | 検証の結果、警告、開閉 | axe |
| P6 | 200% に拡大しても、横に動かすのは表だけで、文字が欠けない | 1.4.4、1.4.10 | 画面の全体 | 手で確認 |
| P7 | 省略した識別（ハッシュ値の先頭）の全体を、読み上げでも得られる | 1.1.1 | 今の状態、履歴 | 部品のテスト |

## 3. 理解できる（Understandable）

| # | 項目 | WCAG | 当てる場所 | 確かめ方 |
|---|---|---|---|---|
| U1 | 画面の言語（`lang`）が表示言語（ja・en）に合う | 3.1.1 | 画面の全体 | 既存の仕組みに乗る。部品のテスト |
| U2 | 入力の欄は見える label を持ち、案内（5MB まで・YAML）を入力の前に示す | 3.3.2 | 投入 | 部品のテスト |
| U3 | 誤りは文字で、何が・どこで・どう直すかを示す（行・列・場所・内容） | 3.3.1、3.3.3 | 誤りの一覧、読み込みの失敗、適用の拒否 | 部品のテスト |
| U4 | 取り消しにくい操作（適用・破棄・置き換え）は、確かめる表示を経る | 3.3.4 | 適用、破棄、読み込み・投入・戻し | 部品のテスト |
| U5 | 操作の結果で、利用者が求めていない画面の切り替えを起こさない（成功でプレビューのタブへ切り替えるのは、操作の結果を見せるため、とあらかじめ文言で示す） | 3.2.2 | 読み込み・投入・戻しの成功 | 手で確認 |
| U6 | 同じ働きの部品は、どのタブでも同じ文言・同じ位置にする | 3.2.4 | ダウンロード、確かめる表示 | 設計の確認 |

## 4. 堅牢（Robust）

| # | 項目 | WCAG | 当てる場所 | 確かめ方 |
|---|---|---|---|---|
| R1 | 処理中・成功・失敗を、読み上げ用の領域で伝える（処理中・成功は `polite`、失敗は `assertive` または `role="alert"`） | 4.1.3 | 処理中の表示、Toast、Alert | 部品のテスト |
| R2 | 開閉のボタンは `aria-expanded` で状態を伝える | 4.1.2 | 違いの表、メニューの木 | 部品のテスト |
| R3 | 確かめる表示は `role="dialog"`・`aria-modal="true"` で、見出しで名前を付ける | 4.1.2 | Modal | axe、部品のテスト |
| R4 | 誤りの件数が表示されたら、件数の警告へフォーカスを移し、件数を読み上げる | 4.1.3 | 誤りの一覧 | 部品のテスト |
| R5 | ネイティブの要素（`button`・`input type="file"`・`table`）を優先し、ARIA の役割は足りないときだけ使う | 4.1.2 | 画面の側で作る部品 | コードの確認 |

## 5. 点検の手順

1. 部品ごとの axe の検査（違反0件）を、画面の部品のテストに1件ずつ入れる（`aidlc/spaces/default/memory/team.md` の Testing Posture）。
2. キーボードだけで、`mockups.md` の8節の各ストーリーの流れを最後まで行う。
3. 読み上げ（macOS の VoiceOver）で、処理中・成功・失敗・誤りの件数・確かめる表示が伝わるかを確かめる。
4. 200% の拡大と、767px 以下の幅で、文字が欠けず操作できるかを確かめる。
