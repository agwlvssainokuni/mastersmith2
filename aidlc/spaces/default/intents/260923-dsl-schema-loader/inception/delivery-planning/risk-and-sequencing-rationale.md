# Risk and Sequencing Rationale — dsl-schema-loader

Bolt（1回分の作りの区切り。設計から実装・テストまでを通し、動くものができて終わる）の順序を、なぜこうしたかを示す。確定した答えは `delivery-planning-questions.md` の Q1〜Q5。

## 使った考え方

**危険の大きいものを先に（risk-first、Boehm の Spiral Model の考え方）** を、依存の図（`inception/units-generation/unit-of-work-dependency.md`）が許す範囲で当てた。WSJF（価値と緊急度と危険の減りを、作る大きさで割って順位を付ける方法）のような点数付けは使っていない。単位の数が少なく、依存がほぼ一本道のため、点数を付けても順序の選択肢は「U1 と U2 のどちらを先にするか」だけになるからである。

## 順序と理由

| 順 | Bolt | 理由 |
|---|---|---|
| 1 | B1 DSL の定義（U2） | 最も不確かな「誤りの行・列を求める作り」（ADR-008）と、Jackson 3 系と組み合わせられる YAML・JSON Schema の部品の選定を先に確かめる（Q1: A）。U2 はどの単位にも依存しないため、先に置ける。後続の Intent が使うモデルの形もここで決まり、U3・U4 の前提になる |
| 2 | B2 対象DB（U1） | 既存の構成に手を入れる「対象DB の接続の足し方」（ADR-006）と、Testcontainers の導入を確かめる。U3・U4 の前提 |
| 3 | B3 既定の DSL の生成（U3） | U1・U2 に依存する。3種類の DB の型の違いと性能（30 秒）を確かめる |
| 4 | B4 DSL の管理（基本、U4 の Must） | U1〜U3 に依存する。Must のストーリーの大半と、状態の移り変わり・同時の操作・監査を受け持つ |
| 5 | B5 DSL の管理（履歴、U4 の Should） | B4 の履歴の書き込みの上に足す。Should のため、Must の後に置く（Q2: A、Q3: A） |
| 6 | B6 DSL の管理画面（U5） | U4 の API に依存する。API の形（契約）が固まってから作る |

## 依存の順（トポロジカルな順）との違い

依存の順を破る並びは無い。依存の図が許す並びのうち、U1 と U2 の順だけが選べ、U2 を先にした（Q1: A）。U4 を B4・B5 に分けたのは、1つの単位の中の区切りで、単位の間の依存は変わらない。

## 気がかりな点と、確かめ方

依頼者がいちばん気がかりとした2点（Q5: A・B）は、設計の段ごとに全単位を通す進め方（Q4: A）ではコード生成が最後になる。そのため、コード生成を待たずに、NFR 要件の段で小さく試して確かめる。

| 気がかりな点 | 確かめる時点 | 確かめ方 | 確かめられなかったとき |
|---|---|---|---|
| 誤りの行・列を求める作り（ADR-008） | NFR 要件（U2） | 候補の YAML・JSON Schema の部品で、位置の対応表と誤りのパスの突き合わせを小さく試す（本番のコードとは別の試しのコード） | 行・列を諦めてパスだけを示す案（ADR-008 の切り替え先）を依頼者に諮る |
| 対象DB の接続の足し方（ADR-006） | NFR 要件（U1） | 「既定の候補にしない」指定で2つ目の接続を足し、ログイン・監査・Flyway・ヘルスチェックが内部DB を向き続けるかを小さく試す | 内部DB を明示して既定にする形（ADR-006 の切り替え先）に切り替える |

## そのほかの危険

| 危険 | 見込み | 影響 | 手当て |
|---|---|---|---|
| 3種類の DB の結合テストが `./gradlew verify` の時間と colima の VM のメモリに収まらない | 中 | 中 | Build and Test で実測し、実行の場所を決める（team.md の Testing Posture）。それまでは3種類とも毎回実行 |
| 100テーブル×100カラムで 30 秒・10 秒を超える | 中 | 中 | メタデータをテーブルごとではなくまとめて読む作りを NFR 設計で比べる。測れないときは `Unverified` で持ち主の段を明記 |
| U4 が大きく、B4 の設計・実装が長引く | 中 | 中 | Should を B5 に分けた。B4 の中でも API ごとに層を積み、テストを通してから次へ進む |
| JDBC ドライバーのライセンス（GPL v2＋FOSS 例外、LGPL 2.1） | 低 | 高 | B2 で採用の前に確かめ、採用の理由を設計の記録に残す（team.md の Code Style） |
