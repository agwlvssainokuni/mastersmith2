## 1. アイコン `mail`・`users`・`shield` を足す

- **困っていること**: 管理メニューの項目（招待・グループ・ロール）に、意味の近いアイコンが `Icon` の登録の 18 個に無い。誤読を避けるため、無理に近い絵は使わず、アイコンを付けずにいる。
- **お願いしたい形**: `Icon` の登録に、`mail`（招待の意味）・`users`（グループの意味）・`shield`（ロール・権限の意味）を足し、`IconName` の型に出す。
- **使う場所**: サイドバーの管理の区画と、ホームの管理のカード。

## 2. アイコン `table`・`view`・`folder` を足す

- **困っていること**: 業務メニューの項目の既定のアイコンを、テーブル・ビュー・子を持つ項目（フォルダ）で見分けたいが、今の 18 個にこの3つに合う図柄が無い（`list` はテーブルに近いが、ビューとフォルダは近いものが無い）。
- **お願いしたい形**: `Icon` の登録に `table`・`view`・`folder` を足し、`IconName` の型に出す。
- **使う場所**: サイドバーの業務の区画と、ホームの業務のカードの既定。

## 3. `Topbar` にロゴを置く口を足す

- **困っていること**: アプリのロゴを上のバーの左端に出したいが、`Topbar` にロゴを置く口が無い。
- **お願いしたい形**: `Topbar`（`AppShell`）にロゴを受ける口（例: `logo?: ReactNode`）を足す。口を渡さないときの見た目は今のまま。
- **使う場所**: 画面の枠の上のバー。

## 取り込み

上流の `main` に入ったら、上流のソース（読み取りだけの `git show`）で確かめ、固定先の更新の専用のコミットで上げる。前後の `package-lock.json` の差（増えた・変わったパッケージと、`hasInstallScript` の付いた項目が増えていないか）を同じ記録に書く。取り込み前の間は、アイコン（1・2）は付けず、ロゴ（3）は出さない（ストーリーの Should の扱い）。
