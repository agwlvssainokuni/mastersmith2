# 要件定義（Intent 261102-timezone-ui-polish）

## 1. 依頼の分析

依頼: N6（業務データの日時のタイムゾーンの変換）と画面の仕上げを1つの Intent にまとめたもの [desc]。

| 目的 | 中身 | 出典 |
|---|---|---|
| 目的1（N6） | 時点を表す日時を、利用者が選んだタイムゾーンで見せ、同じタイムゾーンで入れられるようにする。今は時差つきの日時を UTC のまま見せ、入力も UTC で、ほかの画面（ブラウザのタイムゾーン）と食い違っている（K-96） | [desc] [Q1] [Q2] [Q3] [F1] |
| 目的2（アイコン） | アプリのアイコン（SVG と favicon）を作り、管理メニューと業務メニューのアイコンを項目の種類ごとに見分けられるようにする | [desc] [Q8] [Q9] [Q10] |
| 目的3（ホームと管理） | 中身の無いホームを、次に行く先が分かる画面にし、役割の無い管理の仮の画面を廃止する | [desc] [Q6] [Q7] |

- 種類: 既存の機能の拡張（N6・ホーム・アイコン）と画面の削除（管理の仮の画面）。複数の部品（backend の `businessdata`・`dsl`・`dslmanage`・`navigation`・`user`、frontend の骨組み・`tables`・`preferences`・`admin`）にまたがる。
- 複雑さ: 標準（Standard）。日時の変換は3種類の対象DB と夏時間に関わり境目が多い。アイコンは make-you-chic-ui の対応を待つ部分がある。

## 2. 機能要件

### FR1 表示のタイムゾーンの設定

- **FR1.1** 利用者は、プリファレンスの画面で表示のタイムゾーンを選べる。選べるのは「ブラウザに合わせる」（既定）と、ブラウザが知っているすべての IANA のタイムゾーン（例: `Asia/Tokyo`）[Q1] [F3]。
- **FR1.2** 選んだタイムゾーンは、言語と同じく、サーバー側の利用者の設定として内部DB に保存する。「ブラウザに合わせる」は値が無い状態として保存する [F2]。
- **FR1.3** サーバーは、保存の要求のタイムゾーンを IANA の名前として照らし、知らない名前は既存の入力の誤り（`VALIDATION_FAILED`）で拒否して保存しない [F2]。
- **FR1.4** 保存の後は、画面を読み込み直さなくても、表示中の画面の時刻が新しいタイムゾーンで出る（言語の変更と同じ扱い）[Q1]。
- **FR1.5** 効いているタイムゾーン（以下「表示のタイムゾーン」）は、設定があればその値、無ければブラウザのタイムゾーンとする [Q1] [F3]。

### FR2 業務データの日時の表示

- **FR2.1** 時点を表す型（PostgreSQL の `timestamptz`、MySQL・MariaDB の `timestamp`）の値は、一覧・詳細・参照の選択肢と表示名で、表示のタイムゾーンに直して見せる [Q1] [Q2]。
- **FR2.2** FR2.1 で直した値には時差（例: `+09:00`）を添える [Q4]。
- **FR2.3** 時差を持たない型（MySQL・MariaDB の `datetime`・`date`・`time`、PostgreSQL の `timestamp`・`date`・`time`）は、DB の値のまま見せ、時差を添えない [Q2] [Q4]。
- **FR2.4** 日付を持たない時差つきの型（PostgreSQL の `timetz`）は、変換せずに DB の値と時差のまま見せる [assumption]（日付が無く、表示のタイムゾーンに直すと夏時間の地域で一意に決まらないため）。
- **FR2.5** 秒の端数は、DB の値の桁のまま見せ、表示で丸めない（K-98）[Q5]。

### FR3 業務データの日時の入力と検索

- **FR3.1** 作成・更新の画面で、時点を表す型の値は表示のタイムゾーンで入れる。画面はサーバーへ時差つきで送り、サーバーは時点として保存する [Q3]。
- **FR3.2** 検索の条件の時点を表す型の値（範囲を含む）も、表示のタイムゾーンで入れ、同じく時差つきで送る [Q3]。
- **FR3.3** 読んだ値を変えずに更新へ送ったとき、時点を表す型の値は対象DB の中で変わらない（往復）。変えていない値は、画面で「変えた」と扱わない [Q3]（`team.md` Testing Posture の往復）。
- **FR3.4** 表示のタイムゾーンの夏時間の切り替わりで存在しない時刻を入れたときは、画面とサーバーの両方で、どの項目かを示す入力の誤りとして拒否する。重なる時刻（同じ時刻が2回ある）の扱いは設計の段で決め、決めた側の動作を明示したテストにする [assumption]（`team.md` Testing Posture の夏時間の項目）。
- **FR3.5** 時差を持たない型の入力と検索は、今どおり DB の値のまま扱う [Q2]。
- **FR3.6** 入力の欄の「UTC で入れる」の案内は、時点を表す型では表示のタイムゾーンを示す案内に替える [Q3] [Q4]。

### FR4 業務データの外の画面の時刻

- **FR4.1** 利用者の一覧・招待の一覧・DSL の状態と履歴など、今ブラウザのタイムゾーンで時刻を見せている画面も、表示のタイムゾーンで見せる [F1]。
- **FR4.2** 変換は画面の側の1か所（`src/shared/format/`）に閉じ、各画面はその部品だけを使う（`team.md` Code Style）。

### FR5 対象DB の接続のタイムゾーン

- **FR5.1** PostgreSQL の対象DB の接続にも、MySQL・MariaDB と同じく、セッションのタイムゾーンを UTC に明示に設定する（読み取りと書き込みの両方の接続）。JVM の既定のタイムゾーンに頼らない（K-95）。
- **FR5.2** FR5.1 の変更で、時差を持たない型の読み書きの値が変わらないことを、3種類の対象DB の結合テストで確かめる。

### FR6 日時の型の不具合の確かめと直し（K-98）

- **FR6.1** 既定の DSL の生成で、MySQL・MariaDB の日時の秒の端数の上限が 0 になるかを確かめ、そうなら DB の定義の桁に合わせて直す [Q5]。
- **FR6.2** 手書きの DSL の `timestamp(n) with time zone`（桁つきの時差つきの型）が時差を持たない型として扱われるかを確かめ、そうなら時点を表す型として扱うよう直す [Q5]。
- **FR6.3** FR6.1・FR6.2 は、確かめた結果（不具合だったか）と直したかを Build and Test で記録する。

### FR7 ホームの画面

- **FR7.1** ホームに、今の作業ロールを出す [Q6]。
- **FR7.2** ホームに、業務メニューの最上位の項目を入口のカードとして並べる。カードを押すと、その項目の画面（またはその子の最初の画面）へ移る。名前とアイコンはサイドバーと同じ規則で決める [Q6]。
- **FR7.3** 管理の権限を持つ利用者には、管理の画面（利用者・招待・グループ・ロール・ロールの受け渡し・DSL など、サイドバーの管理の区画と同じもの）の入口も並べる。権限の無い利用者には出さない（判定はサーバーの応答に従い、画面で権限を足さない）[Q6]。
- **FR7.4** 業務メニューが無いとき・読み込みに失敗したときの今の案内（`home.notConfigured`・`home.noRole`・`home.nothingVisible`・`home.loadError`）は残す [Q6]。
- **FR7.5** ホームは、対象DB への新しい問い合わせ（行の数など）をしない [Q6]。

### FR8 管理の仮の画面の廃止

- **FR8.1** サイドバーの「管理」の項目と、管理の仮の画面（`frontend/src/features/admin`）を外す [Q7]。
- **FR8.2** 外した画面の道を開いたときは、今の「見つからない」画面を見せる [assumption]（ほかの存在しない道と同じ扱いにし、特別な移し先を作らないため）。
- **FR8.3** サーバー側の管理の権限の確認の API と 403 の判定は残す（k6 と E2E が使う。K-104）。
- **FR8.4** 仮の画面で確かめていた検査（E2E 030・090・130 の 403 の表示・アクセシビリティ・確認の API）は、別の画面か別のテストへ移して残し、移す前と後の件数を Build and Test で記録する（`team.md` Testing Posture）。

### FR9 アプリのアイコン

- **FR9.1** 鍛冶の金床・ハンマーを図案にしたアプリのアイコンを、自作の SVG で作る [Q8]。図柄の細部は画面イメージの段で案を見て決める。
- **FR9.2** ブラウザのタブに favicon を出す（SVG の favicon と、SVG を読めないブラウザのための `.ico` か `.png`）[Q9]。
- **FR9.3** ログインの画面にアプリのアイコンを出す [Q9]。
- **FR9.4** 画面の枠（上のバー）には、make-you-chic-ui にロゴを置く口を依頼し、取り込めたら出す。取り込めるまでは出さない [Q9]。
- **FR9.5** `/favicon.ico` の要求に、HTML ではなく画像を返す（K-102）[assumption]（ブラウザが既定でこの道を読むため）。

### FR10 管理メニューのアイコン

- **FR10.1** 管理の区画の各項目に、項目ごとに違うアイコンを付ける [desc]。どのアイコンにするかは画面イメージの段で決める。
- **FR10.2** make-you-chic-ui に無いアイコンは、画面イメージの段で一覧にして上流へ依頼し、取り込んだ後に付ける。取り込むまでは今の既定のアイコンのままにする（`team.md` Way of Working）。

### FR11 業務メニューのアイコン

- **FR11.1** 業務メニューの項目のアイコンは、DSL の `icon` があればそれを使う（今どおり。許す名前の一覧で照らす）[Q10]。
- **FR11.2** DSL の `icon` が無いときは、項目の種類で既定のアイコンを変える: テーブル、ビュー、子を持つ項目（フォルダ）の3つ [Q10]。
- **FR11.3** メニューの応答に、項目がテーブルかビューかの印を足す（K-101）。既存の項目は変えず、足すだけにする [Q10]。
- **FR11.4** 許すアイコンの名前の一覧（画面の側とサーバーの側の2か所。K-100）は、make-you-chic-ui の固定先のアイコンとそろえる。

## 3. 非機能要件

- **NFR1 セキュリティ**
  - **NFR1.1** 自作の SVG に、スクリプト・イベントの属性・外部の参照を入れない（`project.md` Forbidden）。SVG の先頭にライセンスヘッダーを置き、検査の対象に `.svg` を足す（`team.md` Code Style）。
  - **NFR1.2** 表示のタイムゾーンの設定は、本人だけが自分の分を変えられる。要求の本文で他人の設定を変えられない（一括代入の防止。既存の `/api/me` の扱いと同じ）。
  - **NFR1.3** メニューの応答に足すテーブルかビューかの印は、その利用者が見られる項目にだけ付け、見られない項目の存在を明かさない（今のメニューの出し分けのまま）。
- **NFR2 性能**
  - **NFR2.1** 日時の変換で、業務データの API の対象DB・内部DB への問い合わせの数を増やさない。今の性能の目標（読み取りの p95 など）を変えない。
  - **NFR2.2** ホームは、今のメニューの API と作業ロールの API のほかに、新しい API を呼ばない（FR7.5）。
- **NFR3 アクセシビリティ**
  - **NFR3.1** ホーム・プリファレンス・業務データの一覧・詳細・入力の画面とログインの画面で、WCAG 2.1 AA を満たし、実際のブラウザの axe で違反 0 件とする。ブランドカラーとテーマのすべての組で確かめる（`team.md` の決まり）。
  - **NFR3.2** アイコンは飾りとして読み上げから外すか、意味を持つときは名前を付ける。アイコンの見分けだけで情報を伝えない（テーブルとビューの違いは名前や説明でも分かる）。
  - **NFR3.3** タイムゾーンの選択は、キーボードだけで選べ、選んだ値が読み上げられる。
- **NFR4 互換と戻し**
  - **NFR4.1** 内部DB の変更は、利用者の表に列を1つ足すだけにする（前進のみ）。前の版のアプリは足した列を読まずにそのまま動く（`team.md` Deployment）。
  - **NFR4.2** メニューの応答の変更は項目を足すだけにし、前の版の画面が読んでも壊れない。
- **NFR5 テスト**
  - **NFR5.1** 日時の変換のテストは `team.md` Testing Posture の必須の一覧（3種類の対象DB と型、日付の変わり目、夏時間と端数の時差、秒の端数、範囲の端、往復、性質ベースのテスト）に従う。表示のタイムゾーンを利用者が選べるため、夏時間の地域の確かめは変換の部品の単体テストに限らず、画面を通した形でも行う（★の解決）。
  - **NFR5.2** テストのタイムゾーンは固定し、別の時差を確かめるテストはその時差を明示に指定する。
  - **NFR5.3** 足す E2E は N6 の日時の代表の流れ1本まで。画面の仕上げは既存の E2E の書き換えと axe で確かめる。
- **NFR6 言語**
  - **NFR6.1** 足す画面の文言（ホームのカード・タイムゾーンの選択・案内）は日本語と英語の両方を用意する。タイムゾーンは IANA の名前と今の時差で示す（例: `Asia/Tokyo (+09:00)`）。

## 4. 制約

- 変換はサーバー側（`ColumnValueCodec`）と画面の側（`src/shared/format/`）の各1か所に閉じ、JVM・ブラウザの既定のタイムゾーンを暗に使わない（`team.md` Code Style）。
- アイコンは make-you-chic-ui の `Icon` の登録の名前だけを使う。無いものは上流へ依頼する。`vendor/make-you-chic-ui` は直接変えない（`project.md` Forbidden）。
- 実行時のタイムゾーンの設定（Dockerfile・compose・テストの JVM・E2E の起動）を変えるときは4か所をそろえる（`team.md` Deployment）。この Intent では変えない見込み。
- 統合の前の E2E の要否は、`frontend/index.html`・`frontend/public/` を含めた「frontend の本体」の決まりで決める（`team.md` Way of Working）。

## 5. 前提

| # | 前提 | 理由 |
|---|---|---|
| A1 | `timetz` は変換しない（FR2.4） | 日付が無く、夏時間のある地域で一意に直せないため |
| A2 | 夏時間で存在しない時刻の入力は拒否する（FR3.4） | 黙ってずらすと、利用者の意図と違う時点を保存するため |
| A3 | 廃止した管理の画面の道は「見つからない」画面にする（FR8.2） | ほかの存在しない道と同じ扱いにし、移し先の決まりを増やさないため |
| A4 | `/favicon.ico` には画像を返す（FR9.5） | ブラウザが既定で読む道で、今は HTML が返る見込みのため（K-102、未検証） |
| A5 | 管理者が他人の表示のタイムゾーンを変える操作は作らない | 依頼に無く、表示の設定は本人のものだから |
| A6 | 監査の行・ログ・内部DB の時刻は今どおり UTC で保存し、表示だけを変える | 保存の形を変えると、過去の行と前の版との互換が崩れるため |
| A7 | サーバーが作るメールの本文の時刻（招待の期限など）は、この Intent では変えない | 依頼の範囲が画面の表示で、メールは受け手の設定を前提にできないため |

## 6. 範囲の外

- 時差を持たない型の変換（Q2: A）と、DSL のカラムごとの変換の指定（Q2 の C）。
- ホームの行の数などの集計（Q6 の B）。
- 決めた少数のタイムゾーンの一覧（F3 の B）。
- 管理の画面の入口を並べるページ（Q7 の B）。
- アイコンの図柄を DSL の生成で書き込むこと（Q10 の C）。
- メールの本文の時刻の変換（A7）。

## 7. 未解決の点（後の段で決める）

- K-95（PostgreSQL のセッションの時差）と K-98（秒の端数・型の名前）は未検証。NFR 設計か Code Generation の前の捨ての試しで確かめる。
- 夏時間の重なる時刻の扱い（FR3.4）は設計の段で決める。
- アイコンの図柄と、管理・業務メニューのアイコンの割り当ては画面イメージの段で決め、make-you-chic-ui への依頼（アイコンとロゴの口）の文面を置く。上流の対応の時期は分からない。
- ホームのカードの配置・子を持つ最上位の項目を押したときの移り先（FR7.2）は画面イメージ・機能設計で決める。
