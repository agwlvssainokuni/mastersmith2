## 単位をまたぐもの（横断）

- **アクセシビリティ（US5.2）**: 各画面の axe は、画面を持つ単位（U2・U4・U5・U6）が、それぞれの画面で流す。ブランドカラーとテーマのすべての組・誤りの状態・長い名前で行う。
- **互換と戻し（US5.3）**: 足す変更は、前進のみ（列を足す・応答に項目を足す）で、前の版が読まずに動く。戻しはイメージだけ。
- **要件との差（ADR-002）**: 夏時間で存在しない時刻の拒否は画面の側だけ（U4）。サーバー側（U3・U2）には、拒否を足さない（時差の無い値・読めない値は拒否）。
- **上流への依頼（`make-you-chic-ui-request-8.md`）**: アイコン6つとロゴの口。使う単位は U5。取り込みは、使う Bolt の前に固定先の更新の専用のコミットで行う。

## 単位の中のストーリーの順（単位の中で作る順の目安）

- U1: 時点の表示 → ローカル時刻から時点（夏時間の判定）→ 名前の解釈 → 元の時点の往復
- U2: 設定の列と名前の照合（US1.1 の API）→ プリファレンスの選択（US1.1 の画面）→ 表示のタイムゾーンの配布（US1.2）→ 管理の画面の時刻（US1.2）
- U3: PostgreSQL の接続の時差（US5.1・AC2.2.4）→ 型と端数の確かめ（US5.1）→ 不具合なら直し → 往復（US2.5 のサーバー側）
- U4: 一覧・詳細の表示（US2.1・US2.2）→ 作成・更新の入力（US2.3）→ 往復（US2.5）→ 検索（US2.4）→ axe（US5.2）
- U5: メニューの応答の印（US4.4）→ アイコンの決め方（US4.3・US4.4）→ ホーム（US3.1・US3.2）→ 管理の仮の画面の廃止（US3.3）→ ロゴ（US4.2、取り込み後）
- U6: SVG とヘッダーの検査（US4.1）→ favicon と `/favicon.ico`（US4.1）→ ログインのアイコン（US4.1）

## 直しの記録（Functional Design で見つけ、依頼者の決定で直した）

「関わる単位」の列の複数の単位の区切りを、中黒（`・`）から `;` に直した（US2.1・US2.5・US5.2・US5.3 の4行）。元の状態: `U1・U3` のように中黒で区切っていたため、網羅の道具（`aidlc engine sensor-traceability`）が複数の単位を読まず、U1 などの「関わる単位」の側で、受け入れ基準の網羅の表が足りなかった（U1 は 29 件のうち 17 件）。中身（どの単位が関わるか）は変えていない。見つけたのは U1 の Functional Design の網羅の表を作ったとき。

## 網羅の確かめ

ストーリー17件はすべて、主の単位を1つ持つ。単位ごとの主のストーリーは、U1 が0件（関わる単位としてのみ）、U2 が3件（US1.1・US1.2・US5.3）、U3 が1件（US5.1）、U4 が6件（US2.1〜US2.5・US5.2）、U5 が6件（US3.1〜US3.3・US4.2〜US4.4）、U6 が1件（US4.1）。U1 は主のストーリーを持たない純粋な変換の単位（library）で、関わる単位として US1.2・US2.1・US2.3・US2.4・US2.5 に出る。
