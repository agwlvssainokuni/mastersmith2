# ペルソナ — timezone-ui-polish

出典: `aidlc/spaces/default/intents/261102-timezone-ui-polish/inception/requirements-analysis/requirements.md` の依頼の分析と FR1・FR7・FR9、ストーリーの質問 Q1（ペルソナは3人。前の Intent 261016-business-data-views の P1〜P3 を引き継ぎ、今回の目的を足す）、前の Intent のペルソナ（`aidlc/spaces/default/intents/261016-business-data-views/inception/user-stories/personas.md`）。

## P1 業務データを見る人（田中さん）

- **役割**: MasterSmith の画面で業務データを調べる利用者。管理者の印は持たない。作業ロールでは、扱うテーブルの主権限が READ。前の Intent の P1 を引き継ぐ。
- **目的（前の Intent から）**: メニューからテーブルを選び、条件で絞り、行の詳細を読みやすい形で確かめる。
- **目的（今回、足す）**:
  - 日時（受注の時刻・更新の時刻など）を、自分の使うタイムゾーン（日本時間など）で読みたい。UTC のままだと、日付が1日ずれて見えて読み違える
  - 見ている時刻がどのタイムゾーンのものか、画面で分かってほしい（時差が添えてあること）
  - ほかの画面（利用者の一覧・DSL の履歴など）の時刻と、業務データの時刻を見比べても、時差が食い違わないでほしい
  - ログインした直後に、今の作業ロールと、次に開く業務メニューの入口が分かるホームを見たい
  - メニューのアイコンで、テーブル・ビュー・フォルダを見分けたい
- **困りごと（今）**:
  - 時差つきの日時が UTC のまま出て、ほかの画面（ブラウザのタイムゾーン）と9時間ずれて見える（コード知識ベースの所見 K-96）
  - ホームに何も無く、最初にどこを開けばよいか分からない
  - メニューの項目がどれも同じアイコンで見分けにくい
- **技術への慣れ**: 低〜中（タイムゾーンの名前は知らず、「日本時間」と分かればよい）
- **アクセシビリティ**: キーボードだけで操作する人、読み上げを使う人もいる
- **使う頻度**: 毎日
- **言語**: 日本語または英語

## P2 業務データを直す人（鈴木さん）

- **役割**: マスタの値を登録・修正・削除する担当者。管理者の印は持たない。作業ロールでは、受け持つテーブルが FULL で CREATE・DELETE が可。前の Intent の P2 を引き継ぐ。
- **目的（前の Intent から）**: 行の値を直し、新しい行を登録し、要らない行を消す。誤りはその場で教えてもらう。
- **目的（今回、足す）**:
  - 日時の値を、自分のタイムゾーンで入れたい。UTC に頭の中で直して入れるのは間違えやすい
  - 日時を変えずに別のカラムだけを直したとき、日時が黙ってずれて保存されないでほしい（往復）
  - 夏時間のある地域のタイムゾーンを選んだとき、存在しない時刻を入れたら理由が分かってほしい。重なる時刻は、保存した時点がずれないでほしい
  - 日時で行を探すとき、検索の条件も、同じタイムゾーンで入れたい
  - プリファレンスの画面で、使うタイムゾーンを選びたい（既定は「ブラウザに合わせる」）
- **困りごと（今）**:
  - 日時の入力が UTC で、日本時間の感覚と食い違い、入れ間違える（所見 K-96）
  - 別のカラムを直しただけなのに日時が変わらないか、不安になる
- **技術への慣れ**: 中（表の操作は慣れているが、DB の型や時差の仕組みは分からない）
- **アクセシビリティ**: キーボードだけで操作する人、読み上げを使う人もいる
- **使う頻度**: 毎日（月末などに多い）
- **言語**: 日本語が主

## P3 管理者（佐藤さん）

- **役割**: 前の Intent の P3 を引き継ぐ。MasterSmith の管理画面で、利用者・招待・グループ・ロール・DSL を受け持つ（管理者の印を持つ利用者）。
- **目的（前の Intent から）**: 権限と DSL の設定が、業務データの画面で期待どおりに効いていることを確かめる。
- **目的（今回、足す）**:
  - ホームから、管理の画面（利用者・招待・グループ・ロール・ロールの受け渡し・DSL など）へ入りたい
  - 役割の無い管理の仮の画面（ログイン後に見える「管理」の項目）が無くなり、サイドバーの管理の区画が項目ごとに見分けられるようにしたい
  - 利用者の一覧・招待の一覧・DSL の履歴の時刻も、自分が選んだタイムゾーンで読みたい
  - 管理の画面の403の表示とアクセシビリティの確かめが、仮の画面を無くしても別の画面で残っていてほしい
- **困りごと（今）**:
  - 管理の仮の画面は、権限の確認以外に役割が無く、サイドバーの項目が増えて迷う（所見 K-104）
  - 管理メニューの項目が、どれも同じアイコンで見分けにくい
- **技術への慣れ**: 中（YAML は読めるが、DB は直接触りたくない）
- **アクセシビリティ**: キーボードや読み上げを使う管理者もいる
- **使う頻度**: 週に数回
- **言語**: 日本語が主。英語の画面も使うことがある

## ペルソナの関係と優先度

1. **P1 業務データを見る人**（最優先）: 日時を読む・ホームから入る・メニューを見分ける、が最も多い。
2. **P2 業務データを直す人**: 日時の入力・検索・往復は、読む機能の上に乗る。
3. **P3 管理者**: 管理の入口と仮の画面の廃止・メニューのアイコン。設定そのものは前の Intent までの機能で行う。

同じ人が作業ロールを切り替えると、P1 にも P2 にもなる。管理者の印を持つ人は P3 でもあり、業務データでは作業ロールの権限で見え方が決まる。
