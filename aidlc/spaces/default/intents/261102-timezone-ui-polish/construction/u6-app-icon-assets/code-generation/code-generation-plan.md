# コード生成の計画 — u6-app-icon-assets

## Summary

- Builds: アプリのアイコン・favicon の自作の素材（`frontend/public/` の SVG 2 つと `.ico` 1 つ）、`index.html` の favicon の `<link>`、ログイン画面のアプリ名の上の飾りのアイコン（`src/shared/` の React 部品）、素材を守る検査（`.svg` のライセンスヘッダー、SVG の中身の許可リスト検査、`dist`・WAR に素材が入ったことの検査、`/favicon.ico` の配信の結合テスト）、`.ico` を作る手順の記録。新しい依存・API・表・列・環境変数・サーバーの道は足さない
- Touches: `frontend/public/`（新規）・`frontend/index.html`・`frontend/scripts/`（`check-license-header.mjs` に手を入れ、`check-svg-safety.mjs`・`check-dist-assets.mjs`・`icon-binary.mjs`・`make-ico.mjs` を足す）・`frontend/package.json`（scripts だけ）・`frontend/src/shared/app-icon/`（新規）・`frontend/src/app/layout/LoginLayout.*`・`frontend/e2e/050-display-accessibility.e2e.ts`・ルートの `build.gradle.kts` と `backend/build.gradle.kts`（検査のタスク）・`backend/src/test/`（見本の素材と結合テスト 1 つ）・`docs/app-icon.md`（新規）・`docs/verification.md`・`README.md`（各 1 か所）
- Tests: Vitest 約 60 件（検査の表の行を含めると約 150 ケース。性質ベース 5 件、別のパーサーとの突き合わせ 3 件を含む）、Spring の結合テスト 3 件、E2E は流れを足さず既存の 2 つのテストに書き足す（本数に数えない）

出典: NFR Requirements（`construction/u6-app-icon-assets/nfr-requirements/security-requirements.md` の NFR1.1.1〜NFR1.1.6・NFR2.1.1・NFR3.1.1・NFR3.2.1・NFR5.3.1、`tech-stack-decisions.md`）、NFR Design（`nfr-design/security-design.md` の SD1〜SD7）、Infrastructure Design（`infrastructure-design/cicd-pipeline.md` の 2節の関門と 4節の引き継ぎ H1〜H11）、各段のレビュー（`reviews/review-01.md`）、要件（FR9.1〜FR9.3・FR9.5）、ストーリー（US4.1 の AC4.1.1〜AC4.1.6、US5.2 のログイン）、設計の決定（ADR-008）。この単位には functional-spec・rules が無い（素材と検査だけの単位）。

## 方針

- 方法は test-after（`team.md` Testing Posture）。層（配信の仕組みの確かめ → ライセンスヘッダーの検査 → SVG の中身の検査 → `.ico` の道具 → 素材 → `dist`・WAR の検査と Gradle への組み込み → ログイン画面の部品 → E2E）ごとに実装を書き、同じ Bolt の中でその層のテストを書いて実行し、通ってから次の層へ進む。ただし配信の仕組み（`/favicon.ico` が未認証で画像として返るか）は、設計が「サーバーの変更なし」を前提にしているため、素材を作る前に先に流して確かめる（H7。Step 2・3）。
- サーバー（`backend/src/main`）は変えない。`SecurityConfig`・`WebConfig`・`CacheControlFilter`・`application.yaml` の変更が要る結果が Step 3 で出たら、そこで止めて依頼者に諮る（ADR-008 の前提が崩れるため）。したがって `packagesJudgedByTotal`（7 パッケージ）にも手を入れず、バックエンドのカバレッジの値は変わらない。
- 新しい依存を足さない。`frontend/package.json` は `scripts` に `svg:check`・`dist:check` を足すだけ（`dependencies`・`devDependencies` は不変）、`frontend/package-lock.json`・`backend/gradle.lockfile`・`config/npm-build-tools.txt`・`.github/workflows/ci.yml`・Dockerfile・compose・`db/migration`・実行時のタイムゾーンの設定の 4 か所は変えない（Step 18 で差分を確かめる）。
- 検査のスクリプトは Node の標準の機能だけで書く（XML のパーサーを足さない。SD1.1）。純粋な関数にして export し、CLI の本体は `main()` を実行時の判定で守る（既存の `check-license-header.mjs` と同じ形）。スクリプトと、スクリプトを読む Vitest のテストの先頭には `/* ... */` の Apache License 2.0 ヘッダーを置く。
- 測れる目標（SVG 4096 文字・`.ico` 32 KiB・`.png` 16 KiB・ログイン画面にアイコンのための HTTP 要求を足さない）と axe の違反 0 件は緩めない。axe の規則を外す・`exclude` する・`KNOWN_VIOLATIONS` に足す形で通さない（`project.md` Forbidden）。外れたときは図柄を簡単にし、足りなければ依頼者に諮る（D-P10）。

### この計画で決めたこと（承認の場で変えてよい）

- **D-P1 素材の点数（H4）**: `frontend/public/` に置くのは次の **3 ファイルだけ**。
  - `favicon.svg`: 固定の 1 色（D-P3）の favicon。
  - `favicon.ico`: 16・32・48 px の PNG を詰めた ICO。SVG を読めないブラウザと、ブラウザが既定で読む `/favicon.ico` 用（AC4.1.1・AC4.1.3）。
  - `app-icon.svg`: `fill="currentColor"` の元の図。ログイン画面の部品の図柄の元（`d` の一致の確かめの正本）で、上のバーのロゴ（別の単位）も同じ図を使う。
  - `apple-touch-icon.png`（180 px）・192/512 px の PNG は **採らない**。理由: FR9.2 は「SVG の favicon と、SVG を読めないブラウザのための `.ico` か `.png`」で、`.ico` で満たす。iOS のホーム画面への追加と Web アプリのマニフェストは要件になく（マニフェストを置かない）、使われない `.png` が `public/` に増えると公開される素材と検査の対象が増える。必要になったとき、`public/` の名前の一覧（Vitest の素材のテスト 1 か所）と `docs/app-icon.md` に足せば済む（Gradle には名前を書かない設計のため）。`.png` の大きさの上限（16 KiB）の検査の部品は、ICO の中の PNG にも使うため残る。
- **D-P2 図柄とデザインの方針**: 鍛冶の金床とハンマーを、**直線だけの単純な幾何図形で描いた塗りつぶしの 1 色のシルエット**にする（`viewBox="0 0 64 64"`、`path` の命令は `M`・`L`・`H`・`V`・`Z` と数字だけ、曲線・線の描画（`stroke`）・グラデーション・影は使わない）。16 px で潰れないよう、細い線ではなく面で描き、金床（角・台座）とハンマー（頭・柄）の 2 つの `path` に分ける。背景は透明。理由: 輪郭線の細さは 16 px の favicon で読めなくなる。ヘッダー（約 590 文字）を除いた図柄は 3000 文字以内、できれば 1500 文字以内に収める（D-P10）。
- **D-P3 色**: `app-icon.svg` と部品は `fill="currentColor"`（周りの文字の色。ログイン画面ではアプリ名と同じ `var(--color-text-muted)`）。`favicon.svg`・`favicon.ico` は固定の 1 色 `#2563eb`（既定のブランドカラー blue に近い中間の青。明るいタブにも暗いタブにも見える中間の明るさ）。favicon は利用者ごとのブランドカラー・テーマを知らないため固定にする。ダークテーマ用の切り替え（`<style>`・`prefers-color-scheme`）は許可リストを広げるため行わない（H10）。要るときは依頼者に諮る。
- **D-P4 `index.html` の `<link>`（レビューの R-01）**: `<head>` に 2 本足す。`<link rel="icon" href="/favicon.ico" sizes="32x32" />`（先）と `<link rel="icon" href="/favicon.svg" type="image/svg+xml" />`（後）。`href` は `dist` のルートからの絶対パスで外部の URL を指さない。順序は、素材を置いた後（Step 10）・`dist:check` を有効にする前（Step 14）。ブラウザごとの優先の見え方は配備の後のスモークテスト（S5）で依頼者が確かめる（Chromium 系以外は未確認）。
- **D-P5 検査の道具の置き場と名前**: `frontend/scripts/` に `check-svg-safety.mjs`（SD1。`checkSvgContent(content, { standalone })` と、検査の対象を集める関数、CLI）、`check-dist-assets.mjs`（L2。`dist:check`）、`icon-binary.mjs`（PNG・ICO の形の確かめと ICO を詰める純粋な関数）、`make-ico.mjs`（手で流す道具の CLI。ビルドに組み込まない）を置く。`check-license-header.mjs` からは `collectFiles` と `SKIP_DIRS` を export し、`check-svg-safety.mjs` が import する（範囲を 2 か所に写さない。H3）。テストは `src/` の下に置く（Vitest の `unit` プロジェクトが `src/**/*.test.{ts,tsx}` だけを対象にするため）。`.mjs` は既存の `src/perfEvidenceRedactor.test.ts` と同じ、動的な `import()` と手書きの型で読む。`frontend/scripts/` はカバレッジの計測の対象（`vitest.config.ts` の `coverage.include`）に入っておらず、入れない（除外を増やす・下限を逃れる形にしない）。
- **D-P6 手順の記録の置き場（H1・H11・AC4.1.6）**: 新しい `docs/app-icon.md` に、素材の一覧と役割、`.ico` を作る道具の名前・版（`rsvg-convert` 2.63.4、Node の版）・コマンド・出力の大きさ、別の PC で作るときの代わりの道具、「SVG を変えたらバイナリを作り直す」（機械では確かめない。コード生成のレビューで目で確かめる）を書く。`README.md` の `docs/` の表に 1 行（`docs/app-icon.md`）を足す。`docs/verification.md` の検査の段の表（3・4・9）の説明を、足す検査に合わせて書き換える。README と `docs/verification.md` はこのリポジトリの既存の文書のため、変えるのはこの 1 行・3 行だけで、承認の場で確かめる（下の 3・4）。
- **D-P7 ログイン画面の部品（レビューの R-02・SD5）**: `frontend/src/shared/app-icon/AppIcon.tsx`（名前付きのエクスポート）。props は大きさ（`size`、数）だけで、`d`・色・`className` を受けない。JSX の `<svg>` に許可リストの属性（`viewBox`・`width`・`height`・`fill="currentColor"`・`aria-hidden="true"`・`focusable="false"`）と、ソースに書いた固定の `path` だけを置く。`dangerouslySetInnerHTML`・`title`・`aria-label`・`className`・`style`・`data-*` を付けない。図柄の `d` を export する定数 `APP_ICON_PATHS` に置き、`public/app-icon.svg` の `d` の一覧と一致することをテストで確かめる。`data-testid` は SVG には付けられない（許可リストに `data-*` が無い）ため、`LoginLayout` の中の包み（`<div className="login-layout-app-icon" data-testid="login-layout-app-icon">`）に付ける。包みはアプリ名の `<p>` の直前に置く。
- **D-P8 E2E の置き場（H9・SD4.2 の L4）**: 新しい流れ・新しい `test()` は足さず、`050-display-accessibility.e2e.ts` の既存の 2 つのテストに書き足す。①「login screen（組ごと）」にアイコンの包みが見えること・その中の `svg` が `aria-hidden="true"` であること・`getByRole('img')` が 0 件であることを足す（axe・はみ出しの検査は既存のまま。ブランドカラーとテーマのすべての組で違反 0 件）。②「first screen time ...」の `run === 1` に、`context.request` で `/favicon.ico`・`/favicon.svg` を未認証で読む検査（状態 200・`image/` で始まる種類（SVG は `image/svg+xml`）・本文が HTML でない・ICO は先頭 4 バイトが `00 00 01 00`・`X-Content-Type-Options: nosniff`）と、`<head>` の `link[rel="icon"]` が 2 本で `href` が外部を指さないことを足す。010〜040 は変えない。
- **D-P9 L1 の結合テスト（H7・SD4.2 の L1）**: `backend/src/test/java/cherry/mastersmith/config/StaticIconAssetsIT.java`（`SecurityHeadersIT` と同じ形・同じ設定）。`backend/src/test/resources/static/` に、小さな見本の `favicon.ico`（Node の短い書き込みで作る最小の ICO。1×1 の PNG を 1 枚持つ。画像として表示される必要はない）と `favicon.svg`（ライセンスヘッダー付きの最小の SVG）を足す。確かめは 3 件: ① `/favicon.ico` を未認証で読む（200・`Content-Type` が `image/` で始まる・本文が `<!doctype html` で始まらない・`X-Content-Type-Options: nosniff`・`Cache-Control: no-cache`。`Content-Type` の実際の値を出力に残す）、② `/favicon.svg`（200・`image/svg+xml`・同上）、③ 素材が無い道（例 `/missing-icon.ico`）が `index.html`（`text/html`）に落ちること（検査 L2・L3 が要る理由を、動くテストで記録する）。
- **D-P10 SVG の上限を超えそうなとき（H5・レビューの R-03）**: 図柄を描いたら、ヘッダー込みの文字数を `favicon.svg`・`app-icon.svg` の両方で測って記録する（Step 10）。4096 文字に収まらないときは、**上限を広げる前に図柄を簡単にし**（頂点の数を減らす・小数を整数にする）、それでも足りなければ依頼者に諮る。黙って上限を広げない。
- **D-P11 統合とコミットの区切り**: `develop` から短命のブランチ `feature/261102-timezone-ui-polish-b5`（Bolt B5）を作り、`develop` へ squash マージする（1 Bolt が `develop` の 1 コミット。メッセージは日本語。`team.md`）。統合の前に、監査ログを含む `aidlc/` の未コミットの変更をコミットしておく（`project.md`）。ブランチの中のコミットの区切りの案は、import の向きとビルドの順に合わせた次の 5 つ（コミットの可否は積む前に依頼者に尋ねる）: C1 配信の仕組みの結合テスト（Step 2・3）、C2 検査の道具とテスト（Step 4〜9・13 のスクリプト部分）、C3 素材・`index.html`・`docs/`・素材のテスト（Step 10〜12）、C4 Gradle への組み込み（Step 13 の npm スクリプトの組み込み・Step 14）、C5 ログイン画面の部品・E2E（Step 15・16）。`frontend/public/` を作る C3 は、`frontendBuild` の `inputs.dir(public)` を足す C4 より先にする。

### 承認の場で確かめたい点

推奨を先に書く。

1. **D-P1 素材の点数**: 推奨は **`favicon.svg`・`favicon.ico`・`app-icon.svg` の 3 つだけ**（`apple-touch-icon.png`・192/512 px の PNG は採らない。理由は D-P1）。iOS のホーム画面への追加まで見たいなら `apple-touch-icon.png`（180 px）を足す（バイナリと `<link>` が 1 つ増え、Step 10〜12 に数行足すだけ）。
2. **D-P2・D-P3 図柄と色**: 推奨は **直線の幾何図形の塗りつぶしのシルエット、favicon の色は `#2563eb`**。別の色・輪郭線の図柄にしたいときは、Step 10 の前に伝える（作り直しはバイナリの作り直しを伴う）。16 px での見え方は、Step 10 で 16・32・64 px に描いた画像を実装の担当が自分で見て確かめ、実際のタブでの見え方は配備の後のスモークテスト（S5）で依頼者が見る。
3. **README の表に `docs/app-icon.md` の 1 行を足す**: 推奨は足す（`docs/` の文書の一覧と合う）。足さない場合は `docs/app-icon.md` だけを置く（AC4.1.6 は「README か記録」で、どちらでも満たす）。
4. **`docs/verification.md` の表（3・4・9 の段）の説明を、足す検査に合わせて書き換える**: 推奨は書き換える（`verifyStages` の説明文と食い違えば、文書が古くなるため）。

## 手順

層ごとに「実装 → その層のテスト → 通ってから次へ」。コマンドは `unit-test-instructions.md` のとおり（長い実行は `caffeinate -dims` で包み、前後に `pmset -g log` でスリープの有無を確かめる）。

- [ ] Step 1: 準備の確かめ。`develop` から `feature/261102-timezone-ui-polish-b5` を作る。変更の前の状態で、`unit-test-instructions.md` の Vitest の絞り込みのコマンドが実行できる（`src/app/layout/LoginLayout.test.tsx` で確かめる）こと、`npm run format:check`・`npm run lint`・`npm run license:check` が通ること、`rsvg-convert --version`（2.63.4）と Node の版が使えること、`frontend/public/` が無いことを確かめ、影響の範囲の表の既存のテスト（`LoginLayout.test.tsx`・`LoginPage.test.tsx`・`LoginForm.test.tsx`・`App.test.tsx`）の通過を記録する（直しの前後を比べるため）。
- [ ] Step 2（層A 配信の仕組み L1・H7）: `backend/src/test/resources/static/` に見本の `favicon.ico`（D-P9。Node の短い書き込みで作り、手で編集しない）と `favicon.svg`（Apache License 2.0 のヘッダー付き）を足し、`StaticIconAssetsIT` を書く（D-P9 の 3 件）。ソースの先頭にヘッダー。サーバーのコードは変えない。
- [ ] Step 3: Step 2 のテストを**素材を作る前に**流す。通ったら、`.ico` の `Content-Type` の実際の値（`image/x-icon` か `image/vnd.microsoft.icon`）を `code-summary.md` に書く。**外れたとき（401・403、`image/` でない種類、`nosniff` なし）は、ここで止める**: `SecurityConfig`・`WebConfig` の変更になり ADR-008 の「サーバーの変更なし」が崩れるため（SD4.4）、原因を確かめて依頼者に諮ってから進める。「素材が無い道は `index.html` に落ちる」ことの件も通ること。
- [ ] Step 4（層B ライセンスヘッダー SD2・H3）: `frontend/scripts/check-license-header.mjs` の `HTML_EXTENSIONS` に `.svg` を足し（`<!--` 形のひな形、XML 宣言が先頭なら今の判定のまま失敗）、`collectFiles` と `SKIP_DIRS` を export する。`main()` の実行時の判定（`process.argv[1]`）は今のままで、import しても検査が走らないこと。冒頭のコメントの対象の説明に `.svg` を足す。
