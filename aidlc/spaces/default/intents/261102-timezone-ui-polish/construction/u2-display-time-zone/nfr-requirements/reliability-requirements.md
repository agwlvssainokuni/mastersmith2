## 2. E2E・テストへの影響（レビュー R-01 の取り込み。件数の洗い出しは Code Generation の計画）

| ID | 要件 | 確かめ方 |
|---|---|---|
| NFR4.1.6 | E2E の見本を新しい形にそろえる: `preferencesFixtures.ts` の `preferencesSample` に `displayTimeZone`（文字列か `null`）を足し、`hasPreferencesShape` の項目の一致と型の確かめに5つ目（文字列か `null`）を含める。本物の応答と見本の形の比べ（080 の測り）は5つ目を含めて行う。5つ目の無い見本を配布が読むと `error` になるため、**見本に5つ目が無いまま残る E2E を作らない**。5つ目の値の見本（名前・null・解釈できない名前）を、見本の部品から作る | 080 の形の比べが5項目で通ること。見本を使うすべての E2E（080・100・110 と、`GET /api/me/preferences` を差し替えるもの）が配布の読み取りで `error` にならない |
| NFR4.1.7 | 差し替えの回数の数え方: 080 と 100 は `GET /api/me/preferences` の差し替えをログインの前に置くため、ログインの後の配布の読み取りも差し替えに当たり、「配布の1回 + プリファレンスの画面の1回」を数える。`toBe(1)` のまま放置せず、**配布の読み取りを含めた期待の回数を名前つきの定数にして理由を書く**（具体の回数は Code Generation の計画で、差し替えを置く順を見て実測して決める）。110 は、利用停止の後にプリファレンスの画面を開いたときの 401 を待つ流れで、待つ対象が画面の読み取りか配布の読み直しかを確かめ、順序に依らず待てる形に直す。保存済みの名前を解釈できない状態・読み込み失敗の状態は、差し替えた応答で作る | 080・100・110 が通ること。差し替えの回数の期待が配布の読み取りを含めた根拠つきの値で、回数の不一致が原因で落ちないこと |
| NFR4.1.8 | 管理の画面（利用者・招待・DSL）と確認の表示の既存の単体テストを、`timeZone` の props を外す形（BR2.22）と、配布の提供元で時差を固定する形に直す。配布の提供元を差し込む共用のテストの手伝いを1つ作り、各テストが同じ入口を使う。管理の画面の時刻の期待は新しい書式（分までと数字の時差）に書き換える。書き換えは E2E の本数に数えない。書き換えるテストと E2E の件数は Build and Test に記録する | 画面のテストが全件通る。`formatDateTime`・`formatLockedUntil` の旧書式（`JST`・`GMT+9`）を期待する記述が残っていないこと（検索で 0 件） |

## 3. 画面の読み込みの失敗と回復（NFR4 に当たる行が無い追加。NFR4.3）

| ID | 要件 | 根拠・決まり | 確かめ方 |
|---|---|---|---|
| NFR4.3.1 | 設定の読み込みが失敗したとき（接続の失敗・サーバーの 5xx・形が違う応答）は、`error` にし、ブラウザのタイムゾーンへ落とさず、時刻の欄を出さず、短い文と、画面の上の1か所の再読み込みを出す。再読み込みの成功、またはプリファレンスの画面の読み込み・保存の成功で `ready` に戻る。すでに `ready` のときの読み直しの失敗は前の値を残す。401 は今の認証の失敗の扱い（更新→ログイン画面）に従い、`error` の画面で止まらない | BR2.14・BR2.15・AC1.2.5 | 画面の単体テスト: 失敗の3種類（接続の失敗・5xx・形の誤り）で `error`、再読み込みで `ready`、`ready` での読み直しの失敗で前の値が残ること。401 のときにログイン画面へ戻る既存の動作が変わらないこと |
| NFR4.3.2 | 古い答えの競り合いに強い: 要求の世代で比べ、遅れて届いた古い答え・ログアウトの後の答えは捨てる。待ち合わせは時間に預けず、決定的に作る（注入した取得の関数の解決の順を入れ替える）。`ready` の画面に遅れて届いた失敗の答えが、`ready` を `error` に落とさない | BR2.14・`team.md` Testing Posture（`waitFor`・時間に依存しない） | 画面の単体テスト: 取得の解決の順を入れ替えても、新しい世代の値が残ること。未ログインになった後の答えが値を作らないこと |
