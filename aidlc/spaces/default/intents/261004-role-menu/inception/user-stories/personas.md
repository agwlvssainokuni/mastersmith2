# ペルソナ — role-menu

出典: `aidlc/spaces/default/intents/261004-role-menu/inception/requirements-analysis/requirements.md` の 1節（利用者）、ストーリーの質問 Q1（ペルソナは2人。運用者・監査者は監査の受け入れ基準の中で扱う）、M2・M7・M8 の答えと、デザイナーの担当の意見（`contributions/aidlc-design-agent.md`）。統合で、P1 の目的と困りごとに当たる受け入れ基準を注記し、P2 の使い方を1行足した。

## P1 管理者（佐藤さん）

- **役割**: MasterSmith の管理画面で、利用者・DSL・権限の設定を受け持つ管理者（管理者の印を持つ利用者）。ほかの管理者は1〜2人いる。管理者でも、業務データの権限は自分の作業ロールで決まる（要件 C1・前提 A4）。
- **目的**:
  - 部署や仕事に合わせてロールを作り、どのテーブル・カラムを見られる・直せるかを、スキーマ→テーブル→カラムの順に大きく決めてから細かく上書きしたい
  - 人が増えても一人ずつ設定し直さずに済むよう、グループにロールを割り当てたい
  - 検証用の環境で整えた権限の設定を、本番の環境へそのまま持っていきたい
  - 権限を変えた後に、利用者のメニューが期待どおりに変わったかを確かめたい（権限の設定の画面で、テーブルごとに業務のメニューに出るかを見て確かめる。M7: A、AC1.2.16）
- **困りごと（今）**:
  - 権限は管理者の印だけで、業務データの見せ方を人ごと・部署ごとに分けられない（KB K-32）
  - 1 つのロールで最大 1 万カラムになりうる設定を、全部並べられると探せない（要件 NFR2.1）
  - 2〜3人の管理者が同じロールを同時に直すと、ほかの人の変更に気づけない（同時の保存は後勝ちとし、監査に両方の前後の値を残して後から分かるようにする。M2: A、AC1.2.12）
  - 誤ってロールやグループを消すと、利用者の仕事が止まる（割り当てやメンバーが残るものは消せず、残りの数が分かる。AC1.1.3・AC1.1.8・AC2.1.7）
- **技術への慣れ**: 中（YAML は読めるが、DB は直接触りたくない）
- **アクセシビリティ**: キーボードや読み上げを使う管理者もいる
- **使う頻度**: 週に数回。人の出入りや業務の変更のたび
- **言語**: 日本語が主。英語の画面も使うことがある

## P2 一般の利用者（田中さん）

- **役割**: MasterSmith の画面で業務データを扱う利用者。管理者の印は持たない。仕事に応じて複数のロール（例: 「営業」と「経理」）を割り当てられ、作業ロールを切り替えて使う。ロールが1つも無いこともある（入ったばかり・異動の途中）。1日に何度か作業ロールを切り替えることがある（例: 午前は「営業」、午後は「経理」）ため、どの画面からも今の作業ロールが見えて切り替えられるとよい。管理者がロールを外して作業ロールが変わったときに知らせる案内は無く、作業ロールの表示が変わるだけである（M8: B）。
- **目的**:
  - 今の仕事に合ったロールを選び、そのロールで見てよいものだけを見たい
  - 左のメニューから、扱う業務データの画面へ迷わずたどりたい
  - 自分が今どのテーブル・カラムを見られる・直せるのかを確かめたい（見えないときに、権限のせいか分かるように）
- **困りごと（今）**:
  - メニューが平らで、業務のまとまりで探せない（KB K-36）
  - 見えてはいけないものが出ていないか、出るはずのものがなぜ無いのかが分からない
- **技術への慣れ**: 低〜中
- **アクセシビリティ**: キーボードだけで操作する人、読み上げを使う人もいる
- **使う頻度**: 毎日
- **言語**: 日本語または英語

## ペルソナの関係と優先度

1. **P1 管理者**（最優先）: ロール・グループ・権限・割り当てを設定しないと、P2 の作業ロールもメニューの出し分けも意味を持たない。
2. **P2 一般の利用者**: P1 の設定の結果を受け、作業ロールを切り替え、メニューから移る。P1 も業務データを扱うときは P2 と同じ振る舞いになる。

運用者・監査者は立てず、ロール・権限・割り当て・import・作業ロールの切り替えが監査に残ることを、各ストーリーの受け入れ基準で扱う（Q1: A）。
