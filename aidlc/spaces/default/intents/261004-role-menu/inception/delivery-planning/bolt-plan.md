# Bolt の計画 — role-menu

Bolt は、作る1回ぶんのまとまり（終わると動くものができる作業）である。この計画は、承認済みの7つの単位（`aidlc/spaces/default/intents/261004-role-menu/inception/units-generation/unit-of-work.md`）を、どの順で、どの大きさの Bolt で作るかを決める。出典はこの段の答え（`delivery-planning-questions.md` の DQ1〜DQ6）。

## 前提

- 依頼者1名と AI で作る。Bolt ごとに `develop` から短命のブランチ（`feature/261004-role-menu-<bolt>`）を作り、`./gradlew verify` を通してから `develop` へ squash で戻す（`team.md`）。make-you-chic-ui の固定先の更新を含む B9 は、固定先の更新を専用のコミットに残すため fast-forward で戻してよい。
- 最初の Bolt の特別な手順（walking skeleton、全体を薄く通す最初の版）は行わない（`team.md`）。どの Bolt にも walking skeleton の印は付けない。
- 1つずつ順に作る（DQ4: A）。
- Construction は、設計の段（機能設計・NFR 要件・NFR 設計・基盤の設計）をすべての単位で通してから次の段へ進み、コード生成は最後に Bolt の順で行う（stage-major、DQ6: A）。U4 は設計の段では1つの単位として通し、コード生成の計画で B4〜B6 に分ける（`project.md`）。

## 各 Bolt

### B1 U2 dsl-v2

- **含む単位**: U2
- **walking skeleton**: いいえ
- **終わりの条件（Definition of Done）**:
  - 版 2 の DSL（スキーマの階層）を投入・プレビュー・適用・ダウンロードでき、版 1 は書式の版の誤り（4xx）になる（AC6.1.1〜AC6.1.2・AC6.1.9）。
  - 既定の DSL の生成が版 2 で、設定のスキーマ名を書く（AC6.1.3）。
  - メニューの深さの上限の境界（上限ちょうどは受け付け、超えると拒否）、起動時の読み直しでは深さだけ外して警告（AC5.2.1〜AC5.2.5）。
  - 版 1 の適用済みの環境で版を上げると DSL が無い扱いで起動し、版 1 の履歴の復元は 4xx（AC6.1.6・AC6.1.7）。
  - 上限つきの安全な YAML の読み込みの口が service の層にあり、境界テストは変えずに通る（ADR-007）。
  - DSL の既存のテスト（上限・タグ・重複キー・`$ref`）が版 2 の形で通る（AC6.1.10）。
  - `./gradlew verify` が通る（カバレッジの下限を含む）。
- **確かめること（confidence hypothesis）**: 版 2 への切り替えで、DSL の既存の機能（生成・プレビュー・照合・違い・適用・履歴）を壊さずにスキーマの階層を持てる。
- **見せるもの**: 版 2 の既定の DSL を生成して投入・適用し、DSL の画面でスキーマの階層が見える。版 1 を投入すると誤りの文言が出る。

### B2 U1 cross-cutting

- **確かめること**: 注釈と構造の検査で、以後の Bolt で足す API の分類の書き忘れを落とせる。
- **見せるもの**: 印を外した API が構造の検査で落ちること。
