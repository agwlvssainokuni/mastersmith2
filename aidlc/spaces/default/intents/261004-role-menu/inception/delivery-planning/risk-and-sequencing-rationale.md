# 順の理由と危なさ — role-menu

Bolt は、作る1回ぶんのまとまり（終わると動くものができる作業）である。この文書は、`bolt-plan.md` の Bolt の順を決めた理由を書く。

## 決め方

- 危ないところから作る（DQ1: A）。WSJF（価値と急ぎと危なさを大きさで割る点数、Reinertsen・SAFe）は使わない（DQ2: A）。依存の形がほぼ一本道で、順の選び方が U1 と U2 の前後、U5 と U6 の前後くらいしかないため、点数を付けても順は変わらない（前の Intent と同じ判断）。
- 考え方は Cohn の「危なさを先に減らす」（risk-first）で、依存の形（`unit-of-work-dependency.md`）の中で選べる所だけ危ないものを前に置いた。

## 順の理由

| 順 | Bolt | 前に置いた理由 |
|---|---|---|
| 1 | B1 U2 dsl-v2 | DSL の書式の版 2 は、DSL の既存の機能（生成・プレビュー・照合・違い・適用・履歴・画面）に広く手が入り、版を上げると既存の DSL が無い扱いになる（ADR-005）。役割・権限とメニューはどれも版 2 の DSL を前提にするため、いちばん先に形を固める。依存が無いため先に置ける |
| 2 | B2 U1 cross-cutting | 以後のすべての Bolt が足す API に分類の印を付けるため、注釈と構造の検査を先に用意する。共有の木と登録の型も画面の Bolt（B8・B9）の前提 |
| 3 | B3 U3 group | U4 が依存する。監査の表の変更（C10）を持ち、U4 の監査の土台になる |
| 4〜6 | B4〜B6 U4 | 解決の口は割り当てと作業ロールを要るため、「ロールと設定」→「割り当て・作業ロール・解決の口」→「受け渡し」の順にした（質問の案の「設定と解決」を依存に合わせて並べ替えた）。受け渡しは他の Bolt が依存しないため最後 |
| 7 | B7 U5 navigation | U4 の解決の口に依存する |
| 8 | B8 U6 role-admin-ui | U3・U4 に依存する。U5 とは依存が無く前後を選べるが、案のとおり B7 の後にした（管理の画面と業務のメニューの画面は互いに依存しない） |
| 9 | B9 U7 app-frame-ui | U4・U5 に依存する。make-you-chic-ui への依頼の取り込みを待つ時間を最も長くとれるよう最後に置く |

## 依存の形からの外れ

- 単位の依存の形（topology）の順からは外れていない（B1 と B2 は依存が無く、どちらを先にしてもよい）。U4 の中の3つの Bolt の順は、単位の中の機能の依存に合わせた。

## 主な危なさと先に打つ手

| 危なさ | 影響 | 先に打つ手 |
|---|---|---|
| DSL の版 2 で既存の DSL の機能を壊す | DSL の管理ができなくなる | B1 を最初に置き、既存のテストを版 2 の形で通す（AC6.1.9・AC6.1.10） |
| 版を上げた後・戻した後に DSL の機能が止まる | 投入し直すまで権限の対象とメニューが空 | 配備の段で生成し直しと戻しの手順を書く（ストーリーの確かめの R-01 で受け入れ済み） |
| 要求ごとの実効の権限の解決が重い | 業務のメニュー・権限の設定の画面が遅い | NFR 要件・NFR 設計で目標と試しのコード、B5 で写しの形（ADR-003・ADR-006） |
| 削除と割り当ての同時の重なり | 割り当てのあるロール・グループが消える | NFR 設計で試しのコード、B3・B5 で待ち合わせのテスト（ADR-006） |
| make-you-chic-ui への依頼が間に合わない | B9 のサイドバーが作れない | U7 の機能設計ですぐ依頼し、B9 を最後に置く。間に合わなければその時点で諮る（DQ5: A） |
| 既存のすべての API への印でパッケージの下限の作業が増える | B2 が大きくなる | 実測で下限に足りないのは common.health（行 79.2%）だけ。手を入れたらテストを足す |
