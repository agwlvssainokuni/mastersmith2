## 1. S1 アプリの枠

### 1.1 管理者で、業務のメニューがあるとき（RQ3: A・RQ6: A）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ MasterSmith                       [作業ロール: 営業 ▼]   [佐藤 ▼]         │ ← トップバー
├────────────────────┬─────────────────────────────────────────────────────┤
│ 業務               │                                                     │
│ ▾ 販売             │   （コンテンツ）                                    │
│   ▾ 受注           │                                                     │
│     ● 受注明細     │ ← 今の項目（aria-current="page"、太字と左の線）     │
│     ・受注ヘッダ   │                                                     │
│   ▸ 出荷           │                                                     │
│ ▸ マスタ           │                                                     │
│                    │                                                     │
│ 管理               │                                                     │
│ ・管理             │                                                     │
│ ・DSL              │                                                     │
│ ・招待             │                                                     │
│ ・利用者           │                                                     │
│ ・ロール           │ ← 新しい項目                                        │
│ ・グループ         │ ← 新しい項目                                        │
│ ・権限の受け渡し   │ ← 新しい項目（S7）                                  │
└────────────────────┴─────────────────────────────────────────────────────┘
```

- 「業務」「管理」は見出しで、読み上げでもまとまりの名前になる（AC5.3.4）。中身が無い見出しは出さない（AC5.3.5）。
- ▾／▸ は開閉のボタン（`aria-expanded`）で、文字の名前は「販売を閉じる／開く」。テーブルを指す項目（・）はリンク。テーブルと子の両方を持つ項目は、名前をリンク・右の ▾ をボタンに分ける。テーブルが NONE で子だけ見えるときは、リンクにしない（移れないまとまり。ストーリー D9）。
- 深さの上限まで、1段ごとに字下げする。長い名前は1行で省略し、Tooltip とリンクの読み上げの名前で全体を出す（AC5.1.10）。
- 開閉の状態は画面を移っても保ち、直接開いた画面では今の項目の祖先を開く（AC5.1.8・AC5.1.9）。
- DSL から来る label は文字として出す（`<script>`・`&` などはそのまま文字で見え、タグにならない）。icon は make-you-chic-ui の許したアイコンの名前だけを使い、許していない名前・空は既定のアイコン（list）にする（AC5.1.7）。
- テーブルの画面の道は、スキーマ名とテーブル名をそれぞれエンコードして `/tables/{スキーマ名}/{テーブル名}` に組み立て、名前に `/`・`..`・`?`・`#`・`%`・空白・`javascript:`・`https://` を含んでもこの道の形から外れない（AC5.1.13）。

### 1.1a 管理者でない利用者のとき（AC5.3.2・AC5.3.5・AC5.3.7）

```
┌──────────────────────────────────────────────────────────────┐
│ MasterSmith               [作業ロール: 営業 ▼]   [田中 ▼]     │
├────────────────────┬─────────────────────────────────────────┤
│ 業務               │                                         │
│ ▾ 販売             │   （コンテンツ）                        │
│   ・受注明細       │                                         │
│                    │ ← 「管理」の見出しと項目は出さない       │
└────────────────────┴─────────────────────────────────────────┘
```

- 業務のメニューも空のとき（作業ロールが無い・すべて NONE）は、サイドバーに見出しを1つも出さず、「表示できるメニューはありません」とだけ出す。ホームは 1.3 の案内。
- 管理者でも作業ロールですべて NONE のときは、「業務」の見出しを出さず「管理」だけを出す（AC5.3.3）。
- 管理者の印を外された利用者は、次の要求でこの形になる（AC5.3.7）。

### 1.2 作業ロールの切り替え（トップバー、AC4.1.1・AC4.1.7〜AC4.1.9）

```
[作業ロール: 営業 ▼]  を押すと
┌────────────────────────────┐
│ 作業ロールを選ぶ            │
│ ◉ 営業                      │
│ ○ 経理                      │
│ ─────────────────────────── │
│ 自分の権限を見る →          │ ← S8 への入口（Should、RQ7: A）
└────────────────────────────┘
```

- 今のロールは ◉ と文字「（使用中）」で示す。選ぶとすぐ切り替わり、Toast と読み上げで「作業ロールを経理に切り替えました」と伝え、フォーカスは切り替えのボタンに戻る（AC4.1.8）。今と同じロールを選んでも何も起きない（AC4.1.13）。
- ロールが1つだけ: 「作業ロール: 営業」は見えるが ▼ と一覧は出さない（ボタンにしない）。Tooltip と読み上げの説明で「割り当てられたロールは営業だけのため、切り替える先はありません」と示す（AC4.1.9）。自分の権限を見るへのリンクは利用者のメニューに置く。
- ロールが無い: 「作業ロール: なし」と出し、押すと「割り当てられたロールがありません。管理者に依頼してください。」と自分の権限を見るへのリンクを出す（AC4.1.4・AC4.2.4）。
- 切り替えた後、サイドバーの業務のメニューを読み直す（AC5.1.5）。今の画面が新しい作業ロールで権限なしになったときは、その画面を S2 の権限なしの表示にする（AC4.1.10）。

### 1.3 ホーム（業務のメニューが1つも無いとき、AC4.2.7・AC5.1.6・AC5.3.3）

```
┌──────────────────────────────────────────────┐
│ ようこそ、田中さん                           │
│ ⓘ 表示できる業務のメニューがありません。     │
│   作業ロールに見てよいテーブルが無いか、     │
│   ロールが割り当てられていません。           │
│   [自分の権限を見る]                         │

```

- 適用済みの DSL が無い・`menus` が空のときも、業務の見出しを出さずに同じ案内を出す（文言は「業務のメニューが設定されていません」に変える）。

## 2. S2 テーブルの画面の置き場（AC5.1.3・AC5.1.4・AC5.1.11）

```
準備中（実効 READ・FULL）                 権限なし・存在しないテーブル（同じ表示）
┌──────────────────────────────┐         ┌──────────────────────────────────┐
│ 受注明細                      │         │ この画面を表示する権限がありません │
│ 🛠 この画面は準備中です。     │         │ 今の作業ロール: 経理              │
│ 一覧と詳細の画面は、後の更新  │         │ [作業ロールを切り替える] [ホームへ]│
│ で追加されます。              │         └──────────────────────────────────┘
└──────────────────────────────┘
```

- 見出しはテーブルの表示名。権限なしと、DSL に無いテーブルの道は同じ表示にし、表示名を出さない（道を変えてテーブルの有無を探れないように。ストーリー D12）。
- 古いメニューから移って権限が無かったときも、同じ権限なしの表示にし、あわせてサイドバーの業務のメニューを読み直す。読み直した木には権限の無いテーブルが出ない（AC5.1.11）。

## 3. S3 ロールの一覧（RQ1: A、AC1.1.1〜AC1.1.4・AC1.1.7〜AC1.1.9）

```
ロール                                                      [ロールを作る]
┌──────────────┬───────────┬───────────┬──────────────────────────┐
│ 名前          │ 利用者     │ グループ   │ 操作                      │
├──────────────┼───────────┼───────────┼──────────────────────────┤
│ 営業          │ 2          │ 1          │ [開く] [⋯ ▼]              │ ← ⋯: 名前を変える／削除
│ 経理          │ 0          │ 0          │ [開く] [⋯ ▼]              │
└──────────────┴───────────┴───────────┴──────────────────────────┘
```

- 「ロールを作る」「名前を変える」は Modal で名前を入れる（上限ちょうどの文字数を残りの数で示す）。名前の誤り・重なり・同じ名前への変更は、入力欄の下に文字で出す（AC1.1.2・AC1.1.9・AC1.1.14）。
- 削除の確かめ（AC1.1.7）: 「ロール『営業』を削除します。権限の設定も消え、元に戻せません。」［やめる］［削除する］（はじめのフォーカスは「やめる」）。
- 割り当てが残るときの拒否（AC1.1.8）: 「ロール『営業』は利用者 2 人とグループ 1 つに割り当てられているため削除できません。先に割り当てを外してください。」と、割り当てのタブへ移るリンク。
- 空: 「ロールがありません。[ロールを作る]」。読み込み中・読み込みの失敗は既存の管理の画面と同じ形。
- 操作のメニューは表の右端に置くため、Dropdown の placement は bottom-end（`project.md` の学び）。

## 4. S4 ロールの詳細「権限の設定」（RQ4: A・RQ5: A、AC1.2.1〜AC1.2.7・AC1.2.13〜AC1.2.17）

```
ロール: 営業                                    [← ロールの一覧]
[ 権限の設定 ] [ 割り当て ]
┌──────────────────────┬────────────────────────────────────────────────────────────────────┐
│ スキーマ・テーブル    │ テーブル: 受注明細（ORDER_LINE）                                   │
│ ▾ 販売DB（SALES）     │ テーブルの設定                                                     │
│   ● 受注明細          │  主権限 [設定なし ▼] 実効: READ（スキーマ 販売DB から継承）        │
│   ・受注ヘッダ        │  CREATE [可 ▼]  実効: 可（明示）   DELETE [設定なし ▼] 実効: 不可（既定）│
│   ・出荷              │  業務のメニュー: 出る                                 〔Should〕   │
│   ・旧テーブル ⚠今のDSLに無い                                                          │
│                      │ カラム                                                             │
│                      │ ┌──────────────┬────────────┬─────────────────────────────┐      │
│                      │ │ カラム        │ 主権限      │ 実効                          │      │
│                      │ ├──────────────┼────────────┼─────────────────────────────┤      │
│                      │ │ 受注番号      │ [設定なし▼] │ READ（テーブルから継承）      │      │
│                      │ │ 単価          │ [NONE ▼]    │ NONE（明示）                  │      │
│                      │ └──────────────┴────────────┴─────────────────────────────┘      │
│                      │ 保存していない変更: 1 件          [変更を取り消す] [保存]           │
└──────────────────────┴────────────────────────────────────────────────────────────────────┘
```

- 左の木はスキーマ→テーブル（開いた所だけを読み込む）。スキーマを選ぶと右はスキーマの設定（主権限・CREATE・DELETE）だけになる（AC1.2.1・AC6.1.1）。
- 実効の値は「値（明示）」「値（〇〇から継承）」「値（既定）」の文字で区別し、色だけに頼らない（AC1.2.2〜AC1.2.4、デザイナーの直し）。
- 〔Should〕業務のメニューに出るか（テーブルの実効の主権限が NONE でないか）をテーブルの設定に出す（AC1.2.16）。
- 〔Should〕今の DSL に無いテーブル・カラムは木と表に「⚠ 今の DSL に無い」の印で出し、選ぶと「この設定は今の DSL に無いため使われていません。[設定を消す]」（AC1.2.7）。画面を開いた後に DSL から消えた対象を保存しようとしたときは、500 にせず同じ印の案内を出す（AC1.2.13）。
- 保存は表の下の「保存」で、そのテーブル（またはスキーマ）の分をまとめて保存する。保存の結果は表の上の Alert と読み上げで伝える。変わる点が無いときは「保存」を押せない（押せない理由を文字で示す）。押せるのに変わる点が無い要求が来たときの拒否は、表の上に文字で出す（AC1.2.17）。
- 保存していない変更があるまま、別のテーブル・タブ・画面へ移ろうとしたら確かめる（AC1.2.15）。
- 適用済みの DSL が無いとき: 「権限を設定する対象がありません。DSL の管理の画面で DSL を適用してください。[DSL の管理へ]」（AC1.2.6）。

## 5. S5 ロールの詳細「割り当て」（RQ2: A、AC2.2.1〜AC2.2.4・AC2.2.7〜AC2.2.9・AC2.2.15・AC2.2.16）

```
ロール: 営業
[ 権限の設定 ] [ 割り当て ]
利用者                                               [利用者を足す]
┌────────────────┬──────────────────────┬─────────────────┬──────────┐
│ 氏名            │ メールアドレス         │ 出どころ          │ 操作       │
├────────────────┼──────────────────────┼─────────────────┼──────────┤
│ 田中 一郎       │ tanaka@example.com    │ 直接・営業部       │ [外す]     │
│ 鈴木 花子       │ suzuki@example.com    │ グループ 営業部    │ （直接なし）│
└────────────────┴──────────────────────┴─────────────────┴──────────┘
グループ                                             [グループを足す]
┌────────────────┬──────────┐
│ 営業部          │ [外す]    │
└────────────────┴──────────┘
```

- 「利用者を足す」は Modal で、氏名かメールアドレスの一部で候補を絞って選ぶ。招待中の人は候補に出ず、利用停止の利用者は「（利用停止）」と分かるように出す（AC2.2.16）。すでに直接割り当てた利用者は候補に「割り当て済み」と出し選べない（AC2.2.15 の拒否は画面ではふつう起きない）。
- 出どころは「直接」「グループ 〇〇」を文字で並べ、同じロールは1行（AC2.2.2・AC2.2.7）。「外す」は直接の割り当てだけを外し、外した後もグループ経由で残るときは行が残り出どころが変わる（AC2.2.8）。
- 〔Should〕外すと本人の作業ロールが変わる・無くなるときは確かめの表示で知らせる（AC2.2.9）。
- 利用停止の利用者にも割り当てられる（AC2.2.16）。

## 6. S6 グループの一覧・詳細（RQ1: A、AC2.1.1〜AC2.1.4・AC2.1.7〜AC2.1.10・AC2.1.13）

```
グループ                       [グループを作る]       グループ: 営業部        [← グループの一覧]
┌────────────┬──────┬──────┐                      メンバー                          [メンバーを足す]
│ 名前        │ メンバー│ ロール │                      ┌──────────┬─────────────────┬──────┐
├────────────┼──────┼──────┤                      │ 田中 一郎 │ tanaka@example.com │ [外す]│
│ 営業部      │ 3     │ 1     │ [開く][⋯▼]          └──────────┴─────────────────┴──────┘
└────────────┴──────┴──────┘                      割り当てたロール: 営業（ロールの詳細で変える →）
```

- 作成・名前の変更・削除の確かめと拒否の文言はロールと同じ形。削除の拒否は「メンバー 3 人とロール 1 つが残っているため削除できません。」（AC2.1.7）。
- 割り当てたロールは読み取りで出し、変えるのはロールの詳細の割り当てのタブ（RQ2: A）。
- 「メンバーを足す」は S5 と同じ候補の絞り込み（AC2.1.8）。
- メンバーを外すと、その人のグループ経由のロールが外れて作業ロールが変わる・無くなることがある（AC2.1.9）。AC2.2.9（Should）の確かめはロールの割り当ての外しを対象とし、メンバーの外しには含めない。メンバーの外しは確かめなしで行い、結果の Alert に「田中 一郎さんは営業部から外れました。グループ経由のロール: 経理 も外れます」と、外れるロールを文字で出す。

## 7. S7 権限の受け渡し（YAML、RQ8: A、AC3.1.1〜AC3.1.6・AC3.1.9〜AC3.1.12・AC3.1.14・AC3.1.15）

```
権限の受け渡し
書き出す  ロールとその権限の設定を YAML で書き出します。グループと割り当ては含みません。 [書き出す]
読み込む  [ファイルを選ぶ] roles.yaml   [確かめる]
確かめの結果
┌──────────┬──────────┬───────────────┬──────────────────┐
│ ロール    │ 変わり方   │ 足す・変わる・消える │ 今の DSL に無い     │
├──────────┼──────────┼──────────────────┼──────────────────┤
│ ▸ 営業    │ 置き換える │ 3・9・4             │ 1                   │
│ ▸ 総務    │ 作る       │ 40・0・0            │ 0                   │
└──────────┴──────────┴──────────────────┴──────────────────┘
置き換えるロールでは、ファイルに無い対象の設定は「設定なし」に戻ります（消える: 4）。
ファイルに無いロール（経理）は残ります。                          [適用する]
```

- ロールの行を開くと、対象（スキーマ・テーブル・カラム）と前後の値の表が出る（AC3.1.2・AC3.1.9）。消える設定は「READ → 設定なし（ファイルに無い）」のように後の値と理由を文字で出す（AC3.1.3）。今の DSL に無い対象は「⚠ 今の DSL に無い」（AC3.1.6）。変わる点が無いときは「変わる点はありません」と出し、適用は押せない（AC3.1.14）。
- 「適用する」の確かめ: 「2 つのロールを置き換え・作成します。置き換えるロールでは、ファイルに無い対象の設定（4 件）は設定なしに戻ります。ファイルに無いロールは残ります。」（AC3.1.3・AC3.1.10）。結果は「作成 1・置き換え 1」と Alert で出す。
- 確かめの後に設定が変わって拒否されたとき: 「確かめた後にロールの設定が変わったため、適用できませんでした。もう一度[確かめる]を押してください。」（ファイルの選択は残す。AC3.1.11）。
- 中身の誤り・上限・タグ・重複キーは、DSL の投入の誤りの一覧と同じ形で、場所と内容を文字で出す（AC3.1.12）。適用済みの DSL が無いときは「DSL が適用されていないため読み込めません。」（AC3.1.5）。

## 8. S8 自分の権限（Should、RQ7: A、AC4.2.1〜AC4.2.4・AC4.2.6）

```
自分の権限                                   今の作業ロール: 営業 [切り替える]
┌──────────────────────┬────────────────────────────────────────────────┐
│ ▾ 販売DB              │ 受注明細: READ（見られる・直せない）  メニュー: 出る │
```

- 作業ロールが無いとき: 「作業ロールがありません。すべて見られません（NONE・不可）。」（AC4.2.4）。

## 9. S9 利用者の管理（既存）の詳細（RQ2: A）

- 既存の利用者の詳細に「ロール: 営業（直接・グループ 営業部）・経理（グループ 経理部）」を読み取りで足す（同じロールが直接とグループ経由の両方にあるときは1つにまとめ、出どころを並べる）。変えるリンクはロールの一覧へ。既存の画面の他の部分は変えない。
- この表示に要る読み取りの API（利用者のロールと出どころ）は要件に無く、機能設計で扱う。

## 10. S10 DSL の管理（既存）

- 版 1 の DSL を投入したとき・版 1 の履歴を復元したときは、既存の誤りの一覧に「書式の版 1 は使えません。書式の版 2（スキーマの階層あり）で書いてください。既定の DSL を生成し直すと版 2 で得られます。」と出す（AC6.1.2・AC6.1.7）。
- メニューの深さの上限を超える DSL は、既存の誤りの一覧に誤りの位置（メニューの道）と上限の値を出す（AC5.2.2）。
- 版 2 で、DSL の画面のメニューの木（`DslMenuTree`）と違いの表は今までどおり使え、スキーマの階層を木と表に1段足す（AC6.1.9）。

## 10a. 画面の幅ごとの振る舞い（R-01 の直し）

区切りは make-you-chic-ui と既存の画面に合わせ、768px と 1024px の2つにする。どの幅でも画面全体の横のスクロールを出さない（AC5.1.10）。

| 要素 | 1024px 以上 | 768〜1023px | 768px 未満 |
|---|---|---|---|
| サイドバー（S1） | 常に出す | 常に出す（幅を詰める） | AppShell の既存の開閉（ボタンで開く重ねた表示）に任せる |
| トップバーの作業ロール（S1） | 「作業ロール: 営業 ▼」 | 同じ | 「営業 ▼」に縮め、読み上げの名前は「作業ロール: 営業」のまま |
| S4・S8 の木と表の2分割 | 左に木（幅 280px）、右に表 | 左の木を 220px に詰める | 縦に積む。上に木（開閉できる区画）、下に表。木で対象を選ぶと表へフォーカスを移す |
| S3・S5・S6・S7 の表 | すべての列 | すべての列（文字を折り返す） | 表を内側で横にスクロールさせ（表の外枠の中だけ）、1列目（名前）は固定して見える。操作の列は右端の Dropdown（bottom-end） |
| S4 の表の Select | 列の中 | 列の中 | 1行を2段にし、上に対象の名前と実効の値、下に Select |
| Modal（作成・候補・確かめ） | 幅 480px | 同じ | 画面の幅いっぱい（左右の余白 16px） |

- 確かめる幅は 360px・768px・1280px の3つとし、axe と「画面の中に収まるか（開いたメニュー・Dropdown・Modal を含む）」をこの3つで確かめる（`accessibility-checklist.md`）。

## 11. 要件・ストーリーとの差

- **差1（S9）**: 既存の利用者の管理の画面の詳細に、その人のロールと出どころを読み取りで足す（RQ2: A）。要件・ストーリーに無い表示で、AC2.2.7・AC2.2.8 の出どころの表示を利用者の側からも見られるようにしたもの。新しい操作は足さないが、読み取りの API が要り、機能設計で扱う。
- そのほかの答えは、ストーリーの受け入れ基準の範囲に収まる。
