# 信頼性の要件 — U5 navigation

## 出典

- `functional-spec.md`・`rules.md`（この単位の承認済みの機能設計。3節の状態の遷移、BR1.5・BR4.3・BR7.2）
- `requirements.md`（NFR1.1、NFR3.1・NFR3.2、NFR6.1）
- `contract-summary.md`（C3・C5）
- `technology-stack.md`（コード知識ベース。`GlobalExceptionHandler`、起動の仕組み）
- この段の答えとまとめの確認（アイコンの一覧のファイルの誤りは統合の前の検査で止まるため可用性の要件にしない）。

## ID の対応表

全体の表は `security-requirements.md` の「ID の振り方」にある。上流の NFR3（同時性・一括確定）はこの単位では当たらない（書き込みが無い）。この単位の信頼性の要件は、意味の近い当たる枝番の続きで振る。

| 上流の枝番 | この単位での扱い | この単位の ID |
|---|---|---|
| NFR3.1・NFR3.2 | 当たらない（書き込みが無い。割り当て・切り替えの重なりの守りは U4 role） | — |
| NFR1.1 サーバー側の判定 | 当たる（重なり・想定外の失敗の間も権限の無い項目を出さない） | NFR1.10・NFR1.11 |
| NFR6.1 必須のテスト | 部分（アイコンの一覧のファイルの誤りを統合の前に止める） | NFR6.8 |

## 要件

| ID | 要件 | 測り方・確かめ方 | 持ち主の段 |
|---|---|---|---|
| NFR1.10 | 読み取りの間に DSL が適用し直されても、またはテーブルの主権限・割り当てが変わっても、権限の無い項目と権限の無いテーブルの表示名を返さない（BR1.5）。メニューの API は読み直さず、`current()` で読んだ menus を写しで絞る。新しい DSL に無いテーブルは写しが NONE を返して落ちる。置き場の問い合わせで、`resolve` の後に `current()` のモデルに組が無ければ 403 にする（機能設計 2.2 の 4） | 結合テスト `NavigationDslSwapIT`。待ち合わせの口で `current()` の後・解決の口の前に止め、その間に DSL を適用し直す（テーブルを1つ消した DSL と、別のテーブルを足した DSL の2通り）。再開した応答に、新しい DSL で NONE のテーブルを指して移れる項目が無いこと。置き場も同じ止め方で、消えた組が 403 になること。重なりはスレッドの数に頼らず待ち合わせで作る（`team.md`） | Code Generation（B7） |
| NFR1.11 | 内部DB の誤りなど想定外の失敗は例外のまま投げ、既存の 500 にする（BR7.2）。途中まで絞った木や、理由の違いが分かる本文を返さない。応答に内部の例外の文を載せない（`project.md` の Forbidden） | 結合テスト `NavigationFailureIT`。解決の口を例外を投げる替え物にし、メニューと置き場の応答が 500 の共通の本文（例外の文を含まない）であること | Code Generation（B7） |
| NFR6.8 | アイコンの一覧のファイル（`backend/src/main/resources/navigation/allowed-icons.txt`）が無い・読めない・名前が0個・`list` が無い・名前が重なるときは、アプリの起動を止める（BR4.3）。ファイルは WAR の中にあり運用で書き換えないため、誤りは統合の前の `./gradlew verify` で止まる。配備した後に起きうる経路が無いため、起動の停止を可用性の要件にはしない | 単体テスト `AllowedNavIconListTest`（`#` の行・空行・前後の空白の読み方、5つの誤りそれぞれで起動の部品が例外を投げること）。既存の起動のテスト（アプリの文脈の起動）が、実際のファイルで起動できること | Code Generation（B7） |

## 補足

- 空の木（DSL が無い・menus が空・作業ロールが無い・すべて NONE）は誤りにせず 200 で返す（BR1.2・BR1.3・BR2.5）。メニューの読み込みの失敗の表示と読み直しは U7 app-frame-ui。
- 書き込みが無いため、巻き戻し・戻しの確かめ・移行の後方互換の要件は無い。配備の戻しはイメージだけで足りる（表を足さない）。
