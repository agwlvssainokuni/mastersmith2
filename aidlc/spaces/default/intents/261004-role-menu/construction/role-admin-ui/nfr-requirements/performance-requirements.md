## 3. 画面の振る舞い

| ID | 要件 | 確かめ方（テスト・境界） | 持ち主の段 |
|---|---|---|---|
| NFR2.10 | 画面は要求に独自の時間切れを置かない（既存の ApiClient のまま）。送信から 5 秒を過ぎても応答が無いときは「時間がかかっています」を出し、応答で消す。S7 の確かめと適用では、上限ちょうどのファイルで確かめは最大 15 秒・適用は最大 30 秒かかりうることを案内の文に含める。二重の送信は、押したボタンを処理中にし、フックが送信の最中を参照で持ってその間の呼び出しを捨てることで防ぐ | 画面のテストで偽の時計を進め、4.9 秒では出ず 5 秒で出て応答で消えること、送信中の2回目の押下で API が呼ばれないことを確かめる（S3・S4・S5・S6・S7） | Code Generation（B8） |
| NFR2.11 | 木の開閉・節の選び・読み直しが重なったら、最後に始めた読み込みの答えだけを使い、画面を離れた後の答えを捨てる。決まった間隔の自動の読み直しはしない | 画面のテストで、答えの順を入れ替えた2つの読み込みで古い答えが描かれないこと、画面を外した後の答えで状態が変わらないこと、偽の時計を進めても API が呼ばれないことを確かめる | Code Generation（B8） |

## 4. 受け入れた制約

- 画面の時間は手元の PC の1台・1つのブラウザで測り、値を記録するだけで統合を止めない（前の Intent の U5 と同じ）。配備先の端末での時間は測らない。
- S7 の確かめの応答は、上限ちょうどで数十 MB の JSON になりうる。画面は描画を 100 件ずつに抑えるが、応答の受け取りと読み込みの時間・メモリは減らせない（機能設計 9節 (g)）。NFR2.7 で値を記録し、応答の大きさそのものは U4 の持ち物とする。

## 5. コード生成（B8）への引き継ぎ

- 測りのテストの見本: 100 カラム・1,000 カラムのテーブル、25 ロール × 1万の変わる点の確かめの応答を、型付きの見本の作り方（関数で作る）で用意する。見本の形が本物と同じことは流れの E2E で確かめる（tech-stack の NFR6.10）。
- B8 の前の `check-bundle-size.mjs` の値を、計画の時点で記録しておく。
