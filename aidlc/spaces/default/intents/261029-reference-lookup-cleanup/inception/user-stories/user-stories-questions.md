## M1: 必須（NOT NULL）の参照項目で、参照先を読めない、または候補が 201 件以上のときの作成
この項目は入力不可（またはピッカー案内）になり、値を入れられません。必須なので、作成が成り立たない行き止まりが残ります。品質担当と開発担当が気にしている点です。

A. 作成は 409 `BUSINESS_REFERENCE_NOT_FOUND`（その項目の誤り）で拒否し、「必須の参照項目に値を入れられません」と項目の近くに出す。行き止まりを許容し、管理者へ権限またはピッカー（LOOKUP）への切り替えを頼む
B. 値を文字で入力できる欄に切り替える（権限を欠く人が参照先の存在を試せるため、Practices Discovery と要件の Q2 の決定と食い違う）

## M2: refresh トークンなど、JWT の形でない認証の値の扱い
JWT を `eyJ…` の形で置換するだけでは、形が違う認証の値（refresh トークン・Authorization ヘッダー）は伏せられません。Forbidden は認証の値全般を挙げています。k6 の summary json にそれらが入るかは未確認です。

A. 形による置換に加えて、summary json にキー名（`refresh`・`Authorization` など）の認証の値が無いことを確かめ、有れば失敗にする。キー名の一覧は設計で決める
B. 要件どおり JWT の形だけを伏せる。ほかの認証の値は入らない前提で、設計で確かめる
X. Other (please specify)
