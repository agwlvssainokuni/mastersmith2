# ペルソナ — reference-lookup-cleanup（最終版）

出典: `aidlc/spaces/default/intents/261029-reference-lookup-cleanup/inception/requirements-analysis/requirements.md` の Intent の分析、ストーリーの質問 Q1（P1・P2・P3 を前の Intent 261016-business-data-views から引き継ぎ、P4 を足す）。

## P1 業務データを見る人（田中さん）

- **役割**: MasterSmith の画面で業務データを調べる利用者。管理者の印は持たない。扱うテーブルの主権限は READ で、作成・削除の権限は無い。前の Intent の P1 を引き継ぐ。
- **目的**:
  - 注文のように他のテーブルを参照する行を、これまでどおり一覧・詳細で読みたい
  - 今回の変更で、一覧・詳細の見た目と操作が変わらないこと（US3.4）を確かめたい。入力不可の項目を見るのは編集できる利用者（P2）に限るため、P1 の関わりは一覧・詳細に絞る
- **困りごと（今）**:
  - 参照している値が ID のまま出る（今回の範囲では変えない。ラベル併記は範囲の外）
- **技術への慣れ**: 低〜中
- **アクセシビリティ**: キーボードだけで操作する人、読み上げを使う人もいる
- **使う頻度**: 毎日
- **言語**: 日本語または英語

## P2 業務データを直す人（鈴木さん）

- **役割**: マスタの値を登録・修正する担当者。受け持つテーブルが FULL で、CREATE・DELETE が可。参照先のテーブルは READ のことも、権限が無いこともある。前の Intent の P2 を引き継ぐ。
- **目的**:
  - 注文の「顧客」のように、他のテーブルを参照する項目を、ID を覚えずに、選択肢から（または検索して）選びたい
  - 参照先の候補が多いときは、検索して絞り込んで選びたい
  - 参照先の権限が無い項目があっても、同じ行のほかの項目を直したい
  - 選んだ値が正しい参照かを、保存の前に（保存のとき）教えてもらいたい
  - 参照先の権限が無い項目が必須のとき、入力できない理由と次の手（管理者への依頼）が分かりたい
- **困りごと（今）**:
  - 参照する項目は文字の入力欄で、ID を直接打つ必要がある（コード知識ベースの所見 K-74）。打ち間違いは保存のときに外部キー違反の誤りで初めて分かる
  - 選択肢が長いと選べない。検索のダイアログで条件を入れても何も出ない状態が不安
- **技術への慣れ**: 中（DB の制約やエラーの文は読めない。誤りは業務の言葉と該当の項目で伝える必要がある）
- **アクセシビリティ**: キーボードだけで操作する人、読み上げを使う人もいる
- **使う頻度**: 毎日（月末などに多い）
- **言語**: 日本語が主

## P3 管理者（佐藤さん）

- **役割**: MasterSmith の管理画面で、利用者・DSL・ロールと権限の設定を受け持つ。前の Intent の P3 を引き継ぐ。
- **目的**:
  - 設定した権限（参照先のテーブルの主権限・カラムの権限）が、参照の選択肢とピッカーに期待どおり効いていること（権限が無い人に参照先のラベルが漏れないこと）を確かめたい
  - 権限を欠く人に何が見え、何が見えないかを、運用の説明として言える。権限を欠く人の画面を代わりに見るには、作業ロールの切り替えを使う
- **困りごと（今）**:
  - 参照先の権限をどう効かせるかが決まっておらず、設定の結果を確かめられない
- **技術への慣れ**: 中（YAML は読めるが、DB は直接触りたくない）
- **使う頻度**: 週に数回
- **言語**: 日本語が主。英語の画面も使うことがある

## P4 運用・性能を測る人（高橋さん）

- **役割**: アプリを動かし、性能を測り、記録を残す人（このプロジェクトでは開発者本人が兼ねることが多い）。手元のコンテナ（Mailpit・otel-lgtm）と k6 の負荷試験を扱い、結果を `evidence/` などの記録に置く。新しく加えたペルソナ。
- **目的**:
  - k6 の結果に入る使い捨ての環境の JWT を、記録に置く前に自動で伏せ、手で置換する漏れをなくしたい
  - 動いているコンテナの版を `compose.yaml` の版とそろえ、そろったことを確かめたい
  - perf の README と台本で、どの値が今の基準かをすぐ読み取りたい
- **困りごと（今）**:
  - JWT の伏せ字は手で置換する手順で、前の Intent では伏せ漏れの記録が公開側に残り、CI の失敗と履歴の書き換えになった
  - 止まっている lgtm のコンテナが作り直されず、古い版が残ったことがある
  - perf/README.md は約 1,360 行で、前の線と今の線が混ざっている
- **技術への慣れ**: 高
- **アクセシビリティ**: 該当する画面は無い
- **使う頻度**: 測るとき（Intent ごと）
- **言語**: 日本語

## ペルソナの関係と優先度

1. **P2 業務データを直す人**（最優先）: 参照の選択肢とピッカーを使い、保存前の確かめを受ける。
2. **P1 業務データを見る人**: 一覧・詳細が変わらないこと（US3.4）で関わる。入力不可の項目は編集できる P2 が見る。
3. **P3 管理者**: 権限の効き方と、漏れないことを確かめる。
4. **P4 運用・性能を測る人**: 持ち越しの片付け（JWT の伏せ字・コンテナの版・perf の文書）の受益者。

同じ人が作業ロールを切り替えると、P1 にも P2 にもなる。
