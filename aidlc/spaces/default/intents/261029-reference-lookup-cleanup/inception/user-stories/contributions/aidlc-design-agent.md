## Contribution

観点: 利用者の体験とペルソナの忠実さ。初稿の AC は権限・上限・漏えいに強く、画面の状態と助けになる文言が薄い。以下を追加・修正の案とする（ID は候補）。

### 追加する受け入れ基準の案

**US1.3（入力不可の見え方）**
- **AC1.3.6（候補）** Given 権限を欠いて入力不可になった項目があるとき、When 画面を見る・読み上げるとき、Then 項目名の近くに「参照先を読む権限がないため変更できません」の説明が文字で出て、入力欄は `aria-disabled` または `readonly` で支援技術に伝わる。灰色だけで示さない（色だけに頼らない）。
- **AC1.3.7（候補）** Given 入力不可の項目に保存済みの値が入っているとき、When キーボードで移動するとき、Then 値を読み上げで確かめられる（値を読めない `disabled` だけにしない）。フォーカスは項目を飛ばさず止まるか、説明に到達できる。
- **AC1.3.8（候補）** Given 参照先が 201 件以上でピッカーへ案内される項目（AC1.2.2）のとき、When 画面に出るとき、Then 権限不足とは別の文言（「候補が多いため検索して選んでください」）が出て、権限不足と見分けられる。LOOKUP が未定義のカラムでは、行き場のない案内にならないよう、文言で「管理者へ」と伝える。

**US1.1（選択肢）**
- **AC1.1.6（候補）** Given 選択肢が 0 件（参照先の表が空）のとき、When 画面に出るとき、Then 「選べる候補がありません」が出る。NOT NULL の項目では保存できない理由が分かる。
- **AC1.1.7（候補）** Given 取得の途中のとき、When 画面に出るとき、Then 項目は読み込み中と分かる表示（`aria-busy`）で、入力できないことが伝わる。
- **AC1.1.8（候補）** Given ラベルが長い・同じラベルが複数あるとき、When 選択肢が出るとき、Then 長い名前は折り返すか省略して全文を取れ、同じラベルは値を併記して見分けられる。

**US2.1（ピッカーの流れ）**
- **AC2.1.7（候補）** Given ダイアログの検索中のとき、When 結果を待つとき、Then 「検索中」が出て、検索ボタンの二重押しが防がれる。検索の失敗（503・時間切れ）は、条件を保ったまま「再度検索」を促す。
- **AC2.1.8（候補）** Given 条件が空のまま検索したとき、When 実行するとき、Then 条件の入力を促す文言が出る（初期状態と区別する。0 件の文言と混ぜない）。
- **AC2.1.9（候補）** Given 選択済みのラベルが入力欄の隣にあるとき、When 値を変えたい・消したいとき、Then 再度ダイアログを開く操作と、NULL を許す項目では値を消す操作がある。
- **AC2.1.10（候補）** Given ダイアログを「閉じる」「Esc」「選ばずに戻る」で閉じたとき、When 閉じるとき、Then 入力欄の値は変わらない。背景のクリックで閉じない（前 Intent の確かめる表示と同じ）かは Refined Mockups で決める。
- **AC2.1.11（候補）** Given ラベル・値に `<script>`・引用符・`javascript:` が含まれるとき、When 一覧・入力欄の隣に出るとき、Then 文字として出る（team.md の (f)）。US2.1/2.2 に現れていないため明示する。
- **AC2.1.12（候補）** Given ページ送りがあるとき、When 次のページへ移るとき、Then 現在のページと総ページの状態が読み上げられ、ページ送りの文言は日本語と英語で出る。

**US2.4（アクセシビリティ）**
- **AC2.4.5（候補）** Given ダイアログを開いたとき、When 見出し・検索結果の件数・行の選択を読み上げるとき、Then ダイアログに名前（見出し）があり、結果の件数の変化が `aria-live` で伝わり、選択の行は 1 行ずつ操作の対象（ボタン等）になる。
- **AC2.4.6（候補）** Given 狭い幅（375px）のとき、When ダイアログと表を開くとき、Then 横の画面全体のスクロールが出ず、ダイアログが画面に収まる（project.md の固定の部品の確かめ）。
- **AC2.4.7（候補）** Given axe の検査をするとき、When 状態を選ぶとき、Then 「ピッカーを開いた状態」に加え、誤りを出した状態（検索の失敗・0 件・入力不可）と、2 語以上の現実に近いデータを含める（project.md の axe の学び）。
- **AC2.4.8（候補）** Given 画面に出る誤りのとき、When 表示するとき、Then 業務の言葉と該当の項目で伝え、DB の制約の文や内部の語は出ない（P2 の慣れの水準）。

**US3.1（保存前の確かめ）**
- **AC3.1.7（候補）** Given 参照の誤り（409）のとき、When 画面に出るとき、Then その項目の近くに誤りが出て、フォーカスがその項目に移り、誤りは `aria-describedby` で結ばれる。存在しないのか権限がないのかは文言で区別しない（AC3.1.3 と同じ）。

**US3.4**
- **AC3.4.3（候補）** Given 参照の項目が入力不可・案内つきになったとき、When 一覧・詳細を開くとき、Then 一覧・詳細の表示と操作は変わらない（入力不可の見た目が一覧・詳細に漏れない）。

### make-you-chic-ui の部品の見込み（Refined Mockups の足りない点の一覧の種）
- 有るはず（要確認）: Modal（フォーカスの閉じ込め・戻り）、TextInput、FormField（誤りの結び付け）、Table（並べ替え・ページ送り。ただし 1 ページの件数の選択と横スクロールの領域は前の依頼（5）で依頼済みのため、固定先に取り込まれたか確認）。
- 無い見込み: 検索ボックスと結果の一覧を 1 つのダイアログに収めるピッカー（コンボボックス・ダイアログの複合）、選択可能な行（行の選択ボタン）、入力不可項目の説明つき表示、選択済みのラベルの表示欄。`select`・`radio` が 200 件の候補でも使えるか（長い候補の検索つき選択）。
- team.md の決まりどおり、足りない点は Refined Mockups で一覧にし、機能設計の承認の前に `make-you-chic-ui-request-<n>.md` で依頼する。ストーリーの段では「部品の有無はストーリーの合否ではない」とだけ書き、UI の AC は部品に依存しない形（振る舞い）で書く。

### ペルソナの過不足
- **P2（鈴木さん）**: 「アクセシビリティ」は書かれているが、権限の無い参照先を持つ行を直す場面（入力不可の項目が混ざったフォーム）が目的に入っている点は良い。補う案: 困りごとに「選択肢が長いと選べない」「ダイアログで条件を入れても何も出ない状態が不安」を足す。
- **P1（田中さん）**: 今回の変更が見えるのは主にフォームで、P1 は読むだけである。US1.3 の「P1 / P2」の P1 は、入力不可を見るのは編集権限を持つ人（更新の画面を開ける人）に限るため、P1 の関わりは US3.4（一覧・詳細が変わらない）に絞る方が忠実。
- **P3（佐藤さん）**: 「見えない側の体験」を確かめる役。権限を欠く人の画面を代わりに見るには作業ロールの切り替えを使う旨を、AC2.3.5 の確かめ方に添える。
- 新しいペルソナは不要。「読み上げ・キーボードのみの P2」を独立させず、P2 の属性のまま、AC（US2.4）で受ける。
- **P4（高橋さん）** は画面を使わない。US3.5 の「P4 として」は、利用者の体験でなく運用の質のため、横断の確かめとして U3.5 を群3から外すか「非機能のストーリー」と明記する案（リードの判断）。
