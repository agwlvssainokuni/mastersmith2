### 4. JWT の伏せ字（US4.1）の AC の質

- **AC4.1.1**: 「JWT（`eyJ…` の形）」の定義を AC に書く: `eyJ` で始まる base64url の3区間（`.` 区切り）。境界: 2 区間は置換しない、`eyJ` を語の途中に含む文字列（前が英数字）は置換しない、同じ文字列に JWT が複数、JSON の値・配列の要素・**オブジェクトのキー名**（k6 のタグ名に入りうる）・長い文字列（数 MB の summary）のどれにあっても伏せる、`Bearer eyJ…` は JWT の部分だけを伏せる。
- **AC4.1.2** は文面が循環している（置換した後に残るのは、置換の誤りだけ）。→ 「残存の検査（置換とは独立の関数）が、JWT の形を含む入力を検出して非 0 で終わる」「検査が失敗したとき、`evidence/` にファイルが作られず、一時ファイルも残らない」「入力が JSON でない・空のときも失敗し、ファイルを置かない」の3件に分ける。
- **AC4.1.3**: 性質ベースのテストにする（`team.md`）。性質: (1) 置換後に JWT の形が無い、(2) 冪等 `f(f(x)) == f(x)`（`[REDACTED-JWT]` 自体が JWT の形に一致しない）、(3) JWT を含まない入力は変わらない（数値・場面名・真偽・null・入れ子・長い文字列）、(4) 出力は JSON として解析でき、構造（キーと型）が入力と同じ。失敗時の乱数の種を記録する。ランダムな入力に、JWT に近い文字列（2 区間・`eyJ` の前に英数字・末尾の `=`）を混ぜる。
- **欠けている AC**: Forbidden は「JWT・**リフレッシュトークン**・Authorization ヘッダー」を伏せるとあるが、リフレッシュトークンは `eyJ` の形ではない可能性が高い。形による置換だけでは漏れる。→ **AC4.1.6** summary json にリフレッシュトークン・Authorization ヘッダーの値が入らないことを、(1) k6 の台本が書き出す項目の確認、(2) 伏せ字の仕組みの入力に既知のキー名（`refreshToken`・`Authorization`・`access_token`）の値を入れた fixture で、形に関わらず値を伏せる、のどちらで担保するかを決めて AC にする（R-07 の未解決を、ストーリーで解く）。
- **AC4.1.4**: 「通る」は意味が薄い。→ 「仕組みのテストが `./gradlew verify` の中で実行される（`:backend:cleanTest ...` のようにスキップされない）。CI の同じ段で実行される。`evidence/` に置くファイルに `gitleaks dir` を流して 0 件」。
- **NFR8 の「手置きで抜けない」に AC が無い**: **AC4.1.7** `evidence/` に置く手順は仕組みを通すスクリプトの1つだけで、`perf/README.md` はその使い方を書く。`aidlc/` の `evidence/` 以下の既存のファイルに、JWT の形が無いことを確かめる検査（`verify` か CI の段）を置く。
- **AC4.1.5**: 「伏せる対象と対象外が書かれている」は文書の有無だけ。→ 対象外（標準出力・ログ）の**手順**（どのコマンドで伏せるか）まで書かれていること。

### 6. E2E 1本の流れの候補

- **候補**: 「自作のロール（参照元の表を FULL、参照先の表を READ）と自作の利用者でログイン → 参照元の表の作成の画面 → LOOKUP の項目でピッカーを開く（キーボードで） → 検索の条件を入れて検索 → 行を選ぶ（キーボードで）→ 入力欄の隣にラベルが出る → 保存 → 更新の画面を開いてラベルが出る」。REFERENCE の select は同じ画面に置き、選択肢が出る確認を流れの中に1手入れる（本数は増やさない）。
- 前提はすべて自作する: 専用のスキーマの参照先・参照元の表と行（架空の値）、自作の役割・利用者。初期管理者と見本の行・見本の DSL を変えない。対象DB は PostgreSQL の1種類（`team.md`）。
- 注意（要確認）: 適用中の DSL は全 E2E で共有される。LOOKUP を使う表を足すために DSL を適用し直すと、他の E2E の前提を変える。→ 設計の段で「見本の DSL に専用スキーマの表と LOOKUP を**足す**」形にし、既存の E2E は書き換えない（書き換える場合も本数に数えない）。DSL の適用の操作を流れの中に入れない。
- axe は、ピッカーを開いた状態・結果の一覧が出た状態・0 件の状態・誤りの状態・長い名前（100 文字以上、`<` を含む）で、ブランドカラーとテーマのすべての組。ダイアログが画面の中に収まること（375px の幅を含む）も確かめる（`project.md`）。
- 資格情報は環境変数で渡し、Playwright の報告の json を文字列で検索して、トークン・パスワード・接続情報が無いことを確かめる。
- 権限を欠く利用者の確かめは E2E に入れず、結合テストで行う（`team.md`）。ただし、画面のテストで「入力不可・値だけ表示・理由の表示」を1件持つ（AC1.3.3）。

### 7. 追加の小さな漏れ

- 作業ロールを切り替えた直後・割り当てを変えた直後の次の要求で、**REFERENCE の定義の取得**でも選択肢が切り替わる（AC2.3.5 は検索 API だけ）。AC1.3 にも1件。
- 画面のテストは、描画の後の効果で出る値を `waitFor` で待つ（`team.md`）。ピッカーの部品が make-you-chic-ui の部品でないときは、キーボード操作と `aria` の属性を画面のテストで確かめる（AC2.4.1・AC2.4.2 の確かめ方を書く）。
- 純粋な関数（選択肢の並べ替え・「値が変わった」の判定・参照の値の正規化）は、fast-check／jqwik の性質ベースのテストを一部に当てる候補とする（必須ではない）。
- カバレッジ（NFR5）に AC が無い: 行 80%・分岐 70%（全体と新しいパッケージごと）、手を入れる `packagesJudgedByTotal` のパッケージ（例: `common.web` ほか、手を入れるもの）はテストを足して一覧から外す。これは Delivery Planning・コード生成の計画で実測するが、ストーリーの段で「横断の AC」として1件置く。
