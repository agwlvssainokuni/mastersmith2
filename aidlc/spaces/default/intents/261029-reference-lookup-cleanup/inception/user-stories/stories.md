# ユーザーストーリー — reference-lookup-cleanup

出典: `aidlc/spaces/default/intents/261029-reference-lookup-cleanup/inception/requirements-analysis/requirements.md`（FR1〜FR8、NFR1〜NFR9）、質問 Q1〜Q5（`user-stories-questions.md`）、ペルソナ（`personas.md`）。

## 前提と読み方（すべての受け入れ基準に共通）

### 分け方・優先度

- 群は機能のまとまりで4つに分ける（Q2: A）。群1 参照の選択肢（REFERENCE）、群2 参照ピッカー（LOOKUP）、群3 保存前の確かめ、群4 持ち越しの片付け。
- 優先度は MoSCoW。参照の選択肢・ピッカー・保存前の確かめ・JWT の伏せ字を Must、コンテナの版そろえ・perf の文書の整理を Should とする（Q3: A）。最小の範囲（MVP）の線は Delivery Planning で決める。
- 受け入れ基準は、要件の境界と失敗の場合を1件ずつ書く（Q4: A）。

### 共通の読み方

- 「権限」は、作業ロールの権限（主権限 NONE・READ・FULL、補助権限 CREATE・DELETE）で、API ごとにサーバー側で判定する。画面の出し分けは代わりにならない（`project.md` の Mandated）。
- 「参照元」は参照する側の表のカラム、「参照先」は参照される側の表。参照先は同じスキーマの中の表に限る（要件の制約）。
- 参照先の行の値（選択肢の値・ラベル、検索の値）は、アプリのログ・トレースの属性・エラー応答・監査に含まれない（`project.md` の Forbidden）。各ストーリーの受け入れ基準に繰り返さず、ここで一度だけ書く。
- 「誤り」は Problem Details の形で返り、画面が分岐に使う安定した `code` を持つ。内部の例外メッセージを含まない。
- 画面の文言と誤りのメッセージは日本語と英語の両方。
- 3種類の対象DB（MySQL・MariaDB・PostgreSQL）のすべてで同じ結果になる（`team.md`）。

## 群1 参照の選択肢（REFERENCE）

### US1.1 参照先の選択肢から値を選ぶ 〔Must〕

P2（鈴木さん）として、他のテーブルを参照する項目（`select`・`radio`）で、参照先の行を選択肢から選びたい。それは、ID を覚えず、打ち間違いなく入力するためである。

- **AC1.1.1** Given 参照先の表を読める利用者が、REFERENCE のカラムを持つ表の作成の画面を開いたとき、When 画面が表示されるとき、Then 参照先の `valueColumn` を値、`labelColumn` を表示にした選択肢が出て、`labelColumn` の昇順（同じラベルは `valueColumn` の昇順）に並ぶ。
- **AC1.1.2** Given ラベルが NULL の参照先の行があるとき、When 選択肢が出るとき、Then その行は並びの最後に置かれ、表示には値が出る。
- **AC1.1.3** Given 更新の画面で、保存済みの参照の値があるとき、When 画面が表示されるとき、Then その値の選択肢が選ばれた状態で出る。
- **AC1.1.4** Given 参照先の読み取りが時間切れ・接続の失敗になったとき、When 画面の定義を取得するとき、Then 既存の業務データの読み取りと同じ誤り（503）で返り、画面はやり直しを促す。
- **AC1.1.5** Given 1つの画面に REFERENCE のカラムが複数あるとき、When 定義を取得するとき、Then 参照先の読み取りは、対象DB の読み取りの接続 1 本で順に行われる。

### US1.2 参照先が多すぎるとき、ピッカーへ案内される 〔Must〕

P2 として、参照先の行が多すぎて選択肢にできないとき、その旨と次の手段が分かるようにしたい。それは、画面が重くなったり、一部だけ見えて誤った選択をしたりしないためである。

- **AC1.2.1** Given 参照先の行が 200 件ちょうどのとき、When 定義を取得するとき、Then 200 件すべてが選択肢として返る。
- **AC1.2.2** Given 参照先の行が 201 件以上のとき、When 定義を取得するとき、Then 選択肢は返らず、その項目に「参照ピッカー（LOOKUP）を使うよう案内する誤り」が付く。判定は 201 件目まで読んで行う。
- **AC1.2.3** Given 参照先が 201 件以上の項目があるとき、When 同じ画面のほかの項目を見るとき、Then ほかの項目は通常どおり表示され、フォーム全体の定義の取得は失敗にならない。
- **AC1.2.4** Given 参照先が 201 件以上の項目の保存済みの値があるとき、When 更新の画面を開くとき、Then その項目は入力できず、値そのもの（保存されている値）だけが表示される。

### US1.3 参照先を読む権限が無いとき、入力不可で値だけ見える 〔Must〕

P1 / P2 として、参照先のテーブルを読む権限が無いとき、参照先のラベルを見せられない旨と、すでに入っている値は分かる状態にしたい。それは、権限を越えて情報が漏れないためである。

- **AC1.3.1** Given 利用者が参照先の表の主権限を欠く（NONE）とき、When REFERENCE のカラムを持つ表の画面の定義を取得するとき、Then 選択肢は返らず、その項目に「参照先を読む権限がありません」の印が付き、定義の取得は 403 にならない。
- **AC1.3.2** Given 参照先の `valueColumn` または `labelColumn` の主権限が NONE のとき、When 定義を取得するとき、Then AC1.3.1 と同じ扱いになる。
- **AC1.3.3** Given AC1.3.1 の項目があるとき、When 画面に表示されるとき、Then その項目は入力不可で、保存されている値そのものだけが表示される（参照先のラベルは出ない）。
- **AC1.3.4** Given LOOKUP のカラムで、参照先を読む権限を欠くとき、When 定義を取得するとき、Then 参照先の表の名前は載らず、AC1.3.1〜AC1.3.3 と同じ扱いになる（REFERENCE と LOOKUP の両方に当たる）。
- **AC1.3.5** Given 参照元の権限だけを持ち、参照先の権限を欠く利用者がいるとき、When 参照先のラベルを得ようとするとき、Then どの API の応答にもラベルが含まれない（サーバー側の判定。画面で隠すことを代わりにしない）。

### US1.4 参照先の値が漏れない・読み取りが守られる 〔Must〕

P3（佐藤さん）として、参照先の読み取りが、権限と上限で守られ、値がログなどに出ないことを確かめたい。それは、運用の説明として、権限どおりに効いていることを言えるためである。

- **AC1.4.1** Given 参照先の表・カラムの名前が適用中の DSL に無いとき、When その名前で参照先を読もうとするとき、Then 読まれず、DSL にある名前だけが使われる。
- **AC1.4.2** Given 参照先の読み取りが行われたとき、When アプリのログ（TRACE を含む）・トレースの属性・エラー応答を調べるとき、Then 参照先の行の値と対象DB の接続情報が含まれない。
- **AC1.4.3** Given 参照先の読み取りが時間の上限を超えたとき、When 誤りになるとき、Then JDBC の例外のメッセージが応答にもログにも出ない（SQLState・業者のエラーの番号・例外のクラスの名前だけ）。
- **AC1.4.4** Given 参照先が、複合の主キー・主キーの無いテーブル・ビュー・自己参照・`valueColumn` が一意でないテーブルのとき、When 選択肢を読むとき、Then 設計で決めた側の動作になる（動作の確定は機能設計。決めた動作を明示したテストにする）。

## 群2 参照ピッカー（LOOKUP）

### US2.1 検索ダイアログで参照先を探して選ぶ 〔Must〕

P2 として、参照先が多いときに、検索のダイアログで条件を入れて探し、1 行を選んで値にしたい。それは、候補が多くても目的の行にたどり着くためである。

- **AC2.1.1** Given LOOKUP のカラムを持つ表の作成・更新の画面を、参照先を読める利用者が開いたとき、When ダイアログを開くとき、Then 検索の条件（`lookupSearch` のカラムと演算子）の入力が出て、検索するまで一覧は出ない（条件の入力を促す）。
- **AC2.1.2** Given 条件を入れて検索したとき、When 結果が返るとき、Then `lookupList` のカラムと並び順で、1 ページ 20 件の一覧が出て、ページ送りができる。
- **AC2.1.3** Given 一覧の 1 行を選んだとき、When 選ぶとき、Then ダイアログが閉じて値が入力欄に入り、選んだ行のラベルが入力欄の隣に表示される。選べるのは 1 行だけである。
- **AC2.1.4** Given 検索の値に `%`・`_`・引用符・`;`・改行が含まれるとき、When 検索するとき、Then それらは一致の条件として働かず、SQL として解釈されない。値は 1,000 文字までで、超えると誤りになる（実装の上限は設計で確かめる）。
- **AC2.1.5** Given 検索の結果が 0 件のとき、When 結果が返るとき、Then 「該当する行がありません」が出る。
- **AC2.1.6** Given 結果に読めないカラム（主権限 NONE）が `lookupList` にあるとき、When 結果が返るとき、Then そのカラムは応答に含まれない。

### US2.2 選んだ値のラベルが分かる 〔Must〕

P2 として、更新の画面で、すでに入っている参照の値のラベルを見たい。それは、ID だけでは何を指しているか分からないためである。

- **AC2.2.1** Given 保存済みの LOOKUP の値があるとき、When 更新の画面を開くとき、Then 参照先の行を 1 件読み、ラベルが入力欄の隣に表示される。
- **AC2.2.2** Given 参照先の行が無い、または読めないとき、When 更新の画面を開くとき、Then ラベルは出ず、値だけが表示される。

### US2.3 検索 API が権限で守られる 〔Must〕

P3 として、検索 API が、権限のない人に使われないことを確かめたい。それは、参照先のラベルが漏れないためである。

- **AC2.3.1** Given 未認証のとき、When 検索 API を呼ぶとき、Then 401 になる。
- **AC2.3.2** Given 参照元のカラムを編集できない（主権限が FULL でない）利用者が呼ぶとき、When 検索するとき、Then 権限を欠く応答になり、参照先の行は返らない。
- **AC2.3.3** Given 参照先の表または `valueColumn`・`lookupList` のカラムを読めない利用者が呼ぶとき、When 検索するとき、Then AC2.3.2 と同じ応答になる。
- **AC2.3.4** Given 権限が無い、参照元の指定が DSL に無い、参照先の行が無い、のそれぞれの場合、When 呼ぶとき、Then 状態コードと `code` がそろい、存在や権限を推測させない（形は Contract Design で決める）。
- **AC2.3.5** Given 参照元の権限と参照先の権限を満たす利用者が呼ぶとき、When 検索するとき、Then 200 で結果が返る。作業ロールを切り替えた直後・割り当てを変えた直後の次の要求で、結果が切り替わる。

### US2.4 ピッカーをキーボード・読み上げで使える 〔Must〕

P2 として、キーボードだけ・読み上げでも、ピッカーを開いて検索して選べるようにしたい。それは、マウスを使えない人も同じ操作ができるためである。

- **AC2.4.1** Given キーボードだけで操作するとき、When ダイアログを開く・条件を入れる・検索する・行を選ぶ・閉じるとき、Then すべてキーボードだけでできる。
- **AC2.4.2** Given ダイアログを開いたとき、When フォーカスを見るとき、Then フォーカスはダイアログの中に入り、閉じたら開いた項目に戻る。
- **AC2.4.3** Given 画面の検査（axe）を、展開した状態・長い名前・ブランドカラーとテーマのすべての組で行うとき、When 検査するとき、Then 違反が 0 件である。
- **AC2.4.4** Given 画面の言語が日本語か英語のとき、When ダイアログと誤りを表示するとき、Then 文言が選んだ言語で出る（既定は日本語）。

## 群3 保存前の確かめ

### US3.1 作成・更新の保存前に、参照先の存在と権限を確かめる 〔Must〕

P2 として、参照先に無い値や、権限のない参照先の値を入れたとき、保存の前に誤りを知りたい。それは、打ち間違いや値の差し替えで、おかしな参照が保存されないためである。

- **AC3.1.1** Given REFERENCE・LOOKUP のカラムに、存在する参照先の値を入れ、その利用者が参照先を読めるとき、When 作成・更新するとき、Then 保存される。
- **AC3.1.2** Given 参照先に存在しない値のとき、When 作成・更新するとき、Then 保存されず、409 `BUSINESS_REFERENCE_NOT_FOUND`（その項目の誤り）で返る。
- **AC3.1.3** Given 参照先の行はあるが、その利用者が参照先を読めないとき、When 作成・更新するとき、Then AC3.1.2 と同じ 409 の誤りで返り、存在の有無と権限の無いことを応答で区別できない。
- **AC3.1.4** Given 要求の本文の参照の値を、権限のない参照先の行を指す値に差し替えたとき、When 送るとき、Then 保存されず、AC3.1.3 と同じ誤りになる（IDOR の防止）。
- **AC3.1.5** Given 参照のカラムが NULL を許し、値が空のとき、When 作成・更新するとき、Then 確かめずに保存される。NOT NULL のカラムで参照先を読めない（または 201 件以上）ときの作成の扱いは、機能設計で決める。
- **AC3.1.6** Given 確かめた後で、保存の前に参照先の行が消されたとき、When 保存するとき、Then 対象DB の外部キー違反が、同じ 409 の誤りに変換される。

### US3.2 値が変わった参照だけを確かめる 〔Must〕

P2 として、参照先を読めない参照を持つ行でも、ほかの項目を更新したい。それは、参照先の権限が無いだけで、無関係な更新まで失敗しないためである。

- **AC3.2.1** Given 参照先を読めない利用者が、その参照を持つ行の、ほかのカラムを更新するとき、When 保存するとき、Then 更新は成功する（参照の値は変わらないため確かめない）。
- **AC3.2.2** Given 更新の本文に、入力不可の参照の項目が（変わらない値で）含まれていたとき、When 保存するとき、Then その項目は確かめられず、更新は成功する。
- **AC3.2.3** Given 参照の値が変わった更新のとき、When 保存するとき、Then 変わった参照だけが AC3.1.1〜AC3.1.4 のとおり確かめられる。

### US3.3 拒否が監査に残り、確かめの読み取りは残らない 〔Must〕

P3 として、参照先の確かめで拒否された操作を、監査で追いたい。それは、権限の差し替えの試みなどを後から調べられるためである。

- **AC3.3.1** Given 保存前の確かめで拒否されたとき、When 監査の記録を見るとき、Then 既存の理由 `REFERENCE_NOT_FOUND` で、操作した人・対象・結果が残る。
- **AC3.3.2** Given 監査の行を調べるとき、When 見るとき、Then 参照先の行の値が含まれない。
- **AC3.3.3** Given 確かめのための参照先の読み取りが行われたとき、When 監査の記録を見るとき、Then その読み取りは残らない（読み取りは監査の対象外の決まりのまま）。

### US3.4 一覧・詳細は今のとおり値を出す 〔Must〕

P1 として、一覧と詳細の画面が、今回の変更で変わらないことを確かめたい。それは、参照している値をラベルで見せるのを今回はやらない（範囲の外）ためである。

- **AC3.4.1** Given 参照のカラムを持つ表の一覧・詳細を開いたとき、When 表示されるとき、Then 参照している値は、今のとおり値（ID）のまま出る。
- **AC3.4.2** Given 定義の応答に参照の情報の欄が足されたとき、When 古い画面の部品が読むとき、Then 読み落としても壊れない。

### US3.5 参照先の読み取りが接続と時間を使いすぎない 〔Must〕

P4 として、選択肢・検索・保存前の確かめが、対象DB の接続と時間を使いすぎないことを確かめたい。それは、負荷の下でも接続が尽きないためである。

- **AC3.5.1** Given 選択肢の読み取り・ピッカーの検索・保存前の確かめを行うとき、When 1 要求で使う対象DB の読み取りの接続を数えるとき、Then 1 本までである（書き込みの接続は別）。
- **AC3.5.2** Given 内部DB の接続を持っているとき、When 対象DB を待つとき、Then 内部DB の接続を持ったまま待たない。
- **AC3.5.3** Given 選択肢（200 件まで）とピッカーの検索を、負荷試験で測るとき、When p95 を見るとき、Then 既存の業務データの読み取りの線（p95 が 1 秒未満、部分一致だけ 3 秒未満）を目標とする。測るのは Performance Validation である。

## 群4 持ち越しの片付け

### US4.1 k6 の結果の JWT が自動で伏せられる 〔Must〕

P4（高橋さん）として、k6 の結果に入る JWT を、記録に置く前に自動で伏せたい。それは、手で置換する漏れで、秘密が公開側に残らないためである。

- **AC4.1.1** Given k6 の summary json に JWT（`eyJ…` の形）が入っているとき、When 記録に置く前の処理を通すとき、Then JWT がすべて `[REDACTED-JWT]` に置換される。
- **AC4.1.2** Given 置換の後に JWT の形が残っているとき、When 処理が終わるとき、Then 記録を置かずに失敗にする。
- **AC4.1.3** Given 処理をもう一度通したとき、When 結果を見るとき、Then 結果は変わらない（冪等）。JWT 以外の内容は壊れない。
- **AC4.1.4** Given 仕組みのテストが `./gradlew verify` と CI に入っているとき、When 流すとき、Then 通る。`gitleaks dir` でも記録に秘密が残っていない。
- **AC4.1.5** Given `perf/README.md` を読むとき、When 手順を探すとき、Then 伏せる対象（summary json）と対象外（k6 の標準出力とログは手順で扱う）が書かれている。

### US4.2 動いているコンテナが compose.yaml の版にそろう 〔Should〕

P4 として、動いている Mailpit と otel-lgtm のコンテナを `compose.yaml` の版にそろえたい。それは、古い版が残って、監視や確かめの結果が食い違わないためである。

- **AC4.2.1** Given 作り直しの前に、Mailpit に溜まったメールが消えることを依頼者に伝えたとき、When 依頼者が了承したとき、Then 作り直しに進む。
- **AC4.2.2** Given `docker compose up -d --force-recreate --no-deps` で作り直したとき、When `docker inspect` で見るとき、Then コンテナのイメージのタグとダイジェスト（RepoDigests）が `compose.yaml` と一致する。
- **AC4.2.3** Given 古い 0.34.0 の lgtm のイメージがあるとき、When 作り直した後に見るとき、Then 戻し先として残っている。
- **AC4.2.4** Given 確かめが終わったとき、When lgtm の状態を見るとき、Then 起動したままか止めたかが手順に書かれ、その状態になっている。

### US4.3 perf の文書が、基準を読み取りやすい 〔Should〕

P4 として、`perf/README.md` と k6 の台本で、今の基準の値をすぐ読み取りたい。それは、前の線と今の線が混ざって、間違った線で判定しないためである。

- **AC4.3.1** Given `perf/README.md` を開いたとき、When 先頭を読むとき、Then 「今の基準の一覧」（合否の線の値と、それを決めている場所）がある。
