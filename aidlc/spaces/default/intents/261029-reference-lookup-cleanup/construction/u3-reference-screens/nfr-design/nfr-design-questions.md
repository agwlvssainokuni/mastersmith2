# NFR Design の質問 — U3 u3-reference-screens（Intent 261029-reference-lookup-cleanup）

U3（作成・更新の画面の参照の部品とピッカーのダイアログ）の NFR 設計で、判断が分かれる点だけを尋ねる。各質問の最初の選択肢を推奨とし、理由を添える。U3 は種類が `ui` のため、この段の成果物は performance-design.md・security-design.md・logical-components.md・traceability.json。

## 決まっていること（質問しません）

- 画面の側の時間の目標は置かない（NFR 要件の Q1: A）。初回の JavaScript は既存の確かめのまま、業務データの画面の chunk は manifest で測って記録する（NFR2.44）。
- 値とラベルは文字で描き、`data-testid`・`id`・`document.title`・ログに入れない（NFR1）。
- E2E は 190（代表の流れ）を1本と、本数に数えない 195（axe）。共有の見本の DSL に参照の表を足す（NFR5.43）。
- サーバーの並びは U1 の決定のとおり、文字のラベル・値は先頭 100 字で並ぶ（U1 の F1: A）。画面は並べ直さない。

## Q1. [アクセシビリティ] 作成の画面を開いた直後の、必須の入力不可の参照項目の誤りを読み上げさせるか（NFR4.45）

必須の参照項目に読める候補が無いとき、作成の画面を開いた直後から誤りの文（管理者への依頼を促す D13 の文）を出す。今の `FormField` の誤りの文は `role="alert"` のため、開いた直後に読み上げが割り込む。

A. 開いた直後は `role="alert"` を付けずに、項目に `aria-describedby` で結んだ説明の文として出す。利用者が保存を押して拒否されたときだけ、既存のとおり `role="alert"` で知らせる（推奨）。画面を開くたびに読み上げが割り込まず、項目にフォーカスしたときに必ず読まれる。決めた側の動作を、画面の部品のテスト（開いた直後に `role="alert"` が無い・`aria-describedby` で結ばれている）と E2E 195 の axe で確かめる。`FormField` にその口が無ければ、make-you-chic-ui への依頼の要否を計画で決める
B. 開いた直後から `role="alert"` で読み上げる。誤りに確実に気づくが、画面を開くたびに読み上げが割り込み、ほかの誤りの知らせと区別しにくい

## Q2. [性能] 更新の画面のラベルの1件読みを、同時に何本まで送るか

更新の画面は、値が空でない LOOKUP の項目ごとにラベルの1件読みを送る。項目が多い表では同時の要求が増え、対象DB の読み取りのプール（性能の試験では 5）を取り合う。

A. 同時に送るのは 3 本までにし、残りは前の答えが返ってから順に送る（推奨）。読み取りのプール 5 のうち、ほかの利用者の分を残せる。LOOKUP の項目は多くても数個で、待ちは数十 ms の見込み。上限の値は画面の定数にし、上限ちょうど・超える数の項目で送る順をテストで確かめる
B. 上限を置かず、項目の数だけ同時に送る。いちばん早く表示されるが、項目の多い表でプールを使い切り、ほかの要求を待たせうる

## Q3. [性能] REFERENCE の選択肢 200 件を `radio` で描くときの確かめ方

A. 画面の部品のテストで 200 件の `radio` を描き、すべてがキーボードでたどれ、ラベルの全文が DOM にあることを確かめ、E2E 195 の axe にも 200 件の `radio` の状態を入れる。描く時間の目標は置かない（推奨）。画面の時間の目標を置かない決定（Q1: A）とそろい、見た目の崩れと読み上げの問題は axe で拾える
B. 加えて、Playwright で 200 件の `radio` を描く時間を測り、目安（例: 500 ms）を置く。遅さに気づけるが、手元の PC の負荷で値が揺れ、合否の回を複数回流す必要がある

## Q4. [体験] ピッカーの検索が長くかかるときに「時間がかかっています」の知らせを出すか

サーバー側の目標は一致の検索 p95 1 秒未満、部分一致 3 秒未満。時間切れ（約 11 秒）までの間、画面は「検索中」を出す。

A. 出さない。「検索中」の表示（`aria-busy` と読み上げの状態の文）だけにする（推奨）。前の Intent の業務データの一覧と同じ扱いで、部品と文言とテストが増えない。時間切れになれば既存の 503 の文で知らせる
B. 検索を始めて 3 秒を過ぎたら「時間がかかっています」の文を出す。待つ理由が分かるが、時計に頼る表示とその文言（日英）とテストが増える
