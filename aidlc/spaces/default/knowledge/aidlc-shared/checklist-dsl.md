# 利用者が投入する DSL（YAML）を読み込む機能

> `team.md`・`project.md` から文を変えずに移した決まり（2026-11-07）。読む時: DSL（YAML）の投入・読み込み・生成に触れる Intent。

> 文中の「上の…」「下の…」「Code Style の…」「Testing Posture の…」は、元のファイル（`aidlc/spaces/default/memory/` の `team.md`・`project.md`）に残した行を指す。特に「上の『共通の形』」は、`team.md` の Testing Posture の「権限ごとの API の認可のテストの共通の形」の行を指す。

<!-- 元: team.md の ## Testing Posture -->
- 利用者が投入する DSL（YAML）を読み込む機能では、Code Style の「信頼できない入力」の決まりを確かめる次のテストを必ず書く（認証・認可・監査と同じ扱い）。上限の具体的な数値は設計の段で決め、決めた値の境界で確かめる。
  - 大きさ: 上限ちょうどは受け付け、上限を超えると拒否される
  - 入れ子の深さ: 上限ちょうどは受け付け、上限を超えると拒否される
  - 別名（アンカー）: 展開の数が上限を超えると拒否され、別名の展開の爆発で処理が止まらない
  - タグ: 任意の型を作るタグ（`!!` など）を含む DSL は拒否され、型が作られない
  - 重複キー: 同じキーが重なる DSL はエラーになり、後の値で黙って上書きされない
  - JSON Schema の `$ref`: 外部の URL を取りに行かない
  - 拒否の応答: Problem Details の形で返り、YAML・JSON Schema の部品の例外のメッセージを含まない

<!-- 元: team.md の ### 静的解析とセキュリティ検査 -->
- 利用者が投入する DSL（YAML）は信頼できない入力として扱う。読み込みの大きさ・入れ子の深さ・別名（アンカー）の数に上限を置き、タグと任意の型の生成を拒否し、重複キーをエラーにし、JSON Schema の外部の `$ref` を取りに行かない。検証はサーバー側を正とし、画面での検証をサーバー側の検証の代わりにしない。上限の具体的な数値は設計の段で決める。確かめるテストは Testing Posture のとおり。
